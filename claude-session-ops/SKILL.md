# Claude 会话管理

## 对象与入口

| 层级 | 对应对象 | 核对要点 |
| --- | --- | --- |
| 分区 | 自定义分组 | 与目录分区一致，如 `02 软件开发` |
| 项目 | 工作目录 | 一个编号、一份实体目录、一份 `PROJECT_HANDOFF.md` |
| 任务 | 任务会话 | 一个任务一个会话，标题写任务，结束后归档 |
| 主会话 | 项目长期入口 | 绑定该项目 cwd，标题用总表项目名，保留不归档 |

- [ ] 先读[工作台规则](/srv/workspaces/03-env/03-01-workbench/AGENTS.md)、[唯一交接](/srv/workspaces/03-env/03-01-workbench/PROJECT_HANDOFF.md)和目标项目规则，核对本轮授权及单写者。
- [ ] 唯一总表为工作台 `项目总表.json`；`项目目录索引.md` 与分区 txt 由 `scripts/gen_index.py` 生成，不手改。
- [ ] 工具必须来自当前 Claude 会话管理能力；先核对实际 schema，不猜 RPC、不直接改应用数据库或认证配置。Codex 缺该工具时交具备能力的 Claude 工作台回读执行，不能声称已操作。
- [ ] 建会话前用 `list_sessions` 按规范化 cwd、标题和状态查重；有已绑定主会话或同任务在跑就复用并对账，超时后先查原结果。

## 预建项目主会话

- [ ] 仅处理当前授权项目；按总表现状排除已完成、已归档、暂停项目，不固定历史数量。
- [ ] 核对 cwd：WSL 用 `/srv/workspaces/...`，Windows 用 `/mnt/d/ws/...`；不能把工作台 cwd 当项目 cwd。
- [ ] 确认当前是用户触发的轮次，且查重未发现可复用对象。
- [ ] `start_session`：选择 fresh 模式，cwd 为项目目录，`use_worktree=false`，`model=claude-sonnet-5-5`，标题按总表；字段名以当前 schema 为准。
- [ ] 保存返回的真实 session id，随后 `detach_session` 脱离成顶级会话；未脱离时会随父会话归组/归档，不能独立归组。
- [ ] `move_sessions` 归入对应分区分组；回读 cwd、标题、模型、detached 状态和分组，不用调用成功替代归属验收。
- [ ] 备份总表本次差异，将 id 写回对应项目 `claude_session_id`，同步 `claude_session` 标题；保留其他项目字段。
- [ ] 在工作台目录执行 `python3 scripts/gen_index.py --apply`，回读总表绑定与生成索引。

信任沿目录向下传递：本机 `/mnt/d/ws`、`/srv` 已有信任记录；实际仍弹提示时由用户处理，根外新目录按现场验证。不要修改信任配置或批量启动来跳过提示。

## 任务派发检查表

1. 在工作台准备完整任务书，包含用户来源、项目目录、允许范围、保护对象、验证与回读要求。
2. 执行 `python3 scripts/dispatch.py <编号> --to claude < 任务书.txt`；回读目标 `claude_session_id`、`message_file` 和 `/srv/work/claude-codex/dispatch-runs/` 留痕。
3. 用当前 `send_message` 将该文件正文发给该主会话。`dispatch.py` 对 Claude 只输出发送动作与文件，脚本成功不代表消息已送达；未知发送先对账，不盲重发。
4. 主会话核对现场，把任务书写入项目原有交接；默认免点击路径只写任务书、不出卡。工作台在用户触发的轮次按该任务书代起任务会话。
5. 代起前再次 `list_sessions` 检查同 cwd、同任务标题、在跑状态；已有用户启动的任务或在途写入者时不再创建。不能只凭总表没有任务 id 就认定不存在。
6. `start_session` 按当前 schema 使用 `user_asked`；工作目录为目标项目，保持该项目单写者。任务模型按任务需求和本次选择，不机械继承主会话模型。
7. 结果回写目标 `PROJECT_HANDOFF.md`，工作台读取证据并回传主会话；detached 主会话不会自动向工作台推送结束通知。

| 当前触发来源 | 可执行动作 |
| --- | --- |
| 用户直接触发 | 在授权内查重后创建主会话或任务会话 |
| 其他会话消息或自动事件 | 不能 `start_session`；只核对现场、写任务书并等待用户触发工作台代起 |
| 已有任务卡被用户点击 | 先查对应会话是否已创建，不另起相同任务 |

应用允许消息轮次出任务卡，不代表必须出卡。工作台规则仍记录该可选路径；免点击路径以本次授权及工作台交接的 2026-10-20 记录为依据。若已有卡，不跨会话使用 `proposal_id`（会报找不到提案）；查重后按交接正文代起，回读成功再由主会话撤卡，避免双启动。

无界面的 `claude-exec`/`win-codex` 是另一个执行入口；只有当前任务授权该方式时才使用，不靠它绕过 Code 页签的触发来源限制、额度或审批。

## 收尾与归档

- [ ] 任务完成：回读最终结果、实际差异、测试、未完成项，先转交主会话再归档任务会话；保留项目主会话。
- [ ] 归档前检查是否仍在跑、Remote Control 客户端是否连接、是否有排队消息；这些都可能导致归档被拒。
- [ ] 被拒时保留真实 session id 和原因，按授权等待结束或由用户处理连接/队列；不擅自 stop、断开或清空消息来强行归档。
- [ ] 归档调用后回读实际状态；目录绑定、总表 id、分组和归档分别验收，不能互相替代。
- [ ] 交付 session id、cwd、分组、触发来源、派发回执、完成及归档状态；保留未知结果，不创建替代会话掩盖失败。

跨主机执行、单写者和派发恢复按[协作能力与通道](/srv/work/claude-codex/协作能力与通道.md)；Windows 文件与命令细节按 `windows-from-wsl`。本 Skill 的安装验证不创建、派发或归档真实业务会话。

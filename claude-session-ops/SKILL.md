# Claude 会话管理

## 对象与入口

| 层级 | 对应对象 | 核对要点 |
| --- | --- | --- |
| 分区 | 自定义分组 | 与目录分区一致，如 `02 软件开发` |
| 项目 | 工作目录 | 一个编号、一份实体目录、一份 `PROJECT_HANDOFF.md` |
| 任务 | 任务会话 | 一个任务一个会话，标题写任务，结束后归档 |
| 主会话 | 项目长期入口 | 绑定该项目 cwd，标题用总表项目名，保留不归档 |

- [ ] 先读[工作台规则](/srv/workspaces/03-env/03-01-workbench/AGENTS.md)、[唯一交接](/srv/workspaces/03-env/03-01-workbench/PROJECT_HANDOFF.md)和目标项目规则，核对本轮授权及单写者。
- [ ] 唯一总表为工作台 `项目总表.json`；`项目目录索引.md` 与分区 txt 由 `scripts/gen_index.py` 生成，不手改。
- [ ] 工具必须来自当前 Claude 会话管理能力；先核对实际 schema，不猜 RPC、不直接改应用数据库或认证配置。Codex 缺该工具时交具备能力的 Claude 工作台回读执行，不能声称已操作。
- [ ] 建会话前用 `list_sessions` 按规范化 cwd、标题和状态查重；有已绑定主会话或同任务在跑就复用并对账，超时后先查原结果。

本版维护未暴露 Claude 会话管理工具，以下工具名、字段、模式和模型值依现行规则列出，实时 schema 尚未核实；执行前以当前工具为准，不从未暴露推断不支持。

## 预建项目主会话

- [ ] 仅处理当前授权项目；按总表现状排除已完成、已归档、暂停项目，不固定历史数量。
- [ ] 核对 cwd：WSL 用 `/srv/workspaces/...`，Windows 用 `/mnt/d/ws/...`；不能把工作台 cwd 当项目 cwd。
- [ ] 确认当前是用户触发的轮次，且查重未发现可复用对象。
- [ ] `start_session`：选择 fresh 模式，cwd 为项目目录，`use_worktree=false`，`model=claude-sonnet-5-5`，标题按总表；字段名以当前 schema 为准。
- [ ] 保存返回的真实 session id，随后 `detach_session` 脱离成顶级会话；未脱离时会随父会话归组/归档，不能独立归组。
- [ ] `move_sessions` 归入对应分区分组；回读 cwd、标题、模型、detached 状态和分组，不用调用成功替代归属验收。
- [ ] 备份总表本次差异，将 id 写回对应项目 `claude_session_id`，同步 `claude_session` 标题；保留其他项目字段。
- [ ] 在工作台目录执行 `python3 scripts/gen_index.py --apply`，回读总表绑定与生成索引。

信任沿目录向下传递：本机 `/mnt/d/ws`、`/srv` 已有信任记录；实际仍弹提示时由用户处理，根外新目录按现场验证。不要修改信任配置或批量启动来跳过提示。

## Claude 会话接力

依据[工作台规则的“Claude 会话接力”（2026-10-20）](/srv/workspaces/03-env/03-01-workbench/AGENTS.md)，将唯一交接冻结为精简上下文入口：

- [ ] 仅在用户要求接力后执行；上下文超过 60 万或阶段结束可作为提出接力的时机，不自动创建后继。
- [ ] 在本项目唯一 `PROJECT_HANDOFF.md` 头部写“接力”条目：冻结时间与时区、项目身份、当前有效规则、已完成与证据、在途与后台、待办与阻塞、禁止动作、后继首项任务。规则和证据引用原路径，不复制整段历史。
- [ ] Git 项目先提交交接，记录提交号及交接文件 SHA-256；非 Git 项目将交接文件 SHA-256 写入仓外回执。回读路径、内容与冻结时间，启动前发现漂移先重新冻结。
- [ ] 用 `list_sessions` 按规范化 cwd、标题和状态核对后继是否已创建；保存源会话真实 id 与原标题，未知创建结果先对账。
- [ ] `start_session` 使用同目录、fresh、Sonnet、`use_worktree=false`，标题沿用主会话；启动包只带交接路径与哈希、冻结时间、首项任务、源会话 id 与原标题、边界，不粘贴整份交接。
- [ ] 后继首轮只读初始化：读取交接、当前规则和现场，核对路径、哈希及项目身份，回报真实 session id、就绪状态和未核实项；初始化不执行首项业务任务。
- [ ] 后继就绪后，由工作台 `detach_session`、`move_sessions` 归组，将总表 `claude_session_id` 改为后继并同步标题、生成索引；按“预建项目主会话”回读绑定与实际归属。
- [ ] 切换验收后源会话改名加“（已接力）”，由用户归档；后继未就绪前源会话保持原名、不归档。不用 fork，避免复制整段历史。

## 项目负责人与派发

按[协作能力与通道的负责人及派发闭环约定](/srv/work/claude-codex/协作能力与通道.md)执行，任务书的明确要求优先于本节通用描述：

- [ ] 项目负责人是该项目的 Claude 主会话，负责派发、等结果、回读验收和项目交接；工作台负责分流与总账。`dispatch.py` 对已绑定主会话的项目默认发往主会话，`--to claude|codex` 可覆盖，适用边界按上述通道约定。
- [ ] 任务书固定写明汇报对象为本项目 Claude 主会话，经本项目 `PROJECT_HANDOFF.md` 与最终回复验收；执行者不向工作台或其他会话汇报，不替其他项目写交接。
- [ ] 固定交付要求：按任务书指定位置与方式汇报；未指定时在本项目交接头部写日期、所做事项、提交号、回执路径、未完成项或断点，并单独提交；任务书明确“不写交接/不提交”或限制可改路径时从其要求。最终回复首行写“提交号 / 回执路径 / threadId”，未完成也交代断点。
- [ ] 派发后保存并核对登记的完整 `ref`，在 Bash 后台运行 `python3 /srv/workspaces/03-env/03-01-workbench/scripts/dispatch_inbox.py wait <ref>` 等结束；超时先回读原任务，不重派。
- [ ] 收到完成通知后回读实际提交、回执、任务书要求的项目交接及最终回复，核对验证与未完成项；通过后运行 `python3 /srv/workspaces/03-env/03-01-workbench/scripts/dispatch_inbox.py accept <ref>` 并回读状态。`done` 只表示检测到结束，不代表验收通过。
- [ ] `dispatch.py`、`claude_bg.sh`、`win-codex` 自动登记收件箱，仍须回读登记结果；UserPromptSubmit 钩子在下一条消息提醒本目录相关的“已完成待验收”和“超 2 小时未结束”项，工作台另看汇总。钩子与交接文件更新时间仅提供线索，不能替代主动等待与产物验收；其他入口按脚本当前用法手动 `register`。

## 任务派发检查表

1. 在工作台准备完整任务书，包含用户来源、项目目录、允许范围、保护对象、验证与回读要求。
2. 在工作台执行 `python3 scripts/dispatch.py <编号> < 任务书.txt`，默认路由主会话；回读目标 `claude_session_id`、`message_file` 和 `/srv/work/claude-codex/dispatch-runs/` 留痕。
3. 用当前 `send_message` 将该文件正文发给该主会话。`dispatch.py` 对 Claude 只输出发送动作与文件，脚本成功不代表消息已送达；未知发送先对账，不盲重发。
4. 主会话核对现场，按任务书维护项目原有交接；能直接做就连续完成，需要派新任务时按本轮触发来源选桌面会话或下节后台入口。
5. 代起前再次 `list_sessions` 检查同 cwd、同任务标题、在跑状态；已有用户启动的任务或在途写入者时不再创建。不能只凭总表没有任务 id 就认定不存在。
6. 仅用户触发轮次用 `start_session`，代起时按当前 schema 使用 `user_asked`；工作目录为目标项目，保持该项目单写者。任务模型按任务需求和本次选择，不机械继承主会话模型。
7. 派发者按上节 `wait` → 回读验收 → `accept` 闭环；执行者按任务书向本项目交接与最终回复交付，由主会话验收后向工作台回报。detached 主会话不会自动向工作台推送结束通知。

## 非用户触发轮次不出卡

| 当前触发来源 | 可执行动作 |
| --- | --- |
| 用户直接触发 | 在授权内查重后创建主会话或任务会话 |
| 其他会话消息或自动事件 | 不调用 `start_session` 出卡；需要派新任务时走下述后台无界面入口 |
| 已有任务卡被用户点击 | 先查对应会话是否已创建，不另起相同任务 |

- [ ] 先读[claude_bg.sh 的当前用法与实现](/srv/workspaces/03-env/03-01-workbench/scripts/claude_bg.sh)；在已授权项目内使用 `/srv/workspaces/03-env/03-01-workbench/scripts/claude_bg.sh "<项目目录>" <任务名> [--model <模型>] < 任务书.txt`，任务书通过标准输入传入，任务名只含字母、数字、点、下划线或连字符。
- [ ] 起任何会话或后台任务前，必须 `list_sessions` 按规范化 cwd、标题和状态查重，同时回读已有后台任务的单元、结果目录和收件箱；同一项目同一时刻仅一个任务写入者。缺少会话查询能力时先交具备能力的主会话核对，不盲起后台替代对象。
- [ ] 脚本封装 `claude-exec`，默认 Sonnet，经用户级 systemd 脱离运行；保存返回的 `unit`、`out`、`model` 并核对登记。结果目录为 `/srv/work/claude-codex/claude-runs/<时间>-<任务名>/`，`ref` 用实际返回的 `out`，按上节后台 `wait` 等待。
- [ ] `exit_code` 文件出现只代表进程结束；回读退出码、`result.json`、必要的 `stderr.log` 和实际交付，验收后 `accept`。未知结果先对账，不重复运行；可选 `--resume <session_id>` 仅用于核实身份后的授权续接。

若已有卡，不跨会话使用 `proposal_id`；先查用户是否已启动，再由用户触发轮次按原任务书代起，回读成功后由主会话撤卡。后台入口沿当前任务授权执行，不用它绕过额度、审批或单写者约束；`win-codex` 的主机与派发边界按协作通道约定。

## 收尾与归档

- [ ] 任务完成：回读最终结果、实际差异、测试、未完成项，先转交主会话再归档任务会话；保留项目主会话。
- [ ] 归档前检查是否仍在跑、Remote Control 客户端是否连接、是否有排队消息；这些都可能导致归档被拒。
- [ ] 被拒时保留真实 session id 和原因，按授权等待结束或由用户处理连接/队列；不擅自 stop、断开或清空消息来强行归档。
- [ ] 归档调用后回读实际状态；目录绑定、总表 id、分组和归档分别验收，不能互相替代。
- [ ] 交付 session id、cwd、分组、触发来源、派发回执、完成及归档状态；保留未知结果，不创建替代会话掩盖失败。

跨主机执行、单写者和派发恢复按[协作能力与通道](/srv/work/claude-codex/协作能力与通道.md)；Windows 文件与命令细节按 `windows-from-wsl`。本 Skill 的安装验证不创建、派发或归档真实业务会话。

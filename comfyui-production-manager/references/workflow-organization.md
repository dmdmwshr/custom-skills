# 工作流组织与生命周期

## 目录事实源

```text
D:\12070\Documents\workspaces\Comfy-Codex-Workspace\workflows\
├── 模板库/                 # 官方 + 特色模板，按学习能力去重
│   ├── 01_图像生成与编辑/
│   ├── 02_视频生成与控制/
│   ├── 03_音频生成与编辑/
│   ├── 04_基础节点与后处理/
│   ├── 05_三维生成与处理/
│   ├── catalog.json        # 官方模板 ID、版本和哈希
│   └── curated_registry.json # 特色模板来源和保留理由
├── 03_自建复用工作流/       # 跨项目可复用的改造版
└── 99_归档/<YYYY-MM>/       # 仍可恢复的停用版本
```

项目工作流放在 `projects/<project>/workflows/`；执行镜像放在 ComfyUI 用户目录的对应分类子目录。工作区母版和运行镜像各一份是正常的双份，必须用哈希确认同步关系。来源不是目录边界：官方和特色模板都在 `模板库/`，来源写入登记表。

## 审计顺序

1. 递归枚举 `*.json`，排除目录索引、日志和备份。
2. 以 UTF-8-SIG 解析；确认每个工作流至少有 `nodes` 或 `prompt` 结构。
3. 提取节点数量、链接数量、节点类型、模型文件名、输入文件名和输出节点。
4. 计算 raw SHA-256 与 canonical JSON SHA-256，分别识别字节副本和语义副本。
5. 对“官方/特色”候选做功能级对照：输入输出、主模型/节点、控制信号、节点是否展开、能否解决新的制作问题。
6. 在工作区、ComfyUI 用户目录、项目、脚本和测试清单中搜索文件名与工作流 ID。

`scripts/audit_workflows.py` 是可重复的只读审计入口。报告应保存到工作区 `reports/`，不要写入 ComfyUI 安装目录。

## 学习价值筛选

手动下载的模板只有满足以下至少一项，才进入 `模板库/`：

- 提供官方模板没有的输入或输出，例如六关键帧、360 全景、四视图 3D；
- 提供不同控制方法，例如动作 LoRA、参考图板 IC-LoRA、Layered Control；
- 把官方子图展开为可见节点，能学习高/低噪模型、采样、LoRA 或 VAE 的连接；
- 提供官方库中没有的模型变体、特殊后处理或真实测试入口；
- 对当前创作问题有明确教学意义，并在 `curated_registry.json` 记录理由。

仅更换 checkpoint、提示词、保存目录、随机种子或 Markdown 说明，不构成独特学习价值。

## 去重与删除决策

| 证据 | 处理 |
| --- | --- |
| 工作区母版与运行镜像相同，且登记为镜像 | 保留两份，更新索引，不删除 |
| 手动模板与模板库已有流程功能等价，且无独特节点/输入 | 按用户授权删除手动母版和运行镜像，保留替代项记录 |
| 节点图不同但输入/输出能力相同 | 比较模型、控制节点和实测结果，不能仅凭文件名删除 |
| 有特殊输入、控制节点、节点展开或新资产类型 | 归入模板库，登记 `curated_registry.json` |
| 被脚本、测试或项目引用 | 先改引用并回归测试，再决定归档/删除 |
| JSON 无法解析或文件损坏 | 先隔离到归档并保留原哈希，不能直接覆盖 |

## 版本规则

不要在原 JSON 上反复覆盖。改造版复制后增加 `_v02`、`_UI版` 或 `_API版`，并登记 `supersedes`、变更原因、输入输出差异和验证状态。工作流锁定至少包含：工作流文件 SHA-256、ComfyUI 版本、核心节点包版本、模型文件名和模型哈希。

# MiniMax H3 的项目化生产方法

## 先确认工作流，不把说明书当作当前事实

MiniMax 的在线能力和本机 ComfyUI 节点会迭代，且不同工作流的输入数量、可选参考类型、时长、分辨率和音频行为可能不同。每次使用前先只读检查当前工作流的节点、输入端口、模型标识和节点内说明；以本机实际节点的输入类型为准。

若工作流提供图像、视频、音频参考输入，先明确每一份参考的叙事职责。不要把多张“看起来都不错”的图无差别塞入；冲突的脸、服装、场景或机位会降低一致性。

## 参考素材的职责分工

| 输入类型 | 主要职责 | 不应承担 |
|---|---|---|
| 图像参考 | 人物身份、服装状态、场景空间、道具形态、首帧构图 | 复杂长动作、完整声音表演 |
| 视频参考 | 动作节奏、镜头轨迹、空间移动、剪辑前后状态 | 替代角色身份卡或强行复制未授权作品画面 |
| 音频参考 | 台词节奏、声线、口型/声音同步的测试、环境/音乐方向 | 在未确认节点支持时强行绑定嘴型或混音 |
| 文本提示词 | 画面从起始到结束的可观察变化、镜头关系、保持项与禁止项 | 取代缺失的角色/道具/空间参考 |

如果本机节点要求使用标签引用输入，使用节点文档显示的准确标签与编号，例如本机显示的图片、视频、音频占位标记；不要凭记忆或从其他版本复制标签。每次保存工作流时把参考 ID、输入顺序和标签同时记入镜头合同。

## H3 镜头包

一个 H3 镜头包应包含以下内容，缺任何一项先停在策划或关键帧阶段：

| 项目 | 必填内容 |
|---|---|
| 镜头身份 | `shot_id`、场次、节拍、剪辑入/出点、计划时长和版本 |
| 叙事任务 | 观众在本镜头结束时新增理解什么、感受什么 |
| 参考映射 | 每张图/每段视频/每段音频的资产 ID、用途、输入顺序和许可状态 |
| 起止状态 | 画面开始时的姿态/视线/道具/光线；结束时允许改变的状态 |
| 动作节拍 | 按可见先后写 1–3 个动作；复杂动作拆开 |
| 镜头计划 | 景别、机位、移动量、速度、焦点变化、是否允许切镜 |
| 声音计划 | 画内/画外、对白 ID、口型策略、环境与音乐入出点 |
| 工作流锁定 | UI/API 工作流文件、节点版本、模型、关键参数、随机性策略 |
| 验收 | 身份、手/道具、空间、动作、镜头、声音和时间连续性检查项 |

## 提示词的写法

从图生视频开始时，图像已经提供了大量静态信息。提示词重点写“将发生什么”和“绝不能漂移什么”，而不是重复描述整张图。

```text
[参考及必须保持项]
保留 [人物身份/服装状态/场景锚点/道具位置]。

[起始状态]
镜头开始时，[人物位置、视线、手部/道具、光线、空间关系]。

[可见动作节拍]
先 [动作 1]；随后 [动作 2]；最后 [动作 3 或结束状态]。

[镜头关系]
镜头以 [景别/机位] 观察，以 [缓慢/静止/明确轨迹] 变化；不得出现未计划的切镜或摇晃。

[声音]
[说话者] 的 [画内/画外] 台词为 [dialogue_id]；保留 [环境声]；音乐在 [入/出点] 变化。

[禁止漂移]
不改变脸、年龄、服装、手指数、道具材质、空间布局、时代物件；不出现文字、水印或未计划人物。
```

只在镜头真正需要时加入“推近、环绕、变焦、拉焦”等运镜。镜头不因提示词写得多就更有电影感；没有明确叙事目的时，静机位和微小表演通常更可控。

## 分层测试与批量门槛

每个资产组按照低风险到高风险的顺序测试：

1. **身份测试**：单人物/单场景的小动作，确认脸、衣物、手、背景和道具没有漂移。
2. **动作测试**：只加入一个明确动作或一次镜头移动，检查起止状态和接触点。
3. **对白测试**：锁定台词音频或画外声策略，检查嘴型可用性、停顿和画面反应。
4. **衔接测试**：把相邻镜头的末帧/状态放在一起，确认视线、道具、光线、天气和声音能够接上。
5. **批量生成**：仅对通过上述测试的镜头组执行；一次批量只使用锁定的工作流、输入和版本。

对口型效果不可靠、人物多、台词长或动作复杂的镜头，优先改为“说话者局部/背影 + 对手反应 + 画外声”的剪辑覆盖方案。不要为了让每一句话都正脸口型而牺牲人物一致性。

## 图像、视频、音频参考的取舍

- **角色说话的近景**：人物正面或三分之二角色卡 + 同服装状态图；声音另行锁定；镜头只做轻微表情或视线变化。
- **群像对峙**：场景板 + 主角背影/局部 + 群像剪影；多条声音用剪辑组织，不要求所有口型同时可信。
- **道具触发**：手部/道具接触关键帧 + 起止状态图；特效变化拆成单独片段，避免动作、变形和大范围运镜同时发生。
- **空间穿行或复杂调度**：先用视频参考定义运动逻辑，人物身份仍由图像/角色卡约束；视频参考必须有可用授权。
- **环境与音乐**：无口型的氛围镜头可以先做画面和环境声；音乐作为后期独立轨道控制，不要绑定到随机画面生成。

## H3 记录与验收

每次运行至少写入：镜头 ID、工作流哈希、模型标识、输入资产哈希、提示词版本、随机性设置、生成时间、输出路径、人工复核结论和失败类型。

失败类型使用可统计的短标签：`identity_drift`（身份漂移）、`costume_drift`（服装漂移）、`prop_contact_fail`（道具接触失败）、`space_flip`（空间左右反转）、`motion_artifact`（动作瑕疵）、`lip_sync_fail`（口型失败）、`audio_mismatch`（声音不匹配）、`unplanned_subject`（未计划主体）、`flicker`（闪烁）或 `technical_error`（技术错误）。一次失败只修改最可能的一个主变量，再试验。

## 外部能力刷新原则

MiniMax 官方资料将文本生成、图生视频、首尾帧和主体参考视为不同能力；ComfyUI 工作流则把它们具体化为节点图与可复用输入。模型的参数、时长和音频能力可能变化，因此本参考不硬编码某个在线版本的参数。需要使用新特性时，先检查当前官方资料与本机节点，再更新项目测试记录。

# 飞书多维表格业务台账

本 Skill 是流程与经验，不是平台 API 封装。已实测范围：Windows 上经 Ego 浏览器对一个企业的测试 Base 做过结构搭建、Excel 导入回读、跨表公式、仪表盘与导出对账；**未实测**多账号权限、表单真实提交、官方 CLI 的 Base 能力。没有实测的部分写“待验证”，不要写成已可用。WSL 编辑源码不代表 WSL 浏览器已实测。

## 先分清入口

| 入口 | 适合 | 不适合 |
| --- | --- | --- |
| 多维表格（Base）数据表 | 有字段类型、关联、公式、视图的业务底座，主数据放这里 | 自由排版、打印成品 |
| 在线表格 | Excel 式排版、对外报送成品、通报模板 | 维护总表、多表关联、分单位填报 |
| 收集表 / 表单视图 | 填报**入口**（主要用于新增一行） | 不当作数据隔离；既有行的编辑/删除能否通过表单实现按当前功能与账号回读 |
| 仪表盘 | 只读统计展示 | 录入、权限控制 |
| 应用 / 智能体 | 稳定后的工作台、辅助问答 | 先把表结构和口径定下来再说；权益与用量另核 |

## 工作流

1. **定范围与授权**：目标企业/租户、owner、是新建还是改既有文件；用户给的范围才写；未经用户授权，不邀请成员、不公开分享、不购买或试用付费功能。云写前先读目标对象确认身份与现状。
2. **建模**：读 [建模与权限](references/modeling-and-permissions.md)。关系实体拆表，一个事实只在一张表主写，其余用关联/查找；主键用稳定业务编号（文本），不用名称或行号。
3. **数据准备**：读 [导入与验证](references/import-and-verification.md)。先盘源和覆盖，再生成导入文件；导入前用 `scripts/preflight_bitable.py` 对 JSON 做预检（主键、孤儿、三态、日期、行数）。
4. **云端执行**（按当前工具能力择一）：
   - 先看官方 CLI 当前是否有对应 Base 能力：`lark-cli skills read <对应技能>`，登录授权维护归 `feishu-operations`。有就优先用。
   - CLI 缺能力才用已授权的 Ego 浏览器；**先读 `ego-browser` 当前 Skill**，用其 TaskSpace/收尾规则。
   - 不抽取 cookies、localStorage、内部 state 去冒充 API；不为一次填表新装认证或新建应用。
   - 未知写入（超时、断线）先读表对账，主键幂等更新，不整批重建重复导入。
5. **验证**：导出云端数据，用 `preflight_bitable.py diff` 与本地标准数据逐表比对；再做界面阅读/填报/刷新检查。分别记录“自测 / 独立验收 / 云端实际 / 多用户权限”，没做的写未覆盖。
6. **统计**：用明细派生（公式、视图、仪表盘），静态快照只作对账。见导入与验证参考的统计一节。

## 不能破的几条

- 缺失不写“否”或 0。三态字段是 `是 / 否 / 待核实`，“否”必须来自来源明确否定；空白与 0、未采集与零记录分开。
- 年度、月份按**业务日期**（如初查日期、检查日期）判定，不用编号里的年份、文书年份、报表标题月份。
- 外部快照（如月报）与明细派生的数字并列保存，**不相加、不互相覆盖**。
- 个人手机号、身份证、人员姓名等非必要字段不进云端，也不进本 Skill 源仓。
- 单位只看自己数据的需求靠真正的角色权限，不靠筛选、隐藏列、表单预填；没有增值权限就如实说明做不到隔离。
- 官方链接（快速上手、高级权限角色、仪表盘跟随访问者权限、数值求和实践）见参考文件；付费权益、界面入口以当前账号和官方文档为准，本文件的版本细节只是 2026-10 的一次观察。

# 数据准备、导入、统计与验证

标注：【实测】在测试 Base 或本地数据上做过；【待验证】只有推断或另一轮正在探测；官方行为随版本变化，以回读为准。

## 1. 数据准备（导入前）

1. **盘源**：每个源记录路径、粒度、数量、时间、哈希、覆盖范围。先写盘点再设计表，否则会把“没采集到”当成“没有”。
2. **来源快照与字段包装**：接口/系统快照常把值包在 `{"value":…,"source":…}` 里，取值前统一解包；顶层没有某字段不等于缺失。预检会拒绝残留的包装对象。
3. **主键与关系**：主键唯一、非空、文本；子表外键必须能在父表找到（无孤儿）；多来源冲突（日期、名称、结果）进“核对”清单，不静默取一，也不把冲突值改成“否”。
4. **未知处理**：缺失 = `待核实` 或空，不是“否”、不是 0。名称关键词只能当候选，不能自动把未命中置否；原文明确“非/不是”不得被关键词倒置。
5. **日期口径**：按业务日期判年度/月份。无业务日期的记录归“日期未知”，不计入年度统计，也不拿其它日期顶替。子记录（如复查）日期未知时同理：**不能仅因父记录（案卷/初查）属本年就推断子记录的发生年份或月份**，必须有本年的业务来源（如复查文书日期、系统字段）；没有独立证据就写待核实、不计入，并在核对清单说明。若采用“晚于父记录且不晚于截止日”之类的逻辑推导，须有明确的先后关系证据，且在口径说明里单列，不与有日期记录混报。
6. **并列快照**：外部填报（如月报）与明细派生分列存放、列名前缀区分，不相加。差异原因没证据就写“未证实”。
7. **覆盖标注**：覆盖不足的时段，派生统计留空并写覆盖说明；空白 ≠ 0。
8. **个人信息**：手机号、身份证、人员姓名等非必要字段不导入。
9. **专项标签**：独立三态字段，各自记录依据来源（可用一列“分类依据”汇总）；不要用一个“类型”字段混装。
10. **手工名词**：自由文本在云端用单选或关联替代；所属单位字段受控，防止用户改单位窜行。

## 2. 生成导入文件

- 日期：本地 xlsx 写**原生日期**并设 `yyyy/mm/dd`；ISO 文本（`2026-05-19`）导入后转日期类型曾把整列清空【实测观察，仅一次，不能推断所有版本；以回读为准】。
- 主键、月份等用文本格式（`@`），写成文本类型单元格。
- 空值写真正的空，不写空串、不写 `-`。
- 首列放主键。关联列先输出**明确的关联键列**，导入后再设关联。
- 行数很少的表（前轮 < 10 行）导入后出现过全空“壳”记录【实测观察；是否稳定依赖版本】。导入后必须回读行数，发现空行再清理，不按版本猜。

## 3. 导入与关联

- Excel/CSV 导入只建数据表和字段，前轮导入**没有自动生成关联**【实测观察，以当前版本回读为准】；关联需在字段类型里设置，并核对关联条数是否与键列数一致（回读全部，不抽样）。
- 文本键列转“双向关联”：**已实测**（一次匿名探针）——父表首列为唯一文本主键，子表文本外键以与父表顺序交叉的两条记录，转成双向关联并关联父表、关闭“允许添加多个记录”、转换弹窗选“不保留未匹配的数据”后，导出父表仅 2 条非空主键，反向字段与子表 2 条均准确匹配，双向反向数量对账一致；原生日期同时保留。此前出现的清空，原因是父表表头被误识别导致父表 0 条记录、键全部未匹配，不是平台不能批量匹配。
- **未验证**：重复键、大小写、首尾空格、前缀/模糊匹配的行为，不得宣称。
- 转换做法：转换前保留文本键（本地留一份可恢复；云端最好另留辅助文本列再转换）；先用预检确认无孤儿，再选“不保留未匹配”，避免自动新增伪父记录；预检发现的未知键应先进核对清单处理，不允许因转换丢失业务值。正式批量转换后仍须**逐键导出对账**（父/子行数、每条关联的键、反向数量）。
- **字段类型转换可能清空值，且可能没有任何提示**：一次正式库观察中，把原为单选的“所属单位”字段转为双向关联（目标为单位名录表）后，573 个非空值全部变为空，转换没有出现“不保留未匹配”之类的对话框，直接提交；同一库里原为文本的外键/键列转关联则弹出匹配保留提示，导出回读全部原列（含父键、日期）一致。上面的匿名探针同样只验证了“文本→关联”，**不能推广到“单选→关联”或其他类型组合**；每一种“源类型→目标类型”都要单独当作未验证。
- **状态更新（一次观察）**：上述被清空的单选列，已用本地标准数据按稳定主键只恢复该列，恢复为单选后导出回读逐格通过（含原本为空的行），反向关联边数量完整。这说明“按主键恢复 + 全量回读”可行，不改变“转换本身可能无提示清空”的结论。
- 因此任何字段类型转换（文本/单选/多选/日期/关联之间）前：先保留当前导出和本地标准数据；区分源类型；先在副本或少量样本上试，样本通过后**正式转换仍要全量回读**（逐键比对该列全部值，含原本为空的行）。UI 显示成功、没有报错、没有弹窗都不等于数据保留。发现被清空时：保留失败导出与差异，按稳定主键用标准数据只恢复受影响的列，再导出确认；恢复未经导出验收前不写“已恢复”。
- 受控取值列（如所属单位）若需要既能引用名录又保留原值：先建新的关联列或辅助列承接，核对全量后再决定是否替换原列，不要直接覆盖原列类型。
- 导入后立即回读：**每张表表头是否为首行、主键列是否正确**（小表/无样式 sheet 可能被自动误识别，如末行被当表头、数据行丢失或父表为空，随后文本转关联会把未匹配键清空——这只说明识别出错，不能据此推断批量匹配能力），再核各表行数、主键非空数与唯一数、日期非空数、关联数、三态取值分布。
- **不能只核数量，还要核字段类型和长文本完整性**：一次正式文件导入观察到，部分说明/来源/问题描述类文字列被自动识别为多选，中文逗号、分号被拆成多个选项，导出后变成英文逗号加空格拼接，文字值与原文不同（主键与结构化字段仍逐值一致）。说明、来源、问题描述等长文本优先建为文本类型；发现被识别为多选时，先保留当前导出和本地原文，调整字段类型后**按主键用原文恢复并逐值复核**——调整类型本身不会自动恢复原标点，不要预设它能恢复。
- **导入入口可能新建一个 Base 而不是写入当前 Base**：一次观察中，文件顶部更多菜单的“导入”上传成功后创建了一个新的多维表格，进度任务名称可打开它。是否因版本、入口、账号而不同未验证；因此每次导入后要核实际 URL、标题、租户和表列表，不凭“上传成功”认定已写入目标。

## 4. 统计

- 统计由明细派生：公式字段、按月份/年度/单位的视图、仪表盘。静态快照只用于对账。
- 前轮在测试 Base 配置并通过导出对账的写法（跨表计数，名称为匿名示例）：

  ```
  [检查].COUNTIF(AND(CurrentValue.[统计月]=[统计月],CurrentValue.[所属单位]=[所属单位],CurrentValue.[阶段]="初查"))
  ```

  源表字段写 `CurrentValue.[字段]`，当前行字段直接写 `[字段]`；多条件用 `AND(...)`。按官方文档当前说明，飞书公式**不使用 Excel 的 COUNTIFS/SUMIFS**，用 FILTER/COUNTIF + AND 代替（版本变化时以当前文档为准），不要把 Excel 写法当成飞书已验公式。公式内用英文半角符号；单选字段互相比较、空值判断等边界先在小样本冒烟，再大面积铺开。
- 月份字段在各表保持同一类型和写法（如统一为 `202610` 数字或同一文本格式）；所属单位在各表选项文字必须一致。
- 年度/月份/单位视图 + 仪表盘做展示；仪表盘筛选条件若固定了月份，切换月份要逐个组件调整（前轮观察），不要宣称有统一月份选择器。
- 零与未采集分开：公式统计的 0 只表示“当前已采集记录命中 0 条”，不是该工作全年未发生；外部快照（如月报）缺列/缺值保持空，不填 0；覆盖不足的说明写在字段/说明里。
- **公式输出类型：导出序列化类型与云端运算类型分开核验**。一次观察：混合空字符串的公式 `IF(COUNTIF(...)=0,"",COUNTIF(...))` 导出的数字是字符串；改为全数值 `COUNTIF(...)` 后，XLSX 导出的公式列**仍然是字符串**，但云端仪表盘指标卡对该列求和得到正确合计且刷新后不变。所以：不得仅凭导出里是 str 就认定云端不能求和/排序，也不得仅凭界面显示就认定类型正确——要在云端做一次实际求和/排序/图表验证，并核对公式字段的数字格式；若还要对导出文件再做 Excel 计算，需显式转换类型后验证。最终导出与增删联动验收前不宣称通过。
- **分组键映射**：统计行的分组文字（如“待核实”）与源记录的空值不相等，公式条件匹配不到。先明确业务映射（本次规则：仅把原本为空的分组值计入“待核实”这一行，不伪造新的分组项如第 9 个单位），再复算所有行；无日期的子记录不因父记录的年度推断实际年度。
- **静态快照要标明**：未改成公式的派生统计列仍是导入时快照，须在字段/说明中标注，不能声称“全部自动汇总”；同一行里静态列与动态列不能互相矛盾。
- 粒度不混：现场判定与抽样结果、初查与复查、明细数与案卷数各自单独统计；“不合格明细数”和“有不合格的案卷数”要用含“同案多条不合格”的数据才能证明区分。
- 给用户示例要匿名、短；字段名适配后才能称可用，跨表公式在目标 Base 回读通过前一律写“待验证”。

## 5. 验证分级与对账

分别记录，缺哪层写哪层“未覆盖”：

1. **本地自测**：预检脚本、匿名测试数据、输入文件哈希前后一致。
2. **云端实际**：导出云端数据，与本地标准数据逐表按主键比对——行数、主键、日期、空白、关系条数、三态分布、公式结果。预检的 `diff` 子命令负责数据层比对（导出需先转成 JSON）。
3. **界面**：真实阅读、填报一条测试记录并删除/恢复、刷新后统计联动、视图与仪表盘显示。截图只能佐证界面，不能单独证明已保存。原生筛选视图调整后要点“保存”并刷新复核；筛选视图不是数据权限。表单新增测试不等于组织级权限验收。
   增删联动验证：可在界面添加一条**明确标记**的临时记录，确认汇总公式、两级反向关联和导出随之变化，再删除并重新导出确认恢复原值、无残留；这是管理员原生录入测试，**不是多账号权限验收**。
   导出还要检查**全空空壳行**（小表导入常见）：清理前先确认该行全部字段为空、且确为自己导入产生的残留，再删。
4. **独立验收**：由未实施者读取导出重算。
5. **多用户权限**：两个普通身份 + 管理员，见建模与权限的验收矩阵。没做就写未覆盖。

失败的导出和原始日志保留，不覆盖；清理只清自己创建的测试对象。

## 5b. 独立复算与批量编辑纪律

- 独立审查者用自己的脚本从导出重算：键唯一/无空行、原列逐值、两级反向关联逐边（不只比行数）、每个动态公式字段逐行语义重算及合计、静态快照列与明细一致、日期为日期型；不复用实施者的脚本结果。
- **键盘/批量粘贴定位纪律**：在画布式表格里，`Ctrl+Home` 不保证选中 A1；批量粘贴前必须用新截图确认首行首格（或用字段/行选择器）；一次逐格键盘导航曾发生列偏移，写出 4 个误字段。操作后**回读整表**（所有列、所有行），不只核对键集合；定位失败后不重复盲目写入，先保留失败导出，只精确删除自己误加的字段，再按主键对齐覆盖并整表回读。
- 说明/来源类文本表若含本地路径或内部接口名，开放给他人前确认是否保留。

## 6. 云端执行提示

- 写入前先读目标 Base 确认企业/owner/对象，范围外不动。
- 官方 CLI 有对应能力优先（先 `lark-cli skills read` 对应技能与 `--help`）；没有再用已授权 Ego；使用 Ego 前先读其当前 Skill，收尾按其现行 TaskSpace 规则关闭自建页面。
- 超时或结果未知：先读表对账，按主键更新，不重复批量创建。
- 不为一次填表安装新认证、新应用，不读取 cookies 或内部 state。

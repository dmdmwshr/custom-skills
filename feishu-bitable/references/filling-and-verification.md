# 填报层、完整性与核实（父→子多层台账）

适用：在已有的“父表→子表→孙表”多维表格上，给填报人建立直观的填报界面，并自动判定缺项和人工核实。以下为一个企业账号、2026-10 的界面观察与一次实施，不是平台承诺；标“待验”的未实测。示例用匿名名：父=案卷，子=检查，孙=产品。

## 1. 填报界面 = 同一底表的视图
- 在父/子/孙三表上各建一个原生视图，记录实时互通，不另建可编辑副本（副本要说明单一主写与双向同步风险，查找引用不能代替可编辑）。
- 填报视图隐藏：数据层级、分类依据、水位/来源、AI 标记、历史年度快照、重复的旧日期/旧大队、辅助计数和时间字段。前排放业务字段、关联下钻、是否核实、核实有效、填报状态、数据是否齐全、待补内容。
- 独立填报视图的隐藏设置不会自动覆盖所有关联内嵌表格。本次从父记录展开子记录、再展开孙记录时，须分别配置关联内嵌表格的字段显示；清理后再次实际下钻核验。其他反向展开路径未测就不声称已清理。
- 视图和隐藏列**不是权限**；管理员仍可展开隐藏列，不得宣称完全屏蔽。成员映射与多账号隔离未测就写未覆盖。
- 另建“待补”“待核实”工作视图，按齐全/状态筛选。

## 2. 年份：底表保留，填报界面不放
- 底表保留业务日期和历史年度快照（静态）；填报界面不放年份专用列，年度由日期派生。
- 实时月份可用公式字段，例如 `IF(ISBLANK([检查日期]),"日期待补",TEXT([检查日期],"YYYY-MM"))`，供分组视图统计；无日期归“日期待补”，不猜年份。该字段是文本分组键，别用于数值运算。
- 静态快照字段（如“计入某年”）对新补录记录为空，**依赖它们的旧公式不会统计新记录**。区分“静态快照”和“按日期实时派生”，并保留旧数与新数的对账：同一统计范围内，某年各月之和 + 其他年份 + 日期待补 = 检查总行数；另对比旧快照覆盖的子集，不能把带快照标记的旧记录数当成全部实时记录数。

## 3. 同名表/反向字段与父级计数
- 反向关联字段与表同名时，`COUNTA([同名])` 被当成整张表（一次观察中编辑器直接拒绝，或得到全表合计）。把反向字段改显示名（如“关联子表”）后，`COUNTA([关联子表])` 才每行正确。只改显示名，原关联保持；改后回读关联数和旧公式。
- 跨表计数用真实关联条件：`[子表].COUNTIF(CurrentValue.[父级关联]=[父级主键])`，实测按关联逐行正确；不用主键字符串前缀代替真实关联。
- 逐层汇总不要重复深层：子表算“下级待补数”（含其孙表，因为子表的齐全已包含孙表），父表只数子表。
- 校验：各父行的子级计数之和 = 子表总行数；若等于总行数 × 父行数，说明取成了全表。空父记录（无关联）不参与业务对账。
- 公式编辑器不支持 `<>`，用 `NOT(a=b)`。

## 4. 完整性（缺项）
- 每层一个文本公式“待补内容”，把缺项用 `；` 拼接；“数据是否齐全” = `IF(LEN([待补内容])=0,"齐全","待补充")`。
- 判空用 `ISBLANK`：0、否、是是有效值；待核实、空白是缺项。三态标记不得把待核实当有效。
- 只列本层必需字段，可选字段不强制，不要求无来源附件或个人手机号；条件必填（如不合格须有问题描述、某类案件须有案号）写成 `IF(AND(条件,ISBLANK(字段)),…)`。
- 同时检查：主键重复（表内 COUNTIF）、键与所属父级/序号是否一致、子级结果与上级结果是否矛盾、缺少下级记录；还有下级待补数。
- 同父同阶段多次记录：保留既有键，新增“序次”并让键带后缀，旧键不改。
- 齐全只说明“该填的填了”，不等于正确，也不等于已核实。

## 5. 核实机制
- “是否核实”是人工复选框，导入或脚本一律为否，不得代勾。
- “核实时间” = 最后更新时间，**只跟踪**是否核实；“资料更新时间” = 最后更新时间，跟踪人工可编辑业务字段、主键文本、父级关联和反向关联，不跟踪公式字段与复选框。创建字段时要选带时间的显示格式。
- “修改人”字段无法指定跟踪字段，所以不能做“核实人”；需要时只能加诚实命名的“最后修改人”（任意字段），不参与判定，谁勾选靠记录历史。单管理员账号阶段，勾选不能证明是业务人员本人。
- 核实有效：
  `IF(NOT([是否核实]),"未核实",IF(AND(NOT(ISBLANK([核实时间])),OR(ISBLANK([资料更新时间]),[核实时间]>=[资料更新时间])),"核实有效","资料已更新，需重新核实"))`
  其中 `OR(ISBLANK(资料更新时间),…)` 让从未编辑过的旧行首次勾选即有效；改资料后须取消再勾选。
- 填报状态：缺项优先“待补充”；其次本级或下级未核实为“待核实”；齐全且本级与下级都核实有效才“已完成”。
- 本次纯测试库实测：旧行资料时间为空时首次勾选有效；父/子/孙填齐并核实后三层均“已完成”；随后修改孙表文本，孙表核实失效，三层状态均回到“待核实”。新增孙表关联会更新子表的指定关联更新时间。父表自身关联变化、关联移除/跨父级移动未覆盖，不将该结果推广到所有关联变更。
- 导出时间到秒，同一秒内先后顺序与精度未覆盖，不得称防篡改或签名审计；核实机制和账号隔离应分别验收。

## 6. 操作界面的观察（Ego，本账号）
- 画布类界面读不到 DOM 业务值，用原生导出到本地对账并截图。
- 字段面板和“指定字段”选择器是虚拟列表，先在搜索框输入字段名再选。
- 菜单项上 DOM `element.click` 不一定触发，用真实 `p.click`；新增字段先选类型再填标题，编辑既有字段时标题框 placeholder 是旧字段名。
- 页面刚导航时可能先呈现旧缓存。若显示“公式计算中”或下载提示“公式计算未完成”，该导出只作失败/中间证据，不能当最新结果；待计算结束，必要时正常刷新，再导出核对。
- 每批字段写完全量导出：原列逐值不变、键集合不变、新增派生列与独立推演一致。

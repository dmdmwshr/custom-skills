# 建模与权限

## 1. 实体拆分

- 先列“一行代表什么”。一个业务对象一张表；一对多拆成父子表，多对多单独建中间表。
- **一个事实只有一个主写表**：其他表通过关联字段与查找引用取值，不手填冗余。确需冗余（如为公式条件方便）要标注“派生/冗余”，并在验收时比对一致。
- 独立生命周期的对象（如企业/场所名录）单独成表，不挂在某个案卷下；需要时再加关联。
- 典型层次示例：案卷（一）→ 检查（多：初查/复查）→ 产品明细（多）。统计用明细行派生，月度汇总表是视图/公式，不另手填。
- 名录类（单位/大队/人员映射）做成单独表，被其他表用**单选或关联**引用，避免自由文本（同一单位写成两种名称会让统计和权限都失效）。

## 2. 主键

- 稳定业务编号，**文本类型**；不用名称、行号、自动编号。组合键用分隔符拼接（如 `案卷号|阶段`、`检查键|序号`），拼接规则写进说明。
- 编号含前导零或长数字时，导入文件按文本写入，导入后回读首尾行确认没被数值化或科学计数法。
- 主键唯一性飞书不强制，靠预检和导入后回读；更新既有记录时按主键查找再改，不按行号。

## 3. 入口的界限（再次强调）

- 筛选视图、隐藏列、表单预填、仪表盘页面筛选只改变展示或默认值，**不是权限隔离**；只有真正配置的角色权限才能隔离，实测是用来验证权限配置是否生效。
- 表单的主要用途是新增记录；既有行的查看、编辑、删除能否经表单、共享视图或角色实现，随当前功能版本与账号权限而定，需按当前界面/官方文档核对并实测，不要预设能或不能。
- 创建人只适合“每人只改自己创建的行”的个人独立填报。多人同单位协作必须有受控的“所属单位”字段和成员名录映射（谁属于哪个单位），不能按创建人区分。
- “所属单位”应为单选或关联到名录；若允许成员自行修改，会出现改单位窜行，所以该字段权限须只读/仅管理员可改。

## 4. 角色分配方案（设计，需实测）

目标：管理员维护表结构；N 个单位只访问和维护自己单位的行。

| 对象 | 管理员 | 单位角色 |
| --- | --- | --- |
| 业务数据表 | 全部 | 本单位行可增改；已锁定行只读 |
| 表结构、公式、视图、权限 | 管理 | 无 |
| 名录 | 管理 | 只读 |
| 更正/审计类表 | 管理 | 只读或无 |
| 仪表盘 | 全局 | 数据跟随访问者权限（见官方说明），需实测 |

按单位隔离行通常要用到高级权限（行列权限）。**当前账号是否具备、是否需要付费、有没有其他可行方式，均以当前账号界面和官方文档回读为准**（2026-10 的一次观察是该账号界面将其标为增值功能）：

- 界面标为增值功能且用户未授权购买/试用时，不购买、不启用试用、不邀请成员；输出可做与未验证清单，用户决定后再继续。
- 无权限时的替代路线（每单位独立文件 + 管理员总表）会增加汇总与同步成本，同样需用户授权和权益核对，不自动实施。

## 5. 权限验收矩阵（实施后必做）

至少两个普通测试身份（不同单位）+ 管理员，逐项交叉验证：查看、新增、编辑、删除本单位与别单位记录；关联字段选择器是否能看到/选到别单位记录；查找引用/汇总字段是否泄露别单位数据；仪表盘数字是否跟随访问者；导出/复制；表单提交后的归属。任一项未测，在报告中写“未覆盖”。

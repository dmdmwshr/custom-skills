# 经验落位矩阵

## 证据等级

| 等级 | 含义 | 可支持的动作 |
| --- | --- | --- |
| `current_readback` | 本轮直接回读当前文件、运行态、测试或结构化接口 | 可提出实施建议；变更前仍需检查授权和现有规则 |
| `historical_evidence` | 已归档任务的最终结果、失败记录或已保存摘要 | 可提炼候选经验；必须标明历史时点，不能冒充当前事实 |
| `unverified` | 标题、计划、队列接受、旧截图、单一推断或缺少终态证据 | 只能列为待验证，不得据此宣称完成或写成硬规则 |

## 复用强度

优先级从高到低为：当前用户明确且稳定的要求；多个独立任务重复出现并具有相同不变量的失败/成功；一次可复现且影响明确的失败；孤立噪声或无法重现的推断。低强度样本默认不持久化。

## 落位决策

| 落点 | 判断条件 | 必须避免 |
| --- | --- | --- |
| 全局 `AGENTS.md` | 跨项目适用、稳定、与安全/授权/传输/上下文保护有关，并有足够证据 | 把项目路径、业务状态或一次性偏好写成全局规则 |
| 已有 skill 源 | 明确属于某个 skill 的触发流程、领域约束或重复故障修正 | 同一规则散落多个 skill，或直接改安装副本 |
| 项目 `AGENTS.md`、唯一计划或交接文件 | 只影响一个项目的事实、阶段、端口、数据或未完成项 | 将项目事实复制到全局或 skill |
| 新 skill | 独立、可重复、现有 skill 的触发边界和职责无法清晰承载 | 为单次事件、cc-switch 子功能或简单几行规则新建 skill |
| 不持久化 | 证据不足、无法脱敏、仅为旧任务状态或只是环境噪声 | 为了“留下记录”而写入敏感或未经验证内容 |

## 写入前检查

1. 搜索目标文件和相关 references，确认没有已有等价规则或更具体的事实源。
2. 只保留改变未来决策的最小表述；把长案例、模式差异和证据说明放在直接链接的 reference 中。
3. 去掉项目名、内部任务标识、凭据、Cookie、令牌、账户、完整日志和未经授权的消息正文。
4. 明确规则的适用范围、例外、停止条件和验证方式；把“建议”与“必须”分开。
5. 若目标是项目内 skill，先只读抽象其可复用不变量，再由用户明确授权修改该 skill 源；不要顺手改项目代码、计划或运行态。

## 项目任务接力特别规则

归档复盘发现“需要新项目任务继续”时，只报告并转交 `codex-project-task-handoff`。该 skill 负责先确定并原地更新项目内唯一活动交接文档，再创建和验证后继任务；本 skill 不创建 `PROJECT_HANDOFF.md` 副本、日期副本或聊天版第二交接包。

# 本地状态恢复与归档回读边界

本文件只在用户明确授权精确修复或归档动作后使用。诊断请求本身仍然是只读授权。

## 授权矩阵

| 动作 | 默认 | 另需授权 |
| --- | --- | --- |
| 读取索引、SQLite 完整性、rollout 元数据、进程和日志 | 允许 | 无 |
| 公开无账号网络探针 | 仅在用户请求网络验证时 | 目标、时间和范围 |
| 重启桌面端、app-server、MCP、Docker 或代理 | 禁止 | 精确进程/服务和重启影响 |
| 停止或杀进程、停用 MCP、改代理/路由/TUN | 禁止 | 精确对象、恢复方式和替代路径 |
| 编辑普通配置 | 禁止 | 精确文件、字段、备份和维护窗口；修改后必须实际回读 |
| 手工编辑 Codex 索引、SQLite 或 rollout 文件 | 本 Skill 永不实施 | 只能转交有独立恢复契约的官方或专用流程；canonical rollout 证据不得改写 |
| 归档、恢复、重命名、发送、恢复会话 | 禁止 | 完整 ID、host、动作和读回 |

## 修复前后顺序

1. 先保存只读诊断摘要和精确目标清单，避免把当前事实与历史日志混淆。
2. 对配置、任务定义或数据库创建可恢复备份；活跃 SQLite 使用应用安全的在线备份，不只复制主文件。
3. 只修改用户授权的字段或对象，不顺手升级、重建、去重、迁移或清理其他状态。
4. 对外部过程设置硬超时；超时后先读回，不按失败假设重跑。
5. 回读实际文件/进程/任务/官方状态，比较版本、哈希、状态、时间和工作目录。
6. 备份位置、动作结果、读回结果和仍未闭环的层级分别记录；没有读回就写结果未知。

不要为了让界面恢复而手工修复 state_*.sqlite、session_index.jsonl 或 rollout JSONL。若历史路径兼容性确需修复，应由专门的授权恢复流程实施，且不得借机删除历史、重放消息或改写用户事实。

## 归档、恢复和重命名

对官方任务管理能力执行写入时：

1. 使用完整 session ID、host 和当前项目核对目标；含尾随字符、只有短前缀或存在多个同前缀对象时拒绝猜测。
2. 写入前读回当前 title、archived、项目和 host，记录旧状态。
3. 只用官方写入接口。不要用 SQLite、索引或归档 JSONL 直接模拟归档。
4. 写入后重新列出或读取同一完整对象，核对 title、archived、项目和 host。
5. 返回超时、连接断开或状态不确定时不重发；先读回，仍不能确定则标记 result_unknown。
6. 重命名成功但归档失败时，保留新标题并报告“仍未归档”；归档成功但列表尚未刷新时，报告读回时间和可能的缓存延迟，不追加第二次写入。
7. 硬删除不是归档的后续步骤。需要硬删除时另行确认精确对象、恢复可能性和备份。

## 与项目任务交接的边界

普通项目上下文过长时，交接由 codex-project-task-handoff 执行：先在项目内更新唯一交接文件，默认项目根目录 PROJECT_HANDOFF.md 或项目规则指定的唯一路径，再创建同项目后继任务。不得把本 skill 的诊断摘要当作第二份交接文件。

后继任务取得真实 threadId、完成初始化并回读项目身份、唯一交接路径和工作区后，才允许按交接 skill 的顺序重命名、归档旧任务。任何一步失败都保留旧任务现状，不创建第二个后继任务，不手工编辑 Codex 数据库。

固定会话、绑定代次和移动消息由 cc-connect-collaboration 处理；跨主机 Codex 任务的创建、读取或移交使用官方任务工具，windows-task-scheduler 只管理本机 Windows 计划任务。本 skill 只提供跨层证据，不替代这些流程。

## 最小恢复回执

使用如下字段组织结果，不回传原始配置和日志：

- target：脱敏的完整对象类别、host 和项目
- before：状态、版本/哈希摘要、路径和进程事实
- authorization：当前用户明确授权的动作和范围
- backup：备份类型、时间和位置
- action：实际执行或明确未执行的动作
- after：目标实际回读、时间和一致性结果
- outcome：check_no_update、update_applied、deferred_active_target、result_unknown 或失败类别
- remaining：未闭环证据、风险和下一步

当动作影响外部发送、任务归档或用户可见状态时，必须把“平台接受”“本机登记”“最终送达/列表读回”分开写，不能互相替代。

# 单次被动采样与五类操作卡

用于模型断连、模型看似卡住、工作空间或会话加载慢、工具启动及调用慢。先确定同一主机、实例、完整聊天标识和故障时间窗；只检查与症状有关的层。浏览器连接问题仍走浏览器控制参考。

## 三种动作分别处理

| 动作 | 用途与边界 |
| --- | --- |
| 被动采样 | 人工调用一次，只读现存的限定元数据和日志；不联网、不运行 Codex CLI、不启动模型或服务、不循环等待。 |
| 主动诊断 | 需要主动连通性、工具握手等证据时，按本次任务范围单独执行。先核对当前版本的帮助及实际行为，再选择官方 `codex doctor --json` 等入口；它不能当作离线被动采样。 |
| 修复 | 只有当前任务已包含对应动作时实施，保留精确恢复点并复验同一对象。诊断建议本身不构成重启、清库、停用工具、切提供方或改代理授权。 |

既有清晰授权不逐步重复确认。出现拒绝、动作结果未知或对象不唯一时先对账，不换通道绕过或重复发送。

## Windows 被动入口

入口由 Windows 的 `03-05-codex-env-win` 项目维护：`D:/ws/03-env/03-05-codex-env-win/scripts/audit_codex.py`。先按该项目规则和当前交接核对实际解释器、脚本版本及运行入口；示例中的 `python` 表示该项目当前指定的解释器，不要求全局安装依赖。

```powershell
python -B -X utf8 'D:/ws/03-env/03-05-codex-env-win/scripts/audit_codex.py' --passive
```

`--passive` 必须显式携带。旧无参数入口仍有主动联网和报告写入行为，不能用它代替被动检查。

| 参数 | 语义 |
| --- | --- |
| `--thread-id` | 可选完整聊天标识；不按短前缀、标题或相似目录补猜。 |
| `--turn-id` | 可选轮次标识，须同时提供聊天标识。 |
| `--since`、`--until` | 指定带时区的故障时间窗；默认最近15分钟，最长60分钟。 |
| `--output-dir` | 可选仓外报告目录；省略时只向标准输出返回 JSON，指定后生成独立批次报告，不覆盖历史。 |

被动分支在旧联网、CLI 调用和固定报告写入之前分流。只读配置白名单、入口文件元数据、受限线程元数据和有界日志分类；不导出正文、凭据、完整环境、命令行或私有配置。缺文件、数据库锁、旧结构、日志轮转和截断只标记该层未覆盖，不修复或重试。

退出码 `0` 表示有效报告已生成，不能解释为系统健康；`2` 表示参数或路径错误；`1` 表示无法生成有效报告。报告应读到对象身份、采样时间、已证实事实、未知项、责任方和下一项复验要求。磁盘默认、聊天保存值与实际加载值分别判断；没有加载证据时保持未知。

该工具不保证取得真实队列、模型内部阶段、上传完成或全部产品工具状态。缺少精确聊天或轮次时，实例级错误不能自动归给当前任务；`codex mcp list` 也不能代表全部产品插件和当前聊天工具。

## 五类操作卡

| 症状 | 最小取证与判定 | 有范围的处理条件 | 同入口复验 |
| --- | --- | --- | --- |
| 模型断连 | 对齐同一实例、聊天、轮次及尝试的开始、首事件、断连和终态；请求构造、上传、服务端读取分别记证据。远控或模型目录错误不自动算该轮模型失败。 | 有明确传输证据才向网络维护方交接。重试前确认上次终态和文件效果；结果未知时先回读。 | 原调用入口、准确请求尝试的终态及实际产物；公开探针只能证明探针自身路径。 |
| 模型看似卡住 | 核当前状态、最后完成工具、待用户或工具的原因和可观察进度。思考、压缩、工具运行与排队不能仅凭静默时长区分。 | 有进度则保留执行；证据不足记未知。只有精确在途对象、当前授权和取消结果可验证时才考虑中断。 | 同聊天和轮次恢复事件或明确终态，必要时由原持有者核后台命令退出与文件效果。 |
| 工作空间加载超时 | 核同实例加载阶段、目录映射、项目登记、路由/TLS错误和工具初始化时序。文件可读不证明应用登记或真实执行正确。 | 运行支持处理本机链；工作台处理登记和导航；明确网络证据交所属网络项目。 | 原应用入口、真实目录、项目归属及刷新结果分别回读。 |
| 会话加载卡顿 | 核精确聊天的索引/记录元数据、路径和加载时序；仅在必要时读取结构元数据或限定尾部状态。累计历史大小不等于单次请求体。 | 保留原聊天和未知写入。确需接力时才按既有接力规范处理，不把清库、重建或新建聊天作为默认修复。 | 列表、同一历史加载、当前状态分别验证；若已接力，再核后继就绪和旧任务收尾。 |
| 工具启动或调用慢 | 对齐具体工具、实例、聊天、调用及超时；保存开关、实际加载、发现、调用分别观察。连接预热不自动等于工具服务启动。 | 只处理已定位工具及当前授权范围；客户端由环境项目维护，业务服务由所属项目维护。 | 实际加载、启动、工具目录及代表性调用分别给结论；目录列出不等于行为通过。 |

被动报告只覆盖它实际采集的层，操作卡不表示工具已经自动实现所有检查。需要第二个观察点时由人工再次单次调用，并保留两次时间和范围，不自动后台采样。

## 案例沉淀与收尾

案例只记录症状、同对象证据、当时干预、观察窗口、效果、适用版本、反例和未覆盖项。进程数、内存、请求大小和静默时间可以作趋势证据，不能直接转为通用故障阈值或自动恢复条件。多项精简和重启后改善不能证明其中一项就是全部根因。

处理结果按 [分层证据矩阵](evidence-matrix.md) 报告。采样完成、诊断归因、修复生效和业务完成分别给结论；没有复验的层继续保留未覆盖或未知。

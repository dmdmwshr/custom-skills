# 浏览器控制恢复与登录复用验收

用于 Codex 无法控制 Chrome/Edge、启动到错误配置、扩展握手失败、导航后等待误判、加载采集器副本出错，以及验证既有网站登录状态。当前工具文档决定可用 API；普通排障不创建浏览器桥接、专用配置或新控制服务。用户明确要求建设独立隐藏浏览器时，按其需求核对现有隔离入口及能力，不把普通排障的范围限制误作实现禁令。

先按 [主机运行环境](platform-runtime.md) 确认浏览器所在系统。下文 PowerShell、Hidden、Browser Tamer 和 `.ps1` 启动器段落仅适用于 Windows；Linux 采用已有原生入口。用户未明确请求浏览器自动化时仅做可独立完成的文件、版本和进程诊断，不创建标签。

## 先区分发生故障的层

| 层 | 直接证据 | 不能据此推断 |
| --- | --- | --- |
| 目标实例 | 固定可执行文件、主进程及正确用户数据根目录 | 扩展已连接或网站已登录 |
| 扩展控制 | 当前工具握手，并可创建、操作和关闭本次自有标签 | 站点登录有效或采集完整 |
| 页面状态 | 同一自有标签的当前地址、可见控件、刷新后的页面事实 | 后续所有调用都会成功 |
| 采集器加载与正文 | 源文件和内存工厂一致、目标身份及完整正文通过实际验证 | 历史账本或外部送达已修正 |
| 登录及复用 | 第一次显示登录后应用界面，关闭后第二次新标签仍直接进入 | 永久免登录或其他账号、配置已登录 |

从 Codex 扩展直接创建标签时，先查实例和扩展层。只有用户的问题涉及系统外部链接选错浏览器时，才转 `browser-tamer` 核对系统 URL 路由；不修改域名规则来修复扩展或页面问题。

## 授权与可自行完成的动作

- 用户要求诊断/状态时只读；用户明确要求修复指定浏览器控制或采集器时，已定位的启动脚本修正、已授权的受限启动、加载正确副本、离线回归及自有标签实测均属于同一工作范围。代码用 Git 或文件副本保留恢复点，配置改动先备份；不为每个可逆步骤再询问。
- 不以一般修复请求扩大到关闭用户窗口、杀不明进程、清理配置、重置浏览器、卸载扩展、修改代理/任务/服务或复制浏览器数据。确需这些动作时先把对象、影响和恢复方式定位清楚，再按当前用户授权判断。
- 只操作本次创建的标签，不读取旧标签、密码、Cookie、令牌、验证码或浏览器存储。账号登录由现有会话复用；需要输入认证信息时停在明确的登录页面证据，不读取保存的密码。
- 已有固定任务或唯一写入者的项目仍在该任务做真实浏览器与业务验收；已有开发任务可承担源码核对、环境修复和协调，不新建替代浏览器 owner 或并行扫描者。普通网页测试不自动授权业务采集、账本写入或发送消息。
- 用户明确要求修复时，停止失败动作与继续维修分开：不重放未知创建/发送，但继续不依赖该动作的源码、配置与只读接口工作。缺少可执行恢复入口时先查当前产品文档/工具和准确错误，不将“请主控修复”或重复失败回执当成修复交付。共享应用由一个明确执行者负责；其本任务用户授权有效时，不为另一个任务的模式限制新增确认流程。

## 实例与启动参数

1. 只读核对已知浏览器安装位置、主进程及用户数据根目录。排除 renderer 等子进程；“有同名进程”不足以通过。进程信息不可读时记为未核实，不当成未运行。
2. Windows `Start-Process -ArgumentList` 会把字符串数组用空格连接。含空格的用户数据目录必须作为一个带引号的完整参数，例如 `"--user-data-dir=<已核实的 User Data 路径>"`；使用一次拼接后的参数字符串，保留内层引号。不能用 JSON 序列化代替命令行引号。
3. 没有路径覆盖参数的标准安装浏览器按其已核实的默认根目录判断；存在显式覆盖时必须解析完整值。错误的 `User` 根目录进程不能满足预期 `User Data` 的检查，不自动删除这个目录或结束该进程。
4. 当前用户授权启动、且正确目标确实未运行时，优先使用项目已有的受限启动器。启动器不接 URL、任意参数、调试端口或会话恢复参数，后台调用使用 Hidden。已经运行但没有扩展连接时不要反复启动。
5. 运行次数和等待上限沿用具体项目约定，不把某个项目的 8 秒或单次重取值写成所有浏览器的通用定律。结果不确定先回读自己启动的目标，不盲目再启动。
6. 复用已有综合桌面恢复器前，核对它还可能启动哪些应用及本轮预期动作。dry-run/退出码不能证明目标已恢复；实际回读 restored 状态、逐应用 started/reused、真实显示会话、profile 和窗口。旁支仍运行时保持复用，不让 Chrome 维修隐式重启其他业务。

启动器与身份校验器必须采用相同契约：若受管校验要求显式 `--profile-directory=Default`，则新启动和既有进程复用两条路径都须检查该参数。只用带正确参数的合成进程测试校验器，会漏掉真实启动器从未传参的问题；补覆盖实际启动 argv 的隔离回归。服务的 Requires/After/JoinsNamespaceOf 也须先核对，启动 broker 可能同时启动隐藏桌面与两个浏览器，不能描述成只影响 broker。

Linux 原生宿主进程存在但 socket 路径不可见，或重新启用扩展后报 `Native transport disconnected` 时，对比浏览器与 Codex 的 `/proc/<pid>/ns/mnt`、`mountinfo`、经各自 `/proc/<pid>/root` 看到的临时目录及实际启动服务的 `PrivateTmp`。同名路径不保证是同一目录；短命恢复服务拉起长期 GUI 后退出，可能留下指向已删除私有 `/tmp` 的浏览器。此时从普通 shell 看不到 socket 不能直接归因为手动删除、插件损坏或未登录。修复负责启动 GUI 的服务契约；正常恢复原资料必须从正确桌面环境和命名空间启动，单纯 `chrome://restart` 可能继承原错误。现存用户窗口的退出与恢复按精确授权协调，不通过手建 socket 或修改浏览器存储掩盖问题；服务隔离调整只针对已证实不适用的启动器。

独立隐藏 Chrome/Edge 的扩展包、原生宿主登记和传输发现要分别核验。自定义 `--user-data-dir` 下可能没有默认资料已有的 `NativeMessagingHosts`；按实际配置根和官方诊断器的显式 manifest 参数检查，不因为日常配置检查通过就跳过隐藏配置。用户明确授权建设/修复独立入口时，可在自有配置范围引用已校验的官方宿主及 origins；不导入安装器私有实现、不修改插件缓存或绕过策略初始化。

隐藏服务必须保留 PrivateTmp 时，本机已验证的替代方案是在该服务通过 systemd `BindPaths` 仅共享原生插件通信目录，而不是取消整个临时目录隔离。优雅结束并备份精确隐藏资料后重启该服务，从双方实际进程视图比较设备号/inode，再验收 CUA 页面操作。临时 nsenter 挂载、socket 软/硬链接不是已验证的部署方案；不要依赖这类临时别名或把它们的失败误判为插件损坏。保留前台浏览器和原业务实例。

本机 X 项目已有 `scripts/start_managed_browser.ps1 -Browser chrome|edge -CheckOnly`，输出正确根目录是否存在、其他根目录进程数和可读性结论；这是只读入口。正常启动仍受 X 项目的 Chrome 首选及 Edge 授权规则约束。该项目的 `tests/test_managed_browser_start_script.py` 已通过真实 Windows 子进程验证含空格参数完整传递、错误根目录不算成功、CheckOnly 不启动和信息不可读不冒充未运行。其他项目复用这一验证方法，不另复制一个漂移的启动器。

依据：[Microsoft Start-Process 文档](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.management/start-process?view=powershell-7.5)。

## 扩展连接与同名视图

1. 使用当前支持的浏览器工具，只列浏览器元数据，不展开用户旧标签。运行内核重置后重新读取映射；短数字 browserId 不可跨重置复用。同一会话只使用其已返回文档中的 API，不把另一工具或另一个任务中的 `getTab`、`tabs.new()`、滚动接口混入当前运行时。
2. 同一稳定 extensionInstanceId 的重复视图可按同一个连接辨认；不同标识且同名，不足以证明它们属于不同用户配置，也不等于两个都坏了。优先复用本次已经验证的目标绑定，不为普通标签错误重新选择浏览器。
3. 用目标连接创建本次自有空白或无账号页面，验证实际控制。必要时可在工具允许的版本页面仅读取 Profile Path 字段以核对配置；内部页面受保护时不绕过，也不把内部页面不可读等同于公开页面不可控。
4. 用户当前明确要求继续测试时，可对已观察、仍符合授权目标的另一个连接视图做一次独立的新标签验证；先说明这不是对同一未知创建请求的重发。次数限定在当前已观察的目标集合内，通常至多两个视图。不在同一失败连接无限循环，不跨到未授权配置或第三种浏览器。
5. `debugger detached`、握手失败、工具内核重置与目标页面登录失败分开记录。通用 `Browser is not available` 不能直接证明进程没运行；先结合只读实例检查再归类。工具没有暴露可执行的连接恢复能力时，明确指出所缺的一步，不编造“已重连”。
6. 创建时报附加或调试器断开错误，不等于标签未创建。先用当前工具明确限定为“本次自动化会话自有标签”的元数据回读，或已取得的自有标签标识，确认同一创建请求的结果；禁止立即重复创建。只在所有权与目标浏览器都可证明时，按当前文档重新取得该已存在标签一次，实际验证可控制后继续。工具没有自有范围的清单、无法确定归属或再次附加失败时，保留控制结果未知，不扫用户标签、不重启浏览器、不要求重新登录。
7. 创建或关闭结果未知时，不能为了找残留而扫描或关闭用户旧标签；无法确认清理时单列清理未核实。用户另行明确要求清理精确隐藏实例全部旧标签时，先完成未知执行器的受审退役及控制恢复，再按该授权清理。task-scoped清单只证明其可见范围，空清单不等于整浏览器无页；首次list也可能隐式创建连接页，未显式new不等于未新增。新标签创建成功并直接返回自有句柄的工具无需额外枚举；验收结束用该句柄关闭。

### 安装状态、策略初始化与侧栏证据

- 先核对当前消息提供的直接工具命名空间，再查可发现工具；`functions.ALL_TOOLS` 只列该执行器能编排的工具，不包含所有直接工具。它没有 `mcp__cua_repl.js` 不能证明 CUA 未暴露。当前工具表确实缺少入口时才报告未注入；不要因搜索为空重置仍持有标签或运行守卫的内核。普通 `node_repl` 与 CUA 即使都叫 `js`、都有 `nodeRepl`，也不是同一浏览器宿主；只有实际工具入口和其返回文档能证明上下文，调用标题或省略命名空间的日志不能代替。
- 任务预览、旧回执中的版本、PID 和启动路径是历史线索，不能直接当作当前最低版本或必需进程。先对齐当前主机实例、运行版本、产品实际生成配置与连接登记；已验收的回退版本不因数字较旧判为损坏。启动器选择变量可能仅供父进程生成配置，子进程缺少它们不能证明代理或启动器失效，应核对实际启动路径及所需运行环境。
- 元数据调用成功但只返回 IAB 时，准确记录 Chrome 未被枚举；这既不证明 Chrome 未安装，也不证明 IAB 页面可控。结合原生 host 的实际连接与登记定位，禁止凭清单缺项升级、重装或要求网站重新登录。
- 插件管理器的 installed/enabled、浏览器中的扩展启用、设置里的安装错误与实际 CUA 控制是不同证据。用户报告重新安装失败时取产品准确错误并核对管理器状态；不用目录插件数量或扩展/宿主不同版本号推定损坏，不反复安装或手改缓存。
- `Unable to load browser request-header policy` 表示浏览器服务策略准备失败，不是网站登录结论。若当前源码将初始化、调用者身份更新与 Ready 状态合并成同一错误，保留未区分结论；仅凭耗时不能断言竞态或网络根因。修复正常初始化链，不跳过 gate、伪造身份/策略响应或要求重新登录无关网站。
- 怀疑 Clash/代理时，核对当前 mode、TUN、域名规则和目标进程代理；持久选择不等于运行核心的实际命中，TUN 开启时 `--noproxy` 也不等于物理直连。无账号探针须区分无效 GET、有效方法及压缩方式，记录状态、首字节/总耗时和响应大小，不输出配置正文；探针 HTTP 200 不能替代实际调用者初始化。桌面 bootstrap 超时与浏览器服务的初始化预算可能不同，按同一进程和时间窗对齐，不能拿旧网络错误或未压缩探针直接判定当前根因。
- 已授权重启后先回读主进程身份、启动时间、资料根及当前工具结果，不重放旧 PID 的停止任务。启动器退出 0 可能转交了现有实例，服务失败也不证明桌面未恢复；记录执行器状态和真实应用状态两项。若正常初始化恢复仍失败、用户已授权更新，先保存可验证的当前版本恢复包，再用官方源做有界更新及真实控制回归；社区同类问题或较新版本号本身不证明修复有效。
- 用户已在侧栏打开 Codex/网页时，核对侧栏与目标任务的关联及当前工具支持的精确标签入口。用户提供的 tab mention 按工具文档定位，不混用别的工具 API；侧栏可用不能替代另一个任务的实际成功。已明确授权的用户标签可作限定核验，但不因此取得关闭权或全量旧标签读取权。
- 进程、profile、注册或产品窗口关联实质变化后，同一目标可做一次有界元数据复验；调用前固定本次工具参数，按需使用工具允许的较长初始化超时。记录外层超时与内部 fetch/策略失败的区别。配置、版本和环境都未变化时不循环同一请求；仍可继续其余维修工作。
- 原生宿主重连后，短 browserId 可能变化而 extensionInstanceId 不变。收到明确断连时用当前工具的浏览器元数据重新精确匹配该稳定标识，再取得本次已知自有标签并回读；不要继续旧短ID，也不因同名而换到前台配置。新宿主刚出现但尚未发现时做有界元数据等待；工具上下文仍缓存旧清单且没有未完成操作时才重建工具上下文，不重启用户浏览器来代替发现刷新。

### 用户明确选择 Playwright 备用控制时

- 先查本机既有受管 Playwright 与当前 CLI 参数，不重复安装全局 npm 包。用户要求复用已登录的日常 Chrome/Edge 时，优先核对 Microsoft 官方 Playwright Extension 的 `--extension` 与配置选择能力；临时配置的控制成功不能满足免登录要求。Chrome 136 起默认数据目录不接受普通远程调试开关，不用复制 Cookie、迁移默认目录或弱化保护来绕过。新装 Edge 也不自动继承 Chrome 登录。
- 官方扩展须安装在用户实际使用的浏览器配置；固定已核实的 profile，按扩展分配给本客户端的标签组操作，只关闭本次自有测试/连接标签。连接令牌只在用户明确提供或授权后配置，保存在用户私有凭据入口；服务会把令牌带入连接页 URL，输出层须精确脱敏，不能改实际认证或浏览器请求。CLI 注册 MCP 可能规范化其他条目的默认值；做前后语义比对并保留无关设置。
- Chrome 与 Edge 可同时配置为不同 MCP 条目，共用受管 Playwright 依赖；分别固定 `--browser chrome` / `--browser msedge`、实际 profile、输出目录及私有令牌文件。扩展令牌属于该浏览器配置，不是网站 API Key，不能从 Chrome 复制给 Edge；尚无令牌时保留官方人工连接确认。用同时存活的两个客户端各自创建测试页，核对浏览器身份和页面隔离，再验证独立重连；不只检查两个注册条目存在。
- 商店页面空白与扩展下载失败分开核验。Linux Edge 可按微软的外部扩展文档登记精确 CRX ID 的 `External Extensions/<id>.json`，指向官方来源的本机 CRX 与实际版本；不改活动 Preferences、复制扩展存储或强制关闭用户窗口。保留包来源/哈希、登记文件和移除方法，浏览器加载及用户启用后再验收，文件存在不等于已启用；不要把未经实测的安装归因或其他平台步骤写成已验证。若工具明确以浏览器安全策略拒绝扩展管理页并禁止替代路径，不再用原始CDP、桌面输入或其他浏览器入口实现该被拒动作；保留已准备材料，准确说明最后启用仍需用户完成。
- 分别验收软件控制、扩展握手、已有登录复用以及独立下一次连接。测试客户端重连时请求函数/响应表必须绑定当前进程；旧闭包导致的请求超时不属于浏览器或令牌失败。记录“备用链可用、原生策略错误仍在”，不将替代控制成功写成原生插件已修复，不迁移业务固定 owner 或监控职责。

隐藏资料有独立控制器时，按本机当前规范选择已验收入口；日常 Playwright 成功不能替代隐藏链验收。官方扩展的客户端标签组隔离可用于按任务分配页面：固定隐藏进程/profile、浏览器专属 token、真实任务 ID；同一任务保留一个客户端，另一个浏览器使用独立客户端。预热/工具发现应不启动浏览器、不假定 MCP 进程必然继承任务环境；缺少任务上下文时由工具显式传真实任务 ID，不能把安装时的某个任务硬编码为全局 owner。普通工具经白名单暴露，任意代码、整浏览器关闭、内部管理页和存储操作不随普通网页验收自动放开。

人工接管先停止新调用、排空已准入操作并断开旧客户端；恢复后使用新连接与新页面引用。断开不等于关闭标签，测试页须由原 owner 在已知状态下关闭，长期页单独登记，手工加入组的页面不能仅因组内可见就推定有授权。未知调用/部分效果工具错误保持暂停；重启不抹掉未知。真实验收覆盖双浏览器同时操作、中文填表/点击、重连、人工模式连读取也被拒绝、恢复新连接以及前台焦点/指针/剪贴板 owner 不变。标签组与同 UID 合作式 broker 不是安全沙箱，也不能宣称未接入的自动页面台账已完成。

### 隐藏浏览器代理与搜索

独立 XDG_CONFIG_HOME、缺少桌面 D-Bus 的浏览器可能读到代理模式 none，而交互 shell 的 gsettings 是 manual。比较目标进程实际环境/启动参数，不把终端代理成功当成浏览器继承成功。用同一公开搜索 URL 对比本机显式代理与不显式代理，再验证真实搜索输入提交及目标站点；TUN 存在时后者不等于物理直连。首页返回 HTTP 200 也不能证明脚本、登录流程或 API 就绪。

已授权维修精确隐藏实例时，可在其既有启动器显式配置受核验的本机 `--proxy-server` 和回环/私网 bypass，不共享桌面总线、不改系统/Windows 代理、不复制登录资料。配置只解析数据、不执行 shell 内容；非法或重复端口拒绝启动，代理未就绪不能静默换出口。优雅退出精确 profile 后保存会话恢复点，启动后核对新参数；旧 owner 仍在时拒绝把复用进程称为新配置生效。SIGTERM 后出现 Z 状态表示等待父进程回收，不是仍运行，不盲目再次杀进程。网络修复、控制层连接和账号复用分别给出证据。

依据：[Microsoft Playwright 扩展说明](https://github.com/microsoft/playwright/tree/main/packages/extension#readme)、[Edge 外部扩展安装](https://learn.microsoft.com/en-us/microsoft-edge/extensions/developer-guide/alternate-distribution-options)、[Chrome 默认目录调试限制](https://developer.chrome.com/blog/remote-debugging-port)。

### Linux隐藏查看器的分层验收

仅在用户已授权独立隐藏浏览器或查看器修复时采用；不接管日常桌面或已有业务owner。

- 区分GNOME工作区、独立X服务器与浏览器profile：前者只是同一桌面的窗口分组，独立显示也不构成同UID文件安全沙箱。复用已核实的隐藏实例，不为查看器维修重建浏览器。更新查看器/控制服务前确认零在途，恢复后对照浏览器PID及资料根，保留登录和页面。
- 核对隐藏服务实际工作区归属及XDG_RUNTIME_DIR，而不是从“现有Chrome”推定为日常host实例。本机browser-automation由AWL独立显示承载，普通AWL入口与隐藏服务的运行根不同；默认根找不到socket不证明工作区不存在。仅按服务的真实运行根/工作区ID/PID/profile选择公开工具，不接管同名日常实例。Windows跨WSL AWL单客户端占用错误不能替代Linux专用Playwright MCP的独立实测。
- AWL0.3.2的`viewer --background`关闭画面流，不表示进程脱离。Screen stream off先核对参数、偏好及当前源码；非阻塞启动由进程管理完成。检查帧生成、绘图回调与实际用户看到画面三层，不能只凭PID或图片文件存在宣称完成。GTK/PyGObject接收帧但绘制报cairo.Context转换错误时，核对发行版Cairo及GI桥接依赖；离线测试须实际调用绘图，不只创建窗口。
- 整个隐藏桌面的等比缩放不改变浏览器视口；两个窗口重叠时先只读核对自有窗口几何，不以Chrome不可见推断未启动。实现切换/跟随尺寸时按UID、exe、完整user-data-dir及当前窗口ID限定目标；用实际几何裁剪和坐标映射，几何变化拒绝旧输入，显示分辨率/窗口管理器限制单独说明。用户点击路径未验证时明确待验收，不把模拟IPC单测当作真实操作通过。
- 页面/原生弹窗显示不全时，同时核对主桌面工作区、查看器边界、VNC画布与隐藏浏览器实际尺寸；窗口本身未越界不证明弹窗有足够空间。已验证的完整显示模式保留1920×1080隐藏桌面、整体等比缩放，默认不随小查看器压缩浏览器；提供最大化和主动尺寸跟随，工具条窄窗自动换行。测试应实际读合成画面的四角标记并验证各按钮边界，不能只证明中心非黑；实际用户页面仍按授权/策略边界验收。
- 人工模式的图像仅供用户查看；代理诊断使用帧/绘制计数及不含页面标题的窗口元数据，不借后台截图或另一控制入口读取页面。键鼠和浏览器切换同属统一接管门禁，关闭查看器不自动恢复代理；未知操作暂停后先回读。主桌面与隐藏Chrome/Edge分别使用各自profile和扩展令牌，商店入口、扩展目录、成功握手及真实控制分层验收，不复制日常令牌来省略独立配置。
- 使用原生 CUA 而非受管 Playwright 时也要纳入项目的接管协调；本机 `native-begin/native-end` 是每组短调用前后的合作式租约，不是替代官方 API 或能阻止同UID旁路的安全沙箱。按返回的稳定扩展标识匹配目标，工具实际返回后才结算。控制完成与业务命中分开：已完整返回且无未决副作用的只读调用，即使定位数为0或业务结果为 `ok:false`，也不应仅因此结算控制 `unknown`；异常、丢回执及可能部分完成仍按真实证据处理。人工接管等待已准入调用结束，未知/超时保持暂停，broker重启不能抹掉未完成调用。测试分别覆盖真实原生操作、人工拒绝新租约、排空顺序和断连恢复。
- 固定Xvfb分辨率不能靠拉伸查看窗口变成真实桌面尺寸。已验证的自有适配可使用私有Unix socket的TigerVNC增量画面和RandR真实尺寸，保持服务端VNC直接键鼠/客户端剪贴板写入关闭，输入仍走统一门禁；不修改上游二进制。GtkVnc只读上层可能抑制剪贴板信号，RFB旧剪贴板也可能丢失中文：可用底层变更通知触发受控UTF-8读取，区分人工同步与自动化不改前台剪贴板。用隔离合成画面测试实际绘制、动态尺寸和中文往返；更新区域计数、draw回调不等于浏览器FPS。
- 剪贴板有内容但导出计数为零时，先只看实际IPC返回结构/类型，绝不打印凭据。AWL0.3.2的get_clipboard返回clipboard.content，取text再默认空字符串会静默失败；缺字段须明确报错。端到端测试必须经过生产broker解析，不能用直接返回text的mock跳过故障层。用户授权复制时，可通过本机查看器的精确可访问按钮触发，内存比较隐藏与主桌面剪贴板相等后只输出布尔结论；这不授权操作受浏览器策略阻止的扩展管理界面。

### 已完成只读调用被误结算 unknown 的专项审计

普通 unknown 仍不得清锁、重放或试错 resume。WSL 已验证的一次事故对账入口绑定该事故常量、完成原件和独立授权，且单次 journal 已消费；它不是可复用于其他事故的通用恢复命令。精确代码、授权、执行回执与结束时点按本机 browser-control 说明追溯，不把历史 paused 状态当成后续 owner 必须维持的状态。

- 原件与转述分开：通过现有官方 daemon 精确读取 task/turn/call 的完成项，只留元数据及必要 JSON 摘要；不为找证明启动模型 runner、扫描全量聊天或输出 AX。固定原始调用、完成回执、源码和安装哈希，不能凭调用者布尔或任意旧收据认定已知。
- 将真实执行、调用方变量错误、业务校验和结算/报告分开。先保留实际返回，再生成摘要；正常返回后的 `ReferenceError` 不能单凭外层 catch 结算为执行 unknown。安装器已持久 committed 后，额外报告失败也先只读核对正式提交及逐目标哈希，不重跑安装。没有可核验完成记录时仍保持未知，不凭“可能已成功”继续。
- 跨重启时 `/run` 控制文件消失不是已知空闲；未知、在途及已准入请求须有受保护的持久记录，缺失/损坏/恢复不完整都失败关闭。旧事故 grant 若绑定旧 boot/PID/control，不能拿来恢复新实例，也不能造旧记录。确有已审历史完成证据且获精确修复授权时，另做绑定新实例的窄恢复，保留两事故各自审计；首次持久状态只由该入口独占建立。受控恢复成功不代表CLI握手、页面或业务验收通过。
- 同值文件写入不等于页面操作。冻结实际代码，结合同一 PID/start_ticks/boot/epoch，检查 native 已移除、零在途/worker 后内存 unknown 是否锁存，以及 request/native-begin/human 和其他可达入口是否能准入。被拒 takeover/resume 或状态防漂移可能仍保存文件；来源未明须保留不确定，不能推定用户点击。查看器 `full_view→view_action→takeover` 要与实际启动、`schedule_fit` 的 human 条件和日志结合，不能只看调用链；当前 disabled 也不证明历史全程 disabled。合作门禁不排除同UID恶意写入或直接绕 gate CUA。
- 若精确修复另获授权，先隔离测试、冻结变更 pin、独立审查，再分开安装与执行窗口。本次受审机制包括 root 身份校验、受保护父目录、短 grant 绑定完整 inspect target、首次 boot predecessor/零在途/无客户端查看器检查、请求前 O_EXCL 持久 reservation，以及匹配 committed 前禁止恢复。首启动窗口若会被旧查看器注册/轮询污染，须在已获准安装窗口核实精确 PID/start_ticks/安装归属后正常关闭该查看器并确认退出；不是关闭浏览器，也不授权重新启动以伪造 pristine。
- 控制文件的 mtime_ns/ctime_ns 等可能超过 JavaScript 安全整数。用 Python 整数或其他无损解析逐字段核对，固定原始字节与哈希；不得 JSON.parse/JSON.stringify 经 JS Number roundtrip 后构造 grant、比较指纹或保存所谓原件。不同合法 JSON 编码可有不同哈希，应读正式文件而不是借用 stage 哈希。
- 隔离回归使用完整合成记录与临时路径/哈希注入，禁止 setUp 偷读真实 owner rollout；真实原件只作独立只读证据验收。网络、生产数据、browser/worker/IPC 隔离，GTK 用专用 Xvfb；无显示导致的环境失败与代码失败分开，不借生产显示跑测试。
- 执行只提交获准的那一次，任何错误、超时、部分落盘都不重试、不删 journal、不重发旧 end。成功回读 reserved/committed、grant/proof/code pins、完整整数控制指纹、同一实例/epoch及结束状态，保存真实 stdout/退出码。修正误报后仍 paused 是本次交接时点；回执签收后结束维护者控制与轮询，由原 owner 按正常流程恢复，不重写历史结束状态，也不以技能发布要求生产继续暂停。技能发现用无模型 turn 的新进程，不启动业务扫描者。

真实未知与上述误报对账不同：若业务已完成失败收口，用户明确批准退役未知执行器后恢复，本机已验证可保留浏览器及CUA，只结束精确broker/CLI/guard；在原owner撤销证明、进程终结、调度暂停和原件保全齐全后，独立建立新的paused/零在途代次。旧请求仍unknown且不可重放，不能以新状态补造其known完成。恢复脚本绑定该事故/boot/PID/原件并以一次intent防重入，不提供通用清锁；信号前留恢复点，受保护进程不变才验收。一次成功与后续页面清理、MCP可用、业务恢复分别报告。

## 页面就绪、正文及加载副本

- 导航成功、时间链接出现和初次 AX 快照都不保证目标正文已经挂载。依据当前工具文档，在 UI 动作后获取新状态；只读 DOM 提取与等待使用相同的目标范围。
- 本次已实测的一类故障是：单次目标等待在整页预算尚有余量时失败，而下一次显式页面状态刷新可见完整目标。适用修复是在目标尚未出现时、原有共享预算内先刷新一次状态，再做单次等待；不在失败之后以新页面事实覆盖旧失败，不增加无限重试或固定睡眠。具体站点需实测，不假定每个超时都属于该原因。
- 列表或搜索卡的作者自己的“显示更多”表示预览可能截断。按该站点已审计逻辑核验规范原帖及完整正文，排除引用或父帖内控件；身份、UTC、链接和预览前缀必须一致。仍截断不能当完整正文分析。这属于采集逻辑，不是更换浏览器的理由。
- 长工厂代码经过模型转写可能产生字段或括号差异。新加载或版本变更后，使用源文件及运行工厂的确定性指纹比较，再开始实际采集；只比较版本号不够。业务代码已有 `sourceFingerprint()` 时优先调用，不现场生成新的浏览器执行代码、内部导入、eval 或桥接。
- 指纹需要明确编码/换行规范、长度和摘要；例如 X 驱动的完整具名工厂使用 LF 规范化及 FNV 检测意外转写，不能称为密码学签名。预期值由本地实际源文件计算，禁止硬编码运行返回值或修改业务输入掩盖加载偏差。
- 指纹不一致的结果不用于签收或上线。修复后同时验证实际加载副本和原先失败的真实页面；离线测试只验证相应实现，不冒充实际浏览器成功。

## 网站登录复用

1. 用户明确要求测试的浏览器、配置和站点分别记录。打开本次自有标签，仅核对最终地址、登录控件以及登录后应用导航，不读取聊天正文或其他业务内容。地址正确和没有登录输入框只是辅助证据，必须直接观察至少一个登录后可见的通用应用导航控件；不能由地址或控件缺失推断它存在。
2. 飞书可对精确的“消息、日历、云文档、通讯录”等通用名称作可见性查询，不读取聊天列表、消息或全文快照。初始挂载未完成时，对已知导航控件作一次有界等待，再回读实际可见状态；仍不可见则登录未验证，不填成功值。
3. 显示已登录应用界面后，关闭本次标签，再新建第二个同址标签；两次分别保存是否出现认证输入、直接可见的导航名称、是否关闭的简短回执。没有输入密码或验证码仍直接显示应用导航，才能报告“本次新标签复用已验证”。历史验收只作方法依据，后续登录状态必须重新验证。
4. 若控制层失败，登录状态记为未验证，不能要求用户重新登录来解决扩展故障。若直接显示登录页，才报告该配置当前需要人工登录；不推断其他配置也退出。
5. 飞书网页登录与机器人 API 直送是独立链路。网页复用测试不发送探针消息，也不把消息已收到或传输接受当作网页登录证据。
6. 实测结束关闭自己的标签。报告当次复用有效，不承诺登录永不过期。

## 官方 CLI 私有工件权限与收尾

已验证：共享任务根存在default POSIX ACL时，子进程umask077不能保证文件0600/目录0700。受管入口只在本次新建、身份已核实的私有session根上用不跟随链接的目录fd剥离继承ACL，再创建子目录；不能修改共享父目录ACL或以chmod整棵活动目录掩盖问题。验证应包含真实子进程创建文件及后续audit/精确cleanup，不能只检查顶层目录mode。

CLI执行、release和工件清理分别记录。已知release后立即撤销客户端，再以受管audit返回的完整精确清单一次cleanup；后续审计/删除失败不改写浏览器unknown，不自动重发release/cleanup。记录未清理对象与归属，不输出快照正文。无在途/进程且授权范围精确才处理残留；重启、超24小时或目录存在都不自动授予清理权，不从临时文件恢复旧事实或租约。官方CLI和Skill仍按上游管理器更新，不为禁止临时文件维护定制CLI，也不将自建适配规则写入官方缓存。

## 修复闭环与简短回执

用户要求完成修复时，把源修改、适用离线检查、已授权部署、实际页面验证和版本/哈希回读做完。受管 Skill 在源仓提交、推送后，Linux/WSL 按本机 `skills-management.md` 使用原生发布器安装、哈希核对与新进程发现；Windows 按当地 CC Switch 的预演、备份同步及副本核对流程。不要在 Linux 恢复 Windows 管理链或直接改安装副本。唯一任务限制优先，不另建业务任务做发现测试。

每个浏览器分别报告：实例是否核实、控制是否实际通过、页面或登录是否通过、第二次登录复用是否通过、自有标签是否关闭，以及已修复对象和仍缺的证据。未执行写“未验证”，不写“正常”；无需展示内部 ID 或长命令。保持浏览器控制恢复、采集修复、正式周期完成和外部送达为各自独立的结论。

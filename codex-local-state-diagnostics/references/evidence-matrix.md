# Codex 本地故障分层证据矩阵

本文件只定义只读诊断的证据口径。每次检查只采集能区分当前症状的最小字段，不把完整日志、会话正文、访问正文或凭据复制到回复。

## 最小证据卡

每个结论至少记录：

| 字段 | 要求 |
| --- | --- |
| 对象 | 完整任务/会话 ID、host、项目和实际工作目录；不得只写短前缀 |
| 时间 | 北京时间和必要的 UTC 对照；注明是事件时间还是当前回读时间 |
| 阶段 | index、sqlite、rollout、app-server、MCP、网络、用户任务或 archive |
| 事实 | 原始状态的脱敏摘要、计数、时间顺序或哈希前缀 |
| 证据源 | 官方任务工具、文件元数据、SQLite 只读查询、进程/系统查询或网络探针 |
| 结论 | 已证实、高度可能、尚不能确认或结果未知 |
| 缺口 | 仍缺哪一个同对象、同时间窗或回读证据 |
| 动作 | 仅只读，或精确授权后的变更、备份和回读 |

## 阶段判定矩阵

| 现象 | 先查 | 可证明 | 不能直接证明 |
| --- | --- | --- | --- |
| 新会话长时间加载 | 索引、SQLite、rollout、app-server 启动顺序 | 本地状态读取或启动排队在哪一层停住 | 项目代码、模型或远端服务必然故障 |
| 历史缺失或打开超时 | 索引引用、SQLite 线程、rollout 路径 | 引用是否存在、可解析及路径格式是否异常 | 消息已经丢失 |
| 工具列表或 MCP prewarm 超时 | 启用项、命令/工作目录、子进程树、stdio 日志 | 某个 MCP 启动或握手失败、重复进程和排队关系 | 所有 MCP 都坏或网络是唯一根因 |
| 反复重新连接 | app-server 时间线、WebSocket、代理、TLS | 断线发生在本机、握手、应用层或请求体阶段 | “正在重新连接”文字本身代表失败 |
| HTTP 403 探针 | 探针是否带认证、TLS 校验、目标路径 | 未认证请求收到应用层拒绝且传输可达 | 浏览器登录态、会话健康或证书信任 |
| TLS EOF/证书错误 | SNI、发行者、主机名、代理/MITM、IPv4/IPv6 | 指定一次握手的失败层 | 另一种网络路径也必然同样失败 |
| SSH 能登录但 Remote-SSH 不工作 | SSH 认证与动态转发分别查看 | 认证成功或转发被策略拒绝 | Remote-SSH 已就绪 |
| 归档命令返回成功 | 官方任务工具写入后按完整 ID 读回 | 目标 archived/title/project 状态实际改变 | 本地数据库或索引已经同步 |

## 索引、SQLite 与 rollout 的冲突处理

1. 索引无效行、重复 ID、引用路径缺失分别记为三个事实；不把它们合并为“数据丢失”。
2. SQLite integrity_check 为 ok 只代表结构能读；还要分别核对线程计数、归档状态和 rollout 路径。
3. 索引计数、SQLite 线程计数和官方任务列表不一致时，保留各自观察时间，不用最新一个覆盖其他来源。
4. 扩展路径、UNC 路径或旧项目目录能解释“当前引用不可读”，但必须有对象和时间对应才能说它影响了目标任务。
5. 候选路径、候选 ID 或父子关系有歧义时，结论只能是尚不能确认；不以日期、标题或共同前缀猜测。

## app-server、MCP 与进程风暴

按父子关系和启动时间排列进程，不按进程名总数直接判定故障：

- app-server 的启动时间早于配置修复时间，说明旧进程可能仍持有旧配置；它不是“修复未生效”的唯一证据。
- 同一 MCP、docker mcp gateway 或工具服务出现多组相同启动时间，且与 prewarm 超时相邻，才可标为高度可能的重复启动/排队放大。
- Node.js、Python、Docker 进程总数应按父进程、命令路径和目标工作目录过滤；开发环境中的其他进程不能算作 Codex 子进程。
- 进程存在只证明句柄或进程仍在，不证明握手、工具列表或业务请求健康。
- 命令行可能携带令牌、路径参数或私有 URL；回执只保留可执行文件类别、是否存在、退出类别和数量。

## 网络证据分层

将每次探针标记为以下一种或多种路径：

1. 系统代理到本机监听端口。
2. 应用自有代理、TUN 或直接路由。
3. 出口到目标的 DNS、TCP 和 IP 家族。
4. TLS 证书、主机名和代理是否重签。
5. WebSocket/HTTP 应用响应与请求体读取。

WinINET、WinHTTP、应用自有代理和 TUN 不互相代表。公开探针必须记录目标类别、时间、IP 家族、是否经代理和认证状态；不记录 Cookie、正文或完整私有地址。累计会话记录大小与单次实际回传大小必须分开。

## 状态词和回执

- healthy：该层在观察时间内通过了直接检查，但不替代下游层。
- blocked：有直接拒绝或缺失证据，说明该层阻断了当前路径。
- inconsistent：两个事实源在同一时间窗冲突，需停止自动修复。
- deferred_active_target：更新因目标程序活动而延期，未杀进程、未重启。
- check_no_update：检查完成且没有需要应用的版本或配置变化。
- update_applied：更新后版本/哈希和任务回读一致。
- result_unknown：动作或传输可能已被接受但未取得最终读回；禁止重试。

同一回执只写一个主要结果，其他层级作为证据和缺口列出。网络可达、工具启动、任务完成和用户可见送达不能用同一个状态词代替。

# 回测 runner 与证据契约

本文件只补充 `$okxnew-backtest-operations` 的字段和判定口径；项目已有字段优先，不能为了套用示例而改写计划或数据库。

## 运行状态最小回读

一次回测运维回执应能关联以下事实：

| 维度 | 必须回答的问题 |
| --- | --- |
| plan | 哪个冻结计划、来源清单、时间范围和运行输入被使用？ |
| job | 原 job ID、窗口、状态、重试次数和最后检查点是什么？ |
| runner | 唯一 runner 的 owner、进程链、锁和租约是否匹配？ |
| retry | 最近一次状态/原因、`retry_attempt_count`、`Retry-After` 和 `next_retry_at` 是什么？ |
| dataset | 候选/已验证版本、原始/规范化哈希、覆盖、行数和连续性如何？ |
| semantics | 数据是否闭合、时间戳是否单调、是否通过无前视与预热门禁？ |
| report | 三段数据边界、策略执行证明、产物哈希和阻塞项是什么？ |

任何一个硬事实没有回读，不把成功文字、日志末尾或前端进度视为完成。

## 状态转换

`queued → running → complete` 只允许在检查点、产物和硬门禁都验证后发生。网络限流或暂时不可达进入 `retry_wait`；数据不完整或解析不可信进入 `dataset_failed` 或 `evidence_blocked`；官方覆盖或身份不能证明进入 `blocked`。重启只能从原子检查点恢复，不能清理 blocked、重置重试次数或重建 job。

`blocked` 不等于某个独立 job 永久停止：无依赖的原 job 可以继续，但冻结计划的最终状态仍不能越过阻塞。对一条 job 的“完成”也不能掩盖同一计划其他 job 的 `missing`、`evidence_blocked` 或 `dataset_failed`。

## 原子候选与隔离

新下载先写独立候选，完成长度、时间范围、行数、唯一性、顺序、OHLC 合法性、闭合边界和内容哈希检查，再以原子指针切换。旧版本保留为只读审计对象；失败候选移入隔离区并记录原因，不能删除旧版本、直接覆盖验证版本或把候选路径冒充正式数据集。

## 不支持的晋级

以下证据不足时必须保留未完成状态：空响应或零行、只有 HTTP 200、只有网页截图、只有最近市场快照、只有外部订单列表、只有局部窗口、只有代码测试通过、只有 `transport_accepted`/进程启动回执、只有单个 job 完成，或只有计划文字没有当前产物回读。

# OKXnew 数据模块运维

## 范围

只处理 `C:\Users\12070\Desktop\项目开发\OKXnew`。优先使用项目常驻数据链；BLS 发布日历固定由浏览器读取官方年度页，其他已登记宏观页面按产品状态作为备用采集面。浏览器不替代 OKX K 线后台，也不成为交易授权来源。历史下载、冻结计划和回测 runner 只做状态核验并转交 `$okxnew-backtest-operations`。

始终保持以下边界：

- 全部 live 线性 USDT 永续只维护 K 线和必要官方合约元数据；只有当前收藏进入附加市场数据、信息面、策略、计划、授权和模拟执行。
- 只访问 OKX、BLS、BEA、Federal Reserve、Census、DOL 等计划已登记的官方公开来源；不读取 `.env`、密钥、Cookie、浏览器存储、账户、仓位或委托。
- 不抓取 CME 经济日历，不采集 OPEC 报告正文，不调用正式盘或真实下单路径。
- 自动巡检不修改源码、`PROJECT_PLAN.md`、Windows 任务或服务，不重启进程。需要工程修复时只报告证据和建议。
- 不把空响应、翻译后的页面文本或第三方镜像写成成功数据。

## 分层健康回读

每次巡检先生成一份带 `observed_at`、作用域、最近成功时间、覆盖水位和证据原因的当前快照，并在采集或修复后重新读取同一层级。固定区分以下五层，不能用其中一层代替其他层：

| 层级 | 回读重点 |
| --- | --- |
| `favorites` | 当前收藏的行情、K 线和附加市场数据是否新鲜、连续、可读 |
| `all-market` | 全市场产品快照、全量 K 线水位、缺口和失败/等待分布 |
| `strategy` | 策略输入 readiness、候选状态和策略执行健康；不把候选当成回测证明 |
| `simulation` | 模拟/回放对象、数据版本、等待缺口和产物可读性；不触碰真实执行 |
| `history` | 历史计划、原 job、唯一 runner、锁租约、检查点、覆盖/预热和来源证据 |

每层的证据状态统一使用四态：

- `verified`：身份、时间、覆盖、完整性和哈希等要求已通过。
- `not_applicable`：当前计划明确不需要该产品或来源，并记录原因；不能把“未采集”写成健康。
- `missing`：本应存在但当前没有足够数据、覆盖或回执；进入等待/补采/阻塞。
- `evidence_blocked`：数据或服务可能存在，但身份、报告期、单位、修订、冲突、时间语义或哈希无法安全证明；失败关闭。

`healthy` 仍可作为接口/传输层的运行分类，但不能替代上述数据证据状态。历史快照、任务启动回执或单个产品成功不能证明当前五层均健康；API 成功也不能代替页面、数据集和产物的实际可读性。

## 工作流

1. 读取 `http://127.0.0.1:8100/api/v1/health` 和 `/api/v1/data/monitoring`，并按上面的 `favorites`、`all-market`、`strategy`、`simulation`、`history` 分层记录服务状态、七周期 K 线应有缺口、收藏专属产品、宏观日历/实际值水位、模拟回放和历史 runner 证据。每层同时记录四态证据状态、观察时间、覆盖起止和失败原因。
2. 若 Web/API 不可用，标记 `service_unavailable` 并停止写入；不要自行启动或重启服务。
3. BLS 日历只在每日刷新窗口、状态失败/陈旧或官方已发布下一年度日程时使用浏览器；不再尝试 BLS 日历 HTTP 直连。其他官方宏观产品最近成功仍在 24 小时内且状态健康时不重复启用浏览器，只有失败、陈旧或进入刷新窗口才读取并执行 [官方宏观浏览器采集](references/official-calendar-browser-fallback.md)。每个来源、日历与实际值子产品独立收口，一个子产品失败不得阻断其他来源。
4. 浏览器捕获必须经项目 `okxnew.data.browser_capture` 从 UTF-8 标准输入校验并导入。导入器按路由固定请求方法、官方 URL、HTTP 200、媒体类型、带时区采集时间、正文标记、大小和 SHA-256，再复用来源专用解析器和 SQLite 只追加版本存储。
5. BLS 官方年度页是当前发布日历的浏览器事实源：既有事件按统一类型、规范报告期和发布时间锚定稳定身份，改期只追加同一身份的新版本；只有明确晚于现有覆盖尾部的新年度事件可创建新身份，历史未匹配、一对多或歧义必须失败关闭。BLS 就业发布页仍只登记正文哈希并交叉核对。BEA、联储、Census、DOL 的网页/JSON 路由可在校验后写入各自日历产品；联储政策声明和 DOL 全国周度 XML 可写入实际值产品。
6. BEA 与 Census 的公开发布网页只能作为发布证据，不能从标题、摘要或翻译后 DOM 推断完整实际值；两者结构化实际值由项目已配置的官方 API 短任务维护，本技能不读取或管理凭据。没有明确解析器与导入路由时不得自行扩展。
7. 导入后重新读取宏观日历、实际值与数据监控接口，按来源确认事件数、观测数、报告期、单位/季调口径、覆盖起止、原始内容哈希、规范化数据哈希、最远水位、最近成功和连续失败。重复正文应为幂等导入，不得新增重复版本。
8. 如果历史数据、预热、研究/验证/未见分段或回测 runner 是请求目标，只输出当前数据证据和转交摘要，改用 `$okxnew-backtest-operations` 执行其冻结计划与回测门禁；本 Skill 不创建替代 job、不启动第二个 runner、不发布回测结论。
9. 以自然中文报告：本次是否采集、各官方宏观源事件数/观测数/水位/哈希前 12 位、BLS 年度页解析数、稳定身份匹配数、追加版本数、允许的新事件数、被拒绝歧义、五层健康与四态证据、全市场 K 线应有缺口、收藏附加产品状态、当前失败，以及确实需要用户处理的许可或业务映射事项。

## 来源证据与损坏数据隔离

每个来源、日历、实际值和 K 线数据集的状态回执应至少能回到：固定来源身份和请求/最终 URL、带时区采集时间、报告期、单位/复权/季调口径、覆盖起止、观测或行数、版本/修订标记、时间粒度、原始内容 SHA-256 和规范化数据 SHA-256。任何字段不能证明时，标记为 `missing` 或 `evidence_blocked`，不能用 HTTP 200、页面标题、空响应或第三方镜像补齐。

发现损坏、乱序、重复、时间缺口、OHLC 不合法、版本冲突或哈希不一致时，按“隔离旧版本指针 → 写入独立候选 → 校验身份/范围/连续性/闭合/哈希 → 原子切换正式指针”的顺序处理。旧版本保留为只读审计对象，失败候选留在隔离区并带原因；不直接覆盖、删除或把候选路径冒充正式版本。只读巡检不得执行切换，只报告当前指针、候选和证据状态。

## 失败分类

- `healthy`：接口可回读且产品最近成功。
- `network_path_blocked`：某一官方固定页面或同源请求被明确拒绝；不换域名。
- `browser_unavailable`：当前 Codex 环境没有可用浏览器能力；不改用独立浏览器脚本绕过。
- `import_rejected`：路由、来源、状态、类型、哈希、时区或正文结构校验失败；不写数据库。
- `identity_anchor_rejected`：BLS 年度页事件无法唯一锚定既有稳定身份，且不是明确的未来覆盖尾部；拒绝创建重复或猜测身份。
- `corroboration_mismatch`：BLS 就业页与当前规范事件不一致；只保留证据哈希，不晋升、不覆盖。
- `service_unavailable`：OKXnew Web/API 不可访问；只报告，不擅自重启。
- `missing`：计划需要的数据或证据当前不存在；不把零行、等待或旧快照当成成功。
- `evidence_blocked`：身份、报告期、单位、覆盖、哈希、修订或时间语义存在不可安全消除的歧义；失败关闭。

## 输出约束

不输出原始网页正文、完整 UUID、数据库路径、命令行或内部 JSON。只有在排障确有必要时才给出脱敏错误类别。若无需用户动作，明确写“当前无需用户处理”。

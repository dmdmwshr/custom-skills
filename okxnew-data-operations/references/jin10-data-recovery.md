# 金十优先与仅采集恢复

适用于项目已明确选择金十优先、黄金现货或仅采集模式的任务。项目计划决定历史年限、策略标的和资金假设；本页不把某次计划的十年、月投入或 A/B 权重推广成所有项目的默认值。

## 来源与历史范围

1. 先核对既有接入的真实能力，区分金十 MCP 工具与公开数据中心。2026-09-21 实测 `tools/list` 中 `list_calendar` 仅当前自然周，`get_kline` 为代码/分钟周期/条数接口；不能据此声称存在十年宏观或 OKX 现货历史。
2. 同次实测金十官方页面 `https://datacenter.jin10.com/` 的公开脚本 `https://cdn2.jin10.com/dc/js/utils/index.js` 指向 `https://datacenter-api.jin10.com/reports/list_v2`。`category`、`attr_id`、`max_date` 及列标题必须按当前站点公开配置核验；公开应用标识不是用户登录凭据，不照抄私有令牌。项目 `gold_sources.py` 保存已审映射与解析器。
3. 已验证的报告是 SPDR 黄金持仓（etf/1）、美国 CPI 月率（ec/9）、核心 PCE 年率（ec/80）、非农（ec/33）及联储利率决定（ec/24）。这只是已验证子集，不能推断整个金十缺少其他指标；SPDR 单一基金不等于全球黄金 ETF 流量。
4. 分页按当页最早日期减一天向前推进；每页保存内容哈希与检查点，验证列结构、行宽、日期及游标确实推进。首次冻结项目要求的起止范围，后续重启复用，完成后增量更新；保留已有更早数据，不重导旧库。
5. 超时、429、认证错误、未知或结构漂移均不是“没有数据”。保留来源和检查点、遵守 Retry-After；仅当缺项/缺区间有证据时建立补充映射，并注明精确覆盖、单位和时间语义，不静默拼接不同口径。最新数据过期也要独立标记，不能把历史页成功当作最新可用。

## 时间与现货证据

- 分开保存观察期、来源报告日期、公布时间、响应取得后的首次取得时间、版本及原文哈希。无证明的字段保持未知，不能拿采集周期开始时间冒充响应取得时间。
- 金十上述历史列表的日期尚不能证明观察期/精确公布时刻，也不提供已验证完整历史修订链。记录 `research_only`、`publication_timestamp_unavailable`；不伪称支持严格无前视回测。
- 周五截止快照必须同时满足公布时间和首次取得时间不晚于截止点，且使用当时可知版本；缺任一证据就从严格时间点回测中排除。当前补采不能反填成历史上已经取得。
- XAUT-USDT 必须由 OKX 公开 instruments 的 SPOT 身份、币种、上市时间、tick/lot/minSize 核验。现货基础币/计价币成交量不能套用永续合约张数或乘数；保留既有永续集合，独立存储新增现货。
- 各周期单独报告实际首尾、闭合根数、缺口和冲突。上市前历史不可补造；只有日线回补不等于七周期十年完成。不足一年时不输出完整 52 周位置；技术指标不代表买入建议。

## 恢复与验收

- 回读初始激活、当前 release binding 和单元实际发布路径；`activating/auto-restart + MainPID=0` 不算已停服。停止本项目精确单元并验证空 cgroup，保留本次控制文件恢复点和原迁移证据。
- 用项目既有独立 worker（6GiB 内存、512MiB swap、TasksMax64、硬超时、KillMode=control-group）串行验证、构建及安装。管理员构建开发用户仓库时，Git 信任只限定到已核对的精确仓库，不配置全局 `safe.directory=*`。
- `data_only` 保持 `simulation_only`，服务与 API 双层拒绝交易、派发和外发。不加载通知网关凭据，不启动旧官方补采定时器或历史回测 worker，不重放旧通知。队列领取、过期租约恢复及旧任务退休都必须限制在当前允许的类型/前缀，而不仅仅限制 handler。
- 验收真实退出码、实际部署校验器、唯一进程与重启增量、原采集集合、现货与宏观水位、幂等/冲突、限流恢复、重启检查点及只读页面；对照恢复前后交易/通知聚合数。历史旧失败保留，不伪装成当前故障或本次成功。
- 失败只回退本次控制配置/发布，不回退新增业务数据。更新唯一计划、运行说明、交接与覆盖报告；数据恢复、历史回补中、严格回测限制分别陈述，不以服务 active 替代研究可用性。

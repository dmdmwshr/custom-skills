# Codex 项目管理

把用户要求落实到准确对象：项目显示名、磁盘目录、应用项目登记、聊天归属、会话执行目录、自动化/服务引用分别处理。改一层不代表其他层已改变。Codex 和 Claude 均可使用本 Skill；能执行哪些动作，以当前主机的官方工具、接口及界面能力为准。

## 选择本次流程

| 用户目标 | 按需读取 |
| --- | --- |
| 规范项目名称、确认侧栏是否保存 | [项目改名与桌面核验](references/desktop-projects.md) |
| 移动实体目录、修改项目路径、重建项目登记 | [路径与项目登记迁移](references/path-and-project-migration.md) |
| 旧会话仍用旧目录，需继续、迁移归属或重建会话 | [会话与绑定处理](references/session-rebuild.md) |
| 判断本机工具能否触达目标、区分历史经验与当前能力 | [证据与工具入口](references/evidence-and-tools.md) |

只读当前模式需要的参考。单纯改名不开展目录迁移或会话重建；创建/安装本 Skill 不触发任何真实项目迁移。

## 开始前确认

1. 读取目标项目规则和唯一状态入口，确认本轮允许的动作、主机、当前目录及目标目录。按现有总表查重，复用唯一主仓和现有项目，不因显示名不同建立另一套活动源码。
2. 核对实际客户端、版本、活动状态目录和工具能力。优先当前应用提供的项目/聊天管理工具；CLI 或 app-server 必须确认当前版本的公开协议，不能猜接口或字段。
3. 保存精确对象基线到仓外：项目 ID、主机、显示名、根目录及主目录顺序；涉及会话时加真实线程 ID、归属、状态及执行目录。只读元数据，避免加载活跃会话正文或整段媒体历史。
4. 涉及磁盘或运行入口时，再核对 Git、未提交修改、链接/联接、进程、服务、计划任务、自动化和恢复依赖。未涉及的层级不顺带更改。

**不要混用项目 ID。** 桌面应用与独立原生 app-server 的项目列表可能不是同一记录域。先按主机及规范化的实际根目录建立唯一对应，再分别记录各自 ID；不能把某一列表的写入成功当成另一列表已更新。路径歧义、重复登记或多根项目必须先消除歧义。

## 操作与授权

- 当前用户的明确目标包含范围内必要的实施、验证和回读，常规可恢复操作不重复确认。创建新会话、实际迁移、项目移除、外发和服务启停各按本次目标判断，不能由“核对”或“整理 Skill”推导。
- 优先后台，尽量少用前台。在已授权任务范围内，后台不可用或无法完成时可以直接短暂前台操作，无需另问；遵守用户对本次任务明确提出的不抢焦点或禁止前台要求。每次动作绑定新鲜窗口/控件状态，核验真实效果并恢复前台及鼠标状态。
- 项目新增/重建遵守当前工作台准入规则。规则要求人工添加时，助手完成目录、规则、交接和准确路径准备，用户添加后回读；不能借原生命令接口或内部状态文件绕过。用户明确改变该规则时以当前指令为准。
- 一次变更一个精确对象，写入前核对基线未变。超时或结果未知时先查现状和原回执，不重复创建、重建或移除；仅在查明未执行且原因已处理后继续。
- 不直接改 Codex SQLite、全局状态、线程索引或会话 JSONL 来伪造迁移。保留旧线程、唯一恢复副本、未提交修改、暂停状态和失败证据，不能用重跑业务掩盖损失。

## 验收与交付

按本次实际涉及层级逐一回读：文件实体 → 应用项目及路径 → 聊天归属 → 会话实际执行目录 → 调度/运行入口 → 必要业务行为。未检查、待人工操作、失败或未知结果分别写明。

改名可用只读脚本核验同一桌面记录域的前后快照：

```text
python scripts/verify_project_rename.py --before before.json --after after.json --plan plan.json
```

输入为应用 `list_projects` 的 `{ "projects": [...] }` 或其 MCP 文本包装；计划为 `[{"projectId":"原ID","label":"原名","target":"新名"}]`，改名目标须为有路径的本地项目。完整快照可包含未改动的远程/云项目。脚本验证 ID 全集、精确目标名称以及其他项目字段保持，不访问应用、不修改文件；它不证明 GUI 显示、分区、聊天或磁盘内容已验收。输入格式/范围不适用时报告核验工具限制，不能据此断言应用改名失败。

将用户直接指令、已完成层级、剩余断点、恢复点和回执位置写入项目原有唯一状态文档。只修改显示名时交付简短结果；需要迁移/重建时给出旧→新对象映射及各层验收结论。

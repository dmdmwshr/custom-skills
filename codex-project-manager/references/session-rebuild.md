# 会话与绑定处理

先选择能满足目标的最小动作。项目显示名与聊天标题不同；聊天归属、历史保存目录和当前实际执行目录也不同。

| 场景 | 处理 |
| --- | --- |
| 只调整聊天所属项目/侧栏 | 使用应用移动/分区工具；再读归属，不宣称执行目录已变 |
| CLI 要在指定目录继续同一历史 | 核对 `resume`/`fork` 当前语义、精确线程 ID 和目录覆盖选项；单独验证运行目录 |
| 同一工作需要精简上下文接续 | 用户明确要求后使用 `codex-project-task-handoff`，沿用唯一状态文件 |
| 原目录已失效、当前入口无法可靠切换 | 用户要求重建时在已核验的目标项目/目录创建一个候选新会话 |
| 固定机器人/定时会话 | 由拥有绑定的项目负责，普通聊天创建不代表路由或调度已切换 |

`codex resume` 当前支持显式 `--cd` 目录选择；不要把这项能力笼统否定，也不要把 CLI 当前运行目录当成桌面既有会话已永久迁移。`fork` 保留历史，不适合仅为缩短上下文而重建。[Developer commands](https://learn.chatgpt.com/docs/developer-commands)

## 创建一个可验证的后继

1. 创建前确认用户确实要求新聊天/重建/接力。审计、改名、Skill 安装和自动估算上下文长度都不构成新建授权。
2. 在目标项目原有唯一状态文档记录目标、已确认决策、用户修改、当前进度、失败断点、下一步与保护范围；Git 项目记录已核验提交，非 Git 项目记录精确路径/必要哈希。不要复制整段旧聊天或另造长期台账。
3. 优先应用 `create_thread` 等官方工具，使用刚回读的项目 ID 和正确主机。CLI/app-server 作为当前环境公开协议入口时，核对 `thread/start` 的 cwd；普通默认创建本地聊天，只有用户明确要求时建立 worktree。普通跨目录移动不自动转为跨主机迁移。
4. 一次创建，保存真实返回值。`clientThreadId`、排队或 submitted 都不是已初始化的真实 `threadId`。按原创建回执等待并只读对账，不能未知就再建一个。
5. 后继先只读初始化，确认项目/主机、实际工作目录、唯一状态文件、Git 提交或文件哈希、规则加载及保护对象，再承接已授权工作。读取必要元数据及初始化结果，不批量拉取历史正文。
6. 目标列表、线程元数据、真实执行目录和权限分别检查。普通新建/续接会话默认完全控制（`danger-full-access` + `never`），只读初始化约束操作范围，不要求降为只读沙盒；仍遵守用户明确的受限权限要求和平台策略。原生 `projectId` 为空不等于初始化失败，也不证明桌面归属正确；按用户目标核对目标客户端，不为填空手改内部记录或重复重建。
7. 用户授权旧任务归档时，先确认后继已经就绪，检查源任务的子会话、工作树和自动化引用，保全必要未提交/忽略文件，再执行精确归档并回读。没有旧任务处理授权则保留旧任务。

官方 `thread/start`、`thread/resume`、`thread/fork` 是不同操作；恢复历史本身不等于新建后继或迁移项目归属。必须依据返回的真实标识和状态核验。[Codex App Server](https://learn.chatgpt.com/docs/app-server)

## 自动化和固定绑定

- 修改提示词中的路径不能改变原线程工作目录，也不能代替线程换绑。不要给自动化配置添加未被 schema 支持的 `cwd/cwds` 字段。
- 先查唯一现有自动化/路由、目标线程和暂停状态；只在本次明确范围内更新，保留模型、时间、通知和暂停设置。不为路径迁移新增重复调度。
- 核对自动化目标会话的独立权限覆盖：全局默认已是完全控制，不证明旧目标没有保留 `workspace-write`、`read-only` 或审批覆盖。通过产品支持入口修改并分别回读保存值和会话值；不向自动化文件猜加权限字段，不直接改内部状态。后续回合设置也不证明正在执行的回合已经切换。
- 新候选及初始化已验证后再切换绑定，保留旧映射作恢复依据。业务程序支持事务切换时使用它；不把某个 Slack 实现当作所有客户端都具有的接口。
- 创建、初始化或换绑结果未知时保留旧绑定和候选断点，只读对账；不盲目重放，也不擅自发测试消息、启动业务或恢复暂停任务。
- 真实运行验收与绑定保存分开报告。需要下一次授权运行才能验收时，记录该层待验收，不伪造已运行结果。

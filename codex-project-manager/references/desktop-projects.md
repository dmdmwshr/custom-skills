# 项目改名与桌面核验

适用：已有 Codex 项目的显示名称修改。目录、项目编号、分区与聊天名称是独立对象，不自动一起改。

## 对齐目标

- 从应用 `list_projects` 获取实际保存的 ID、名称、路径、主机和其他字段；如同时查询原生 `project/list`，保存为另一份快照，不按序号或同名直接配对。
- 规范名称来自现行项目总表/规则。当前 Windows 工作台使用编号与中文名称；是否带“Codex优先”等标记以总表为准，不把示例名称硬编码成通用规范。
- 建立 `projectId + host + path + 原名 → 目标名` 清单。只在唯一对应时执行，原列表完整保留供核验或恢复。

## 选正确入口

若应用有官方项目改名工具，按其实际 schema 使用。没有暴露该工具不等于不能改名：使用真实应用的项目菜单→编辑项目。独立原生协议只修改其实际连接的记录域，不能代替桌面结果。

Windows 原生界面按 `cua-driver` 或当前指定驱动操作；WSL/Claude 要控制 Windows 桌面，必须先确认已有 Windows 入口能触达精确窗口。WSL 独立 CLI 不是 Windows 桌面界面，缺少入口时交付已核对的清单和技术缺口，不能冒称桌面已改。

逐项执行：

1. 取目标窗口新状态，从项目的“项目操作”打开菜单，再选择当前可见的“编辑”。菜单/对话框产生后重新取状态。
2. 核对对话框中的源文件夹、原名称与计划一致。源文件夹显示简名时，必须有前一步完整项目路径的唯一对应依据。
3. 对名称控件设置完整新值并回读。当前驱动支持控件整值设置时优先使用；普通文字输入可能追加到旧值末尾，不能假定它等于替换。需要键盘替换时选择精确字段、全选、输入并检查完整结果。
4. 完整值正确后点击保存，再从应用列表按原项目 ID 回读。ID、路径和其他项目字段保持；名称与计划完全相同才算成功。
5. 侧栏取新状态确认显示已更新；窗口截断长标题时以控件完整值及应用列表为准，不因视觉省略号重写名称。

后台被拒绝时，按已授权任务的前台规则执行，不重新索取前台许可。控件操作不生效或菜单位于屏幕外时，先观察实际状态、调整目标可见性，再继续；不要盲目重复同一点击，也不要把会话里的“编辑”按钮当成项目菜单。

## 整批完成

- 使用 `scripts/verify_project_rename.py` 对相同记录域的前后快照做名称与元数据比较。它发现 ID 集合不同会失败，帮助识别错误记录域或意外重建。
- 分区/排序不在项目列表字段中时单独回读，不能由名称核验推导。任务没有要求整理分区或排序时保持原有设置。
- 恢复临时展开的分组，关闭自己的编辑框/控制会话。保留用户聊天、未发送输入和其他控制连接。
- 不以“可能需要重启”解释未核清的记录差异；是否缓存需真实证据，不能为了刷新而重启用户应用。

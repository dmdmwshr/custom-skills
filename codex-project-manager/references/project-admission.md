# 新项目准备与启动

用于工作台已经批准的新项目准入。优先复用既有项目；项目添加由用户在 Codex 应用内人工完成。本流程不借项目准备执行业务分析、开发、安装或部署，也不调用私有状态写入绕过人工添加。

## 准备与交付

按目标主机工作台规则查重，准备唯一目录、AGENTS.md、唯一 PROJECT_HANDOFF.md 和 CLAUDE.md 加载桥接。沿用已批准的准入依据和候选编号，在原交接中记录用户授权及本轮范围、名称、分区、真实唯一目录、所属维护项目、登记责任及下一阶段；没有的身份保留待回读，不编造应用项目或主聊天 ID。不新建第二份项目/角色总表，不复制活动源码。

交付准确目录和下述启动任务书。用户人工添加完成后，由目标项目聊天接续核验与登记；不让用户返回工作台转述或催办。

## 统一登记与回读

唯一接口和请求/证据结构以03-01维护的 `/srv/workspaces/03-env/03-01-workbench/docs/PROJECT_REGISTRATION.md` 为准；源码入口为同项目 `scripts/project_registration.py`。Skill只引用入口，不复制参数实现、最小JSON或另一份权威登记。

仅有 `status` 与 `ensure`，均接收 `--request <UTF-8 JSON文件或->`；`status`只读。先确认入口版本已完成本轮独立验收并交付，按该文档在目标项目真实cwd执行。Windows沿既有可用WSL入口，并以同目录WSL映射设置cwd；WSL原生项目保留原Linux目录。Windows标准输入按权威文档使用PowerShell 7与UTF-8编码，不拼接含用户值的命令文本。查询不授权唤醒已关闭实例；不可达保留断点，不复制源码或新建第二入口。

身份、准入编号、规范目录或原主聊天冲突时停止相关登记并保留证据；描述差异交由原管理流程处理。繁忙先status，写表结果未知先对账原事务，不盲目ensure或重新分配pid；已落表但索引未完成只依统一入口恢复索引，第三方新值保留。入口不接受任意总表路径或patch，不用直接改JSON/SQLite补救。

同一规范真实根的第二入口复用原pid和回执，不因准入编号不同创建新身份。合并、退役、改名、角色换代和编号复用仍按原专项边界，本入口不代办。

分别结论化应用保存、聊天目录/权限、总表登记、索引、业务实施和验收。入口的 `businessAccepted=false` 不作业务验收；登记完成不提高角色、消息回路、自动化或业务运行状态。回执写回目标项目原唯一交接，工作台只留跨项目事项指针。

# 路径与项目登记迁移

先明确改的是路径标签、实际目录还是应用登记。用户只要求改名时不移动目录；要求移动目录时也不能默认为同意重建所有聊天或更改服务。

## 迁移层级与基线

| 层级 | 变更前后需要核对 |
| --- | --- |
| 磁盘实体 | 真实绝对路径、文件清单/必要哈希、大小、权限、链接与联接 |
| 源码 | 仓库根、分支/提交、暂存/未提交/忽略的必要数据、worktree 注册 |
| 应用项目 | 目标客户端项目 ID、主机、全部根目录及主目录顺序、显示名、分区 |
| 聊天 | 真实线程 ID、项目归属、实际执行目录、当前运行/暂停状态 |
| 调用入口 | 快捷方式、任务/服务、解释器和可编辑依赖、自动化、固定聊天/机器人引用 |

按目标只检查需要的层级，盘点调用者时不输出令牌、认证或会话正文。路径规范化保留主机身份，Windows/WSL 路径文本对应不等于同一运行实例。

## 实体目录迁移

1. 优先复用唯一主仓。核清活动写者与调用者、用户修改及恢复需要；活动任务/运行入口影响未解决前不移动它们。停止服务、暂停同步等动作须在当前任务授权内，不能由目录整理推导。
2. 对精确源和目标保存恢复基线。目标已存在时先比较，不覆盖独有文件或把两个不同提交的工作树当成一个。涉及业务主资料时遵循当前主从规则，不从旧备份反向覆盖新值。
3. 在同一系统内执行，Windows 使用原生路径操作和 `LiteralPath`。任何递归移动/删除前验证解析后的绝对路径在批准范围内；逐项识别重解析点，不能递归穿透目录联接删除其真实目标。
4. 移动或复制后核验文件/Git/权限和必要数据。虚拟环境、可编辑安装、绝对路径配置及工作树注册可能需要目标项目维护，不能只改目录字符串便声称可运行。
5. 旧目录的恢复职责、活动引用和新入口验收已结清后，才按精确清单清理被替代副本。未知差异、唯一恢复副本和失败证据保留。

## 更新已有项目路径优先

先查当前版本官方能力。支持编辑文件夹时，在原项目登记中添加已验证的新目录、调整主目录，并按本轮范围移除失效的旧附件目录；保存后回读同一项目 ID 的全部根目录及主目录。只移除项目里的目录附件不是删除磁盘目录，界面动作仍须核对真实含义。

官方说明：项目“编辑项目”可附加文件夹并设主目录；新聊天默认使用主目录。该说明不证明既有聊天已经换目录，多根项目和远程项目限制以当前版本为准。[Projects and chats](https://learn.chatgpt.com/docs/projects)

原生 app-server 是否支持更新根目录，应核对当次生成的 `ProjectUpdateParams` schema；本机某次 schema 支持 `roots`，不代表现有包装暴露了该参数，也不代表它连接桌面记录域。先验证连接目标与项目身份，不用旧 socket 文件、独立 CLI 成功或接口缺失推断桌面状态。

## 必须重建项目登记时

- 先说明为什么原登记无法安全复用，按规范化根目录查重；重建的是应用登记，不重新克隆一套活动源码。
- 保存旧项目的 ID、根目录、分区、聊天及必要调度引用。旧登记仍承载聊天或唯一入口时先保留，不能先移除再试建。
- 遵守当前工作台准入规则。本机默认由助手准备唯一目录、`AGENTS.md`、唯一状态文档和 `CLAUDE.md` 加载桥接，再由用户在应用添加；当前用户明确改变该准入规则时按新指令。接口记录不能冒充用户侧已经添加。
- 新项目实际创建后，通过目标应用回读真实新 ID、主机及根目录。只拿到队列令牌或独立原生记录时准确标记未完成，不重复创建。
- 聊天移动及调度绑定分别按授权处理，参见 [会话与绑定处理](session-rebuild.md)。新项目核验通过也不自动授权删除旧项目或归档全部旧聊天。
- 如果平台限制跨主机移动，不改内部数据库绕过；给出最小交接方案，保留源任务与原始材料。

收尾报告分别列出实体、应用路径、既有会话、新会话和调用入口的结果。尚待重建会话时不能把目录迁移称为全部完成。

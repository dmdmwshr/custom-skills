# 专家劳务表 Excel

用于成套材料或补充劳务表；与 Word 共用本次项目、阶段、日期和已确认人选。历史支付记录提供人员信息，外部模板决定版式。参考路径见 [本机资料入口](local-sources.md)。

## 1. 选来源并核验

1. 默认复制 `5.2、专家劳务表.xls`。原表有四个人员行、合计和审批签字区；不使用讲课费表替代。不固定四人：按实际付费专家调整人员行及公式范围，基层代表不列行。用户只要求劳务表时，不重写已确认 Word。
2. 每位专家选一份较新、已确认正确的历史劳务记录，登记文件、工作表和行号。文件名含“有错误”的版本不作来源；有修正版 PDF 时交叉比对，不能沿用早期错误表或复制旧签名。修改时间不等于业务正确性。
3. 与主专家库按姓名精确匹配，核对身份证号、单位、开户行网点、银行卡号、手机及岗位职称。仅删除无意义空白；身份证末位 X 可统一大小写，银行卡逐位比较。不自行补位、猜测更正或覆盖专家库。
4. 同一人名匹配多条、关键字段缺失、不一致、科学计数法或数值型长号码精度无法确认：暂停受影响材料并向用户汇总差异。身份及账号只显示末四位，不能在报错中输出完整行。明确的职称简称可以对应；实际岗位、职级或单位变化须核验。
5. 本轮 600 元为用户确认的通常标准，历史也有 500 元记录。后续结合当前用户要求与选定历史依据决定；存在标准冲突就确认，不能因模板写着 600 自动采用。明确是否为本次确认的实发口径，不自行引入新的税费政策。本流程不执行支付。

### 只读核验工具

`../scripts/audit_labor_sources.py` 使用 `xlrd` 读取 `.xls`，`openpyxl` 读取名册 `.xlsx`；不写任何业务文件。可用本机已有对应依赖的解释器执行，先检查可导入性，不临时改系统环境。

任务工作区内的选择文件只记录人选和来源位置：

```json
{
  "roster": "专家库文件的绝对路径.xlsx",
  "roster_sheet": "专家库",
  "experts": [{"name": "本次已确认专家姓名", "history": "选定历史文件的绝对路径.xls", "sheet": "Sheet1"}]
}
```

```text
python audit_labor_sources.py --selection <任务内选择文件.json>
```

`matched` 仅表示身份、单位、开户行、账号、手机字段匹配；岗位职称简称、修订版适用性、本次金额日期仍需人工语义核验。`needs_confirmation` 或 `error` 均以非零状态退出，禁止继续据此生成。无论结果如何都不是转账授权。不要把选择文件中的具体人选固化进 Skill。

## 2. 按原模板填写

使用独立、隐藏的 Excel 实例操作模板副本，关闭链接更新并禁用宏；只关闭自己创建的实例。保持原 `.xls` 格式，不通过格式转换重建工作表。批量任务先全部核验再填候选，避免发现冲突后留下貌似完成的文件。

当前普通版模板映射如下；每次先核对表头与结构，不能盲用坐标：

| 区域 | 填写规则 |
|---|---|
| A1:N1 | 保留“劳务费发放表”及原标题格式 |
| A2:I2 | 填写当前完整项目名称和评审阶段；保留右侧金额单位 |
| A4:A7、B4:B7 | 按本次意见文件的付费专家顺序填写序号、姓名 |
| C4:C7 | 历史身份证；先设文本格式，再写字符串 |
| D4:E7 | 工作单位、职称/职务分别填写，沿用老劳务表写法；不塞入意见封面的整段简介 |
| F4:F7 | 本次确认的每人标准 |
| G4:G7 | 与意见 Word 一致的会议日期，常用 `2026.09.XX`；待补单元格标黄 |
| H4:I7 | 保留应发金额、个税公式，不覆盖为手算值 |
| J4:J7 | 仅在已确认实发口径时填写本次实发金额；本轮每人 600 |
| K4:M7 | 开户行网点、银行卡号、手机；账号和手机先设文本格式再填 |
| N4:N7 | 签收处留空，不复制历史签名 |
| 第8行 | 保留各合计公式；人数增减时只相应调整求和范围 |
| 第9行 | 保留分管领导、业务部门负责人、制表标签，签字处留空 |

- 保留字体、字号、列宽、行高、合并单元格、边框和打印设置。长开户行文字优先在原单元格内自动换行，利用现有行高；必要时再小幅调整该单元格对应尺寸，不默认缩字号。长项目名称沿用标题单元格的自动换行。
- 清除已填写字段中遗留的黄色底色；只有待补字段标黄。签字空白无需 X。未知金额用 X 的草稿不能被描述为已核算通过，须标明合计待确定。
- 模板 H 列为依据实发额反算应发额，I 列为两者之差；保持模板公式并用 Excel 重算。本轮每人 600 时，应发/实发均 600、个税为 0；四人合计 2400。这是当前模板和输入的计算结果，不是对其他支付情形的税务判断。

## 3. 核验、发布

1. 检查名单与当前会议一致，基层代表不计费；姓名、单位、身份证、账户、开户行、电话逐字段回读，与已核验来源一致。长号码必须是完整文本，无截断、科学计数法或精度丢失。
2. Excel 完整重算，验证每行标准、应发、个税、实发及合计；确认原公式仍为公式，无错误缓存。原生 Excel 已完成重算时无需再用 LibreOffice 改写旧版文件。
3. 对照模板检查实际使用区域的字体、字重、字号、行高、列宽与合并区域。旧 `.xls` 可能字重为 700、冗余粗体标志却为 0，Excel 保存后统一粗体标志不代表视觉变化；比较实际字重和渲染。忽略保存时新增的未使用空列元数据，不忽略实际单元格尺寸变化。
4. 导出 PDF 检查横向单页，标题、单位/职务和开户行显示完整，长号码不遮挡相邻列，合计与审批栏不跨页。完整文本被 PDF 提取出来不证明未被单元格裁切，仍需看版面。优先在本地遮盖身份、银行卡和手机号后制作预览；最多检查必要的少量图。
5. 源文件或目标文件哈希有变化时停止覆盖并重新合并。无变化且核验通过后，把 `.xls` 发布到对应项目文件夹；已有同名文件保留备份。重新打开最终文件，回读金额、公式、长号码和打印页数。
6. 默认每项目交付一份可编辑 `.xls`，文件名包含项目、评审阶段和“专家评审劳务表”。PDF、来源行记录、验证记录和备份留任务工作区，不把真实身份证或银行卡写入 Skill、测试夹具或提交记录。

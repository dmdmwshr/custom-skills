# 评审意见 Word

仅在生成、修订评审意见或维护 Word 模板时读取。共享来源优先级与发布规则见 SKILL.md。

## 资料与写作

1. 首次读取 [本机资料入口](local-sources.md)，盘点指定项目文件夹中的最新需求、原始专家意见、用户手改意见文件与初始模板。排除 `~$` 锁文件，不沿用上一轮临时稿覆盖手改稿。先读当前文件再修改。
2. 按评审阶段选择外部模板。外部模板目录是唯一版式事实源；本 Skill 不保存或发布模板副本，也不从旧缓存覆盖用户模板。模板维护须有用户明确请求，普通项目生成只读引用模板。
3. 将原始意见逐项对照最新材料：已采纳的意见不重复要求补充；保留尚未解决的具体缺口、矛盾和可验证措施。采购范围变化以用户最新说明和最新材料为准，例如仅租电路就不引入平台软件开发、平台维护或功能演示要求。
4. 默认每项目三条意见，每条以“建议”开头，例如“1、建议明确……”“2、建议补充……”，聚焦一组关联问题，直接指向材料中的条款或指标。不堆砌背景、泛泛肯定和套话。已有“建议”不重复添加；保留用户明确指定的其他措辞。用户另定数量或篇幅时遵从，不受辅助脚本的三条校验限制。
5. 用户给出的截图用于确认人选；姓名不全时对照名册候选，不凭头像猜身份。仅提取姓名、单位、职务、职称，不读取输出与任务无关的身份证、银行卡、电话和邮箱。
6. 人员简介先核对名册，再采用同名专家在已确认历史评审文件中的写法；用户要求保持一致时逐字保留，不为了塞进一行自行删去“研究所所长”等职务。来源有实质冲突才提示用户确认。
7. 评审结论区分“供审阅草稿”与已确认会议结果。未经材料或用户确认，不自行形成通过、验收合格等事实结论。通用模板的结论用 X 占位，签字留空。现有手改正文及结论保持不变，除非用户要求改动。

## 文档标准

- 复制用户指定的最新外部模板，仅替换字段；保留首页表格、原字体字号（含中文 eastAsia）、行间距、段前段后、缩进、页面设置、样式、标题横线及绘图对象。不得清空页面后重建，不把历史文件或上轮错误生成文件继续当作版式模板。历史文件只参考专家简介写法。
- 完整专家简介单行显示，先微调姓名列和简介列宽，保留表格总宽及原字号；必要时微调单元格边距。行间距只影响上下距离，不能解决横向换行。不删职务、不缩小字号，不默认重设字符间距。
- 日期保留在首页表格末行，用表格空白行行高控制下方原横线的位置，统一到首页下页边距上沿。不得新增首页页脚，不改正文行间距挤版面。用户明确要求恢复或统一旧模板时，可整理表格后无内容的空行、微调原横线锚点，使横线随表格后的段落流动；保留原横线图形，不重新绘制。普通生成沿用最新模板已验证的结构。
- 未提供的第五位人员仅用 `XXX` 和 `XXXXXXXXXXXXX` 占位，不写“基层代表”“待填”等提示词。日期等其他未知值也使用 X。只有待补充的 X 标黄，已填姓名、单位、意见不得标黄。专家签字区保留空白，不代签。
- 正文从第二页开始，保留签字区。需要明确分页时仅添加正文首段的段前分页；不修改字号、正文行距或删减已确认内容来凑页数。按用户要求核验两页完整、无空白溢出页。
- 使用 `docx` Skill 处理 Word 格式。优先通过 `load_workspace_dependencies` 提供的 Python/库执行辅助脚本，不向系统 Python 安装依赖。

## 辅助生成器

`../scripts/review_docx.py` 依赖 `python-docx` 和 `lxml`，仅写新的输出路径，拒绝原地覆盖。只修改模板中的正文 XML，其他文件部件逐字节保留；不新建页脚、不重建样式或绘图对象。脚本支持单节、两列表格、五名人员、末行日期和三条意见；不认识的结构停止自动替换并人工核对，不能为了通过校验删用户内容。渲染检查是必要步骤，脚本成功不代表版式通过。

从当前已确认内容恢复或生成意见，内容来源与版式模板分开指定：

```text
python review_docx.py --source <当前已确认Word> --template <对应阶段最新外部模板> --output <新候选Word>
```

省略 `--template` 时仅允许来源本身是已确认的表格模板；无表格来源会被拒绝。用户要求给现有三条意见加“建议”时追加 `--prefix-suggestions`，已有前缀不会重复。

用户授权更新通用模板时，把示例人员、意见和结论改为 X：

```text
python review_docx.py --source <外部模板> --template <同一外部模板> --output <新候选Word> --blank
```

使用已审阅的结构化内容生成：

```text
python review_docx.py --source <对应阶段模板> --template <对应阶段模板> --output <候选Word> --content <UTF-8内容JSON>
```

内容 JSON 字段为 `title`、`experts`（五组姓名/简介）、`date`、`introduction`、`opinions`（三段正文，不含序号）、`conclusion`。此接口只填充，不决定事实或结论。人数、意见数量不同时人工沿用模板处理，遵从用户要求。

仅在渲染显示必要时使用 `--name-width-twips` 调整姓名列（总宽不变），或 `--spacer-total-twips` 调整空白行总高度；twip 为 1/20 磅。两个参数均默认不改尺寸。`--body-page-break` 可明确正文另起一页，不改变行距。每次替换较长标题、人员信息后重新渲染，不能照搬上次的空白行高度。

## 核验与交付

1. 改前记录源文件哈希，备份到任务工作区；只改获授权文件。本节只处理意见 Word；同时需要劳务表时转到 [专家劳务表](labor-workflow.md)。
2. 使用 Word 原生打开并导出 PDF；不关闭或保存用户已打开的窗口。LibreOffice 作为可用替代时使用独立 profile，并如实说明未做 Word 原生验证。
3. 对照版式模板核对字体字号、行间距、段前段后、缩进、页面设置与原横线；除必要的表格尺寸、空白段或原横线定位调整外保持一致。核对：源正文保留；每项目三条（或用户指定条数）；人员信息与选定历史来源一致；首页表格与模板一致；每位专家简介在渲染中占一行；黄底只覆盖 X；首页日期与正文一致；签字区完整；无空白溢出页。
4. 批量通过低分辨率联系表检查，最多再查看 1–2 张必要大图。模板组应核对所有首页底线的实际位置一致，不能只凭源格式参数推断。
5. 渲染通过后再发布到用户指定文件夹。覆盖前回读源哈希；源变化时以最新文件重新合并，不覆盖用户手改。被打开占用时保留同目录一份明确命名的新版本并说明，不强制关闭应用或连造多个版本。
6. 回读最终文件、校验哈希和关键文本，说明已更新文件、仍需填写的 X 和任何锁定另存情况。只交付 Word，PDF/图片留工作区作核验，除非用户要求。

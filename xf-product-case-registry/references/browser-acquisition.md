# 来源网页案卷采集

本文件规定消防产品监督来源网页的浏览器流程。浏览器采集、Skill 程序、真实工作目录和 V2 登记系统保持分离；浏览器只把结构化来源证据和下载包交给工作目录，不直接写登记系统。

## 会话与隐私门禁

1. 使用用户当前可见、已登录的受控浏览器标签页。先检查页面是否显示业务导航或案卷列表；若出现登录页、无权限、会话过期或空白跳转，暂停并明确提示用户手工登录。
2. 不自动填写登录凭据，不读取或导出 Cookie、Local Storage、Session Storage、密码、令牌和浏览器配置，不把用户配置复制到无头浏览器。
3. 使用可见文字、控件角色、标签和稳定业务结构定位；不要把坐标、截图像素或一次性的 CSS 序号当作唯一定位。语义定位失败时停止当前步骤并保存断点，不盲点。
4. 保存来源路由时去除 `runId` 以及会话、认证和追踪参数；RWID 作为独立业务字段保存。不要保存包含令牌的完整 URL 或原始 HTML。

## 默认筛选

默认查询上海时间当年 1 月 1 日至当天、全部 8 个大队：

1. 打开“产品监督”。
2. 展开“查询统计”，进入“法律文书查询”下的“法律文书”。
3. 明确设置开始日期为当年 1 月 1 日、结束日期为当天；不要依赖网页残留值。
4. 管辖单位选择“全部管辖单位(含派出所)”。
5. 默认不选“执法单位”，表示无锡支队全部 8 个大队；用户指定单大队时才选择对应执法单位，并把该条件写入批次筛选快照。
6. 打开“法律文书类型”，切换到选择器第 2 页，精确选择“消防产品监督检查记录”。不要把“消防产品监督检查记录表”等相似文字当作成功。
7. 点击“搜索”，等待加载完成和列表稳定；读取页面实时总数、每页条数与页数，不硬编码历史截图中的数量。

把筛选条件和列表页证据保存在 `原始案卷/案卷目录截图/<批次>`。截图仅供人工回查，清单以页面结构化数据为准。

发布前只抽取一个真实案卷验证下载链路时，创建批次必须加 `source begin --acceptance-sample`，并在筛选 JSON 中记录 `acceptanceMode=SINGLE_CASE_DOWNLOAD_PROOF`、页面实时总数和样本数。此模式明确是 `SAMPLE_ONLY`，不得冒充年度全量稳定清单，也不得更新正式水位。

## 已标注页面的低延迟执行规程

以下规则来自已登录页面的实际标注，用于把“产品监督 → 查询统计 → 法律文书 → 打包下载”变成可重复的浏览器操作。它们是**语义定位优先、已观察结构辅助**的规则：先核对可见文字和业务容器，再把观察到的元素结构作为消除同名控件歧义的回退；不能只依赖坐标、菜单序号或一次性的页面位置。

### 导航与筛选

| 阶段 | 首选定位与范围 | 成功判据 |
| --- | --- | --- |
| 产品监督 | 顶部 `tab` 的精确名称“产品监督”；若角色不稳定，回退到已观察的模块容器 `#tab-306`，但必须同时核对其可见文字 | 地址包含 `MODULE_ID=306` 或产品监督左侧菜单出现 |
| 查询统计 | 仅在左侧 `ul.el-menu` 的子菜单标题中匹配精确文字“查询统计”，不要在整页直接按文字点击，因为顶部模块栏也有同名文字 | 对应子菜单处于展开状态，能看到“法律文书查询” |
| 法律文书 | 先在已展开的“查询统计”中展开“法律文书查询”，再在该下级菜单内匹配精确菜单项“法律文书” | 查询页显示日期区间、管辖单位、执法单位、法律文书类型和“搜索” |
| 日期区间 | 限定到查询表单的 `.el-date-editor.el-range-editor` 内两个输入；明确填写上海时间当年 `01-01` 至当天 | 两端输入值均已回读，不能沿用页面残留日期；填写调用超时后先回读，不能直接重复填写 |
| 管辖单位 | 打开单位下拉后精确选择“全部管辖单位(含派出所)”；鼠标点击没有展开时，聚焦该只读输入并按键盘确认键 | 下拉收起后输入框显示该完整文字 |
| 执法单位 | 默认保持“请选择执法单位”，不触发选项点击；仅单大队任务才选择指定单位 | 输入框仍为未选择状态，或与指定大队一致 |
| 文书类型 | 在法律文书类型下拉容器中翻到其**自身**第 2 页，再精确选择“消防产品监督检查记录” | 下拉收起后显示精确文书名称；不得接受“记录表”等相似名称 |
| 搜索 | 只点击查询表单内精确按钮“搜索”一次 | 结果区的实时总数、每页条数、页数与首行记录已刷新 |

当“查询统计”或分页数字出现多个同名候选时，先以其父容器（左侧菜单、文书类型下拉、结果表尾）限定范围；禁止依靠第几个候选或把每个候选逐一远程查询。

### 列表、详情与打包

1. 搜索完成后，在结果表尾读取实时 `总数`、`每页条数` 和页数；用 `ceil(总数 / 每页条数)` 交叉核对页数，但不把任何历史数字写死。跳页必须限定在结果表尾的分页器，翻页后回读当前页码及首末记录特征。
2. 以项目编号打开详情，不以单位名称作为唯一入口。详情页至少同时出现项目编号和文书目录后再截图；字段直接读取表格与目录结构，截图只作本地核查证据。
3. 详情页的按钮文字可能显示为“打 包”。以正则 `打\s*包` 匹配并限定在案卷详情操作区；点击后等待打包面板出现，再点击该面板中的“全选”。
4. “全选”不是成功依据。一次性读取打包面板文书树的可下载**叶子**复选框状态：叶子数必须大于 0，且全部为已选；父级半选状态、按钮变色或树根选中均不能替代这项核对。对多节点状态使用一次 `evaluateAll` 或等价批量读取，禁止逐叶子发起浏览器往返。
5. 仅在叶子文书全选核对通过后，立即执行本案 `source snapshot-downloads --batch-id <批次> --rwid <RWID>`；随后先通过 `tab.playwright.waitForEvent('download')` 注册下载监听，再点击“开始打包”。下载监听与下载目录基线必须共同成立，避免把旧 ZIP 误认成新包。
6. 浏览器建议名即使乱码也只记录为审计信息。只有相对本案基线唯一新增、临时扩展名消失、大小多次稳定并能作为 ZIP 打开的文件，才可交给 `source attach-package`；该命令负责按 `<项目编号>_案卷包_<哈希前12位>.zip` 存入对应验收或待处理目录。

### 慢页面、超时与会话恢复

- 该来源网页及其受控浏览器回传可能需要约 20 秒。每次浏览器调用只执行一个页面动作，再做一个最小状态读取；不在首页执行全页 DOM 快照，不对多个候选逐个 `evaluate`，也不把同一步拆成串行远程循环。
- 点击后到达调用超时不等于点击失败。先回读当前地址、目标容器或按钮后的唯一状态；只有确认动作未生效才重试，避免重复搜索、重复打包或重复下载。
- Element UI 的只读选择框偶尔会吞掉鼠标点击。只有已经确认字段语义与范围正确时，才可以使用“聚焦后按键盘确认键”作为打开下拉的回退；随后仍须按精确可见文字选择并回读字段值。
- 页面操作异常导致控制连接重启时，先从当前内置浏览器的受控标签列表恢复已有来源页；若该页仍存在，不要求用户重复登录。日期填写、翻页或选择动作超时后也遵循这一规则：先恢复并回读当前值，不能假定失败后重做。只有可见页面实际回到登录页、无权限页或会话过期页时才暂停请求手工登录。
- 将每个阶段的“目标控件、开始时间、最小成功信号、重试次数和断点原因”写入批次状态或操作摘要。出现重复文字、下拉未收起、总数未刷新、叶子未全选、多 ZIP、下载不稳定或项目编号不一致时，停止当前案卷并保留断点，不用猜测继续。

## 分页清单与稳定性

- 以 RWID 作为来源记录键，以项目编号作为最终案卷键。每页记录页码、采集时间、列表总数、项目编号、单位名称、可见日期和详情入口特征；不得把 `runId` 当作身份键。
- 遍历页面报告的全部页码后形成一轮集合。再次从第一页完整扫描；只有连续两轮 RWID 集合及其项目编号映射一致，才把 `BrowserCaptureV1` 标记为稳定。
- 集合发生变化时最多执行三轮完整扫描。第三轮仍不一致则保存每轮差异和最后完成页，水位标记“清单变化中”，本批次不得宣称完整。
- 同一项目编号对应多条 RWID 且核心字段一致时合并为一个案卷来源；项目编号、单位、大队或关键日期冲突时标记“需人工处理”，不得自动下载或覆盖已有证据。
- 已完成案卷且列表特征未变化时只更新 `lastSeenAt`；新增、未完成、列表特征变化或来源冲突解除后的案卷进入处理队列。
- 翻页后重新核对当前页码和首末条目标识，防止加载延迟导致重复读取上一页。单页失败只保存断点，不跳过后仍宣称清单完整。

## 详情采集

打开案卷详情后，直接读取页面表格和文书树中的结构化字段：

- 项目编号、单位名称、单位类别、单位地址；
- 受理日期、检查情况、消防监管机构、承办人和所属大队；
- 产品名称、生产单位、数量、市场准入/质量结论和检查结果；
- 文书目录、创建时间、审批状态以及能明确判断的初查/复查关系。

项目编号必须与列表条目一致；不一致时停止该案。把可确认值和来源位置写入 `SourceEvidenceV1`，未知值留空，不从截图 OCR 猜测。依据产品结果和文书目录生成可重叠标签：`现场检查`、`抽样送检`、`不合格`、`复查`、`合格`、`待确认`。

每个新增或变化案卷保存一张完整详情截图到 `原始案卷/待处理案卷/<项目编号>`。截图是核查证据，不是 manifest 文件，也不能替代结构化字段。

## 打包下载与交接

1. 在详情页点击“打包”。
2. 点击“全选”，再读取文书树的选中状态，确认所有可下载叶子文书均已选中；只看到按钮变化不足以证明全选成功。
3. 每个案卷点击前运行 `source snapshot-downloads --batch-id <批次> --rwid <RWID>`，保存绑定当前批次、RWID 和项目编号的下载目录基线；不能跨案卷或跨批次复用。
4. 点击“开始打包”后监听新下载，等待临时扩展名消失、文件大小连续多次稳定并能作为 ZIP 打开。监听必须挂在受控标签的 `playwright` API 上，而不是标签外层对象。调用 `source attach-package` 时显式传入本案快照返回的 `--download-baseline`；成功后会生成不可覆盖的消费回执，其他案卷不能再使用该基线。
   `--download` 只能指向 `workspace.toml` 配置的下载目录本身，或其中一个直接子文件；不得从其他目录挑选同名 ZIP。
5. 某些内置浏览器会让来源网页完成“开始打包”后既不发出下载事件，也不把 ZIP 写入配置下载目录。一次正常尝试后，允许在确认页面没有进度、没有 ZIP/临时文件且基线未被消费时最多重试一次；重试前必须新建本案下载基线。两次均未交付文件即记录“下载交付不可用”，不得第三次点击“开始打包”，不得从浏览器临时目录或其他目录复制猜测文件。该案保持“详情已采集、案卷包待接收”，不执行 `attach-package`、整理或上传，并提示用户处理浏览器下载交付后从该断点续跑。
6. 一次动作只接受一个相对本案基线新增的完整 ZIP。没有新文件、出现多个候选、下载超时、ZIP 不完整或浏览器会话过期时，保持“采集失败/待重试”，不得猜测文件归属。
7. 计算 SHA-256，按 `<项目编号>_案卷包_<哈希前12位>.zip` 保存到 `原始案卷/待处理案卷/<项目编号>`；在 `SourceEvidenceV1` 记录浏览器建议文件名、规范文件名、完整哈希、大小、基线指纹和候选属性。乱码建议名只作审计，不参与案卷识别。
8. 原始 ZIP 不覆盖、不改内容、不删除。`attach-package` 只检查并绑定原包，随后由 `inventory` 安全解压和清点；浏览器不直接解压或上传。

## 中断与恢复

- 每个页面、详情和下载步骤完成后更新批次断点。重新运行必须核对同一工作根、筛选快照、RWID、项目编号及现有包哈希。
- 会话过期时提示用户重新登录，随后从最后一个未确认步骤继续；不得因为重新登录而新建重复案卷。
- 单案采集失败、下载异常或字段冲突不阻塞其他案卷，但必须保留明确错误摘要和重试次数。
- 来源采集完成不等于 V2 上传完成；最终进度以 `CaseWaterlineV1` 为准，只有登记系统飞牛核验达到 `VERIFIED` 才能进入已完成和自动归档。
- `acceptance` 样本完成只表示“真实浏览器下载和本地接收链路通过”；其证据留在 `工作区/采集批次/<批次>/验收样本`，不进入正式队列，不允许继续执行 `inventory` 或上传。

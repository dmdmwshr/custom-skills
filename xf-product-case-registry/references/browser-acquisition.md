# 来源网页案卷采集

本文件规定消防产品监督来源网页的浏览器流程。浏览器采集、Skill 程序、真实工作目录和 V2 登记系统保持分离；浏览器只把结构化来源证据和下载包交给工作目录，不直接写登记系统。

## 会话与隐私门禁

1. 使用用户当前可见、已登录的受控浏览器标签页。先检查页面是否显示业务导航或案卷列表；若出现登录页、无权限、会话过期或空白跳转，暂停并明确提示用户手工登录。
2. 不自动填写登录凭据，不读取或导出 Cookie、Local Storage、Session Storage、密码、令牌和浏览器配置，不把用户配置复制到无头浏览器。
3. 使用可见文字、控件角色、标签和稳定业务结构定位；不要把坐标、截图像素或一次性的 CSS 序号当作唯一定位。语义定位失败时停止当前步骤并保存断点，不盲点。
4. 保存来源路由时去除 `runId` 以及会话、认证和追踪参数；RWID 作为独立业务字段保存。不要保存包含令牌的完整 URL 或原始 HTML。

## 默认筛选

默认查询上海时间当年 1 月 1 日至当天、全部 8 个大队：

1. 打开“产品监督”。
2. 展开“查询统计”，进入“法律文书查询”下的“法律文书”。
3. 明确设置开始日期为当年 1 月 1 日、结束日期为当天；不要依赖网页残留值。Element UI 日期区间必须用每端输入后的 `Tab/Enter` 提交语义关闭，再重开控件回读实际两端值和月份；输入框一度显示正确但重开后回退，表示组件状态没有生效。
4. 管辖单位选择“全部管辖单位(含派出所)”。
5. 默认不选“执法单位”，表示无锡支队全部 8 个大队；用户指定单大队时才选择对应执法单位，并把该条件写入批次筛选快照。
6. 打开“法律文书类型”，切换到选择器第 2 页，精确选择“消防产品监督检查记录”。不要把“消防产品监督检查记录表”等相似文字当作成功。
7. 点击“搜索”，等待顶部细进度条和表格加载遮罩消失、列表连续两次回读一致；读取页面实时总数、每页条数与页数，不硬编码历史截图中的数量。

把筛选条件和列表页证据保存在 `原始案卷/案卷目录截图/<批次>`。截图仅供人工回查，清单以页面结构化数据为准。

发布前只抽取一个真实案卷验证下载链路时，创建批次必须加 `source begin --acceptance-sample`，并在筛选 JSON 中记录 `acceptanceMode=SINGLE_CASE_DOWNLOAD_PROOF`、页面实时总数和样本数。此模式明确是 `SAMPLE_ONLY`，不得冒充年度全量稳定清单，也不得更新正式水位。

## 执行模块与固定顺序

下列模块按顺序执行，前一模块的回读信号未出现时不得跳到下一模块。来源网页慢、分页会变化，因此**页码只是导航坐标，RWID 和项目编号才是身份**。

### 模块 A：固定可见窗口与会话

1. 用户手工登录后，在当前右侧受控浏览器固定为 **1600×1400**；一个批次内不再改比例。若显示仍被裁切，停止并由用户确认新的固定比例，再将新值写入本批次操作摘要。
2. 不读取或保存浏览器的密码、Cookie、令牌、下载历史或配置。页面跳回登录、无权限或会话过期时，只提示用户手工恢复登录。

### 模块 B：筛选与列表水位

1. 按“产品监督 → 查询统计 → 法律文书查询 → 法律文书”进入筛选页，日期提交后重开控件核对实际值和月份，再明确回读管辖单位、空的执法单位和第二页的文书类型，只点击一次“搜索”。日期快捷项“本年”也必须按同样方式回读；若得到跨年区间，立即拒绝该值并明确填写两端日期。
2. 读取页面实时 `总数 N`、`每页条数 S`、`总页数 P`；必须满足 `P = ceil(N / S)`。远距离翻页优先使用结果区右下角页码输入框直接跳转。跳转后等待当前页码等于目标、可见行数符合预期、顶部细进度条和加载遮罩均消失，再连续两次回读相同的首末 RWID；其中任一信号未满足都不能保存该页。
3. 尾页优先的首个游标为“最后一页最后一个可见行”。执行 `source tail-cursor --total-count N --page-size S --page-number P --visible-row-count R`，其中尾页应满足 `R = N - (P - 1) × S`。不一致表示列表尚未刷新或来源总数变化，必须等待、重新回读或保存“清单变化中”断点，不能猜测最后一条。
4. 将 `N/S/P`、当前页、当前可见行数、RWID、项目编号、`sourcePage`、`sourceRow` 和 `tailOrdinal` 写入本地来源记录。完整年度批次仍要连续两轮全量清单一致；单案下载演示只记录 `liveTotalCount` 和首个尾页游标，不能更新 `CaseWaterlineV1`。

### 模块 C：案卷入口与详情证据

1. 一行中出现“文号或文书名称”和“关联项目／案卷名称”两个可点击文本时，**只能点击后者**。前者是单份法律文书／打印入口，不能用来进入案卷。
2. 进入项目详情后，先同时回读项目编号和文书目录；项目编号必须与清单记录一致。然后保存完整详情截图并直接提取结构化字段，未知字段留空。
3. 截图、来源页面地址和 RWID 仅保存在工作目录的来源证据中；不进入上传 manifest。

### 模块 D：打包请求与异步接收

1. 详情页按“打包 → 全选 → 一次性核对全部可下载叶子文书 → 开始打包”执行。父级半选、隐藏操作列或按钮变色均不能替代叶子核对。
2. 点击“开始打包”前生成本案下载基线。浏览器下载事件只是**快速提示**：3 秒内没有事件不代表打包失败，因为来源系统可能先在服务器异步生成压缩包。
3. 点击后运行 `source await-download --batch-id <批次> --rwid <RWID> --download-baseline <基线> --attach`。它在已配置下载目录中轮询最多 30 分钟：只接受相对基线唯一新增的 `.zip`，连续 3 次大小稳定且 ZIP 可打开后才自动规范命名、移入工作根，并在哈希复核后删除下载目录中的该临时副本。
4. `.crdownload`、`.part`、`.tmp` 等临时文件代表仍在下载，绝不确认；持续 5 分钟无大小或更新时间变化标记为 `STALLED`，超时标记为 `WAITING`，多个候选标记为 `AMBIGUOUS`。这些状态都保持“案卷包待接收”，不进入整理或上传。

### 内置浏览器 Blob 本地恢复

仅当同一轮下载同时满足以下证据时，才使用本恢复路径：

1. `Network.loadingFinished` 表明同一点击的来源响应已完成，且其数据长度与下载事件的 `totalBytes` 一致；
2. `Page.downloadWillBegin` 给出同轮的 Blob URL、建议 ZIP 文件名和下载 GUID；
3. 随后的 `Page.downloadProgress` 为 `state=canceled`、`receivedBytes=0`，而下载目录没有新增 ZIP。

这表示来源系统已完成打包，**内置浏览器的 Blob 写盘交付被取消**。它不是 ZIP 转换失败，也不是等待更久能解决的 `.crdownload`。不得读取或保存 Cookie、令牌或其他会话数据；不得从任意历史响应、未知请求或其他页面取包。

恢复步骤如下：

1. 在点击前照常建立本案下载基线；保留本轮 `downloadWillBegin` 的建议文件名、`downloadProgress.totalBytes` 和对应的已完成网络请求 ID，仅用于当前会话，不写入上传 manifest。
2. 仅对该已完成请求调用 `Network.getResponseBody`。返回值必须是 Base64，且解码大小等于 `totalBytes`，文件头为 ZIP；否则保持“案卷包待接收”。
3. 在同一受控浏览器会话中加载 `scripts/browser_blob_receiver.mjs` 的 `receiveBrowserBlobZip`，以已配置下载目录、建议 ZIP 文件名、Base64 包体和预期字节数调用。该程序只允许直接子文件、拒绝覆盖，以临时文件加硬链接原子落盘，并返回 SHA-256。
4. 然后运行 `source await-download --batch-id <批次> --rwid <RWID> --download-baseline <本轮基线> --attach`。它仍负责唯一候选、ZIP 安全检查、哈希命名、基线消费回执、移入工作根和状态更新；仅在工作根副本复核一致后删除下载目录中的恢复 ZIP。

若 CDP 不开放 `Network.getResponseBody`、包体不完整、原子落盘失败或 ZIP 校验失败，记录 `IAB_BLOB_DELIVERY_UNAVAILABLE` 并停在“详情已采集、案卷包待接收”；不得反复点击。此时只能由用户在支持原生下载的外部浏览器手工登录来源系统后继续，不能导出或迁移内置浏览器会话。

### 模块 E：下一案卷与断点恢复

1. 当前页从底部向上处理：同页下一个为 `row - 1`；当前行是第 1 行时，下一个为上一页的“最后一个可见行”，翻页后必须重新读取行数，不能假定等于 `S`。
2. 位置变更时先以 RWID 确认相邻来源记录；进入详情后再以项目编号确认最终案卷，避免前端新增文书导致页码偏移后跳错。不能凭列表特征直接跳过；只有详情项目编号命中已完成水位，且上传和飞牛均为 `VERIFIED`，才只更新 `lastSeenAt` 而不重新下载。
3. 任一页总数、页数、可见行数、项目编号、ZIP 候选或下载基线不一致时，只暂停当前案卷并保存断点；其他已确认案卷不受影响。

## 已标注页面的低延迟执行规程

以下规则来自已登录页面的实际标注，用于把“产品监督 → 查询统计 → 法律文书 → 打包下载”变成可重复的浏览器操作。它们是**语义定位优先、已观察结构辅助**的规则：先核对可见文字和业务容器，再把观察到的元素结构作为消除同名控件歧义的回退；不能只依赖坐标、菜单序号或一次性的页面位置。

### 导航与筛选

| 阶段 | 首选定位与范围 | 成功判据 |
| --- | --- | --- |
| 产品监督 | 顶部 `tab` 的精确名称“产品监督”；若角色不稳定，回退到已观察的模块容器 `#tab-306`，但必须同时核对其可见文字 | 地址包含 `MODULE_ID=306` 或产品监督左侧菜单出现 |
| 查询统计 | 仅在左侧 `ul.el-menu` 的子菜单标题中匹配精确文字“查询统计”，不要在整页直接按文字点击，因为顶部模块栏也有同名文字 | 对应子菜单处于展开状态，能看到“法律文书查询” |
| 法律文书 | 先在已展开的“查询统计”中展开“法律文书查询”，再在该下级菜单内匹配精确菜单项“法律文书” | 查询页显示日期区间、管辖单位、执法单位、法律文书类型和“搜索” |
| 日期区间 | 限定到查询表单的 `.el-date-editor.el-range-editor` 内两个输入；每端填写后用 `Tab/Enter` 提交并关闭，再重开控件 | 重开后两端值仍为上海时间当年 `01-01` 至当天，左右月份与两端一致；只看到输入文字或快捷项高亮不算成功 |
| 管辖单位 | 打开单位下拉后精确选择“全部管辖单位(含派出所)”；鼠标点击没有展开时，聚焦该只读输入并按键盘确认键 | 下拉收起后输入框显示该完整文字 |
| 执法单位 | 默认保持“请选择执法单位”，不触发选项点击；仅单大队任务才选择指定单位 | 输入框仍为未选择状态，或与指定大队一致 |
| 文书类型 | 在法律文书类型下拉容器中翻到其**自身**第 2 页，再精确选择“消防产品监督检查记录” | 下拉收起后显示精确文书名称；不得接受“记录表”等相似名称 |
| 搜索 | 只点击查询表单内精确按钮“搜索”一次 | 结果区的实时总数、每页条数、页数与首行记录已刷新 |

当“查询统计”或分页数字出现多个同名候选时，先以其父容器（左侧菜单、文书类型下拉、结果表尾）限定范围；禁止依靠第几个候选或把每个候选逐一远程查询。

### 列表、详情与打包

1. 搜索完成后，在结果表尾读取实时 `总数`、`每页条数` 和页数；用 `ceil(总数 / 每页条数)` 交叉核对页数，但不把任何历史数字写死。结果区右下角存在页码输入框时优先直接跳到目标页；等待当前页、预期行数、顶部细进度条和加载遮罩稳定后，再连续两次回读相同首末 RWID。尾页优先时使用 `source tail-cursor` 计算当前与下一来源记录位置。
2. 一行中必须点击“关联项目／案卷名称”列进入详情，不点击“文号或文书名称”列的法律文书／打印入口。详情页至少同时出现项目编号和文书目录后再截图；项目编号必须与清单记录一致。字段直接读取表格与目录结构，截图只作本地核查证据。
3. 详情页的按钮文字可能显示为“打 包”。以正则 `打\s*包` 匹配并限定在案卷详情操作区；点击后等待打包面板出现，再点击该面板中的“全选”。
4. “全选”不是成功依据。一次性读取打包面板文书树的可下载**叶子**复选框状态：叶子数必须大于 0，且全部为已选；父级半选状态、按钮变色或树根选中均不能替代这项核对。对多节点状态使用一次 `evaluateAll` 或等价批量读取，禁止逐叶子发起浏览器往返。
5. 仅在叶子文书全选核对通过后，立即执行本案 `source snapshot-downloads --batch-id <批次> --rwid <RWID>`；随后先通过 `tab.playwright.waitForEvent('download')` 注册下载监听，再点击“开始打包”。该监听仅作快速信号，监听超时不得单独判定失败；始终以下载目录基线和 `source await-download --attach` 的唯一完整 ZIP 判定交付，避免把旧 ZIP 或未完成临时文件误认成新包。
6. 浏览器建议名即使乱码也只记录为审计信息。只有相对本案基线唯一新增、临时扩展名消失、大小多次稳定并能作为 ZIP 打开的文件，才可交给 `source attach-package`；该命令负责按 `<项目编号>_案卷包_<哈希前12位>.zip` 存入对应验收或待处理目录，并在哈希复核成功后清理下载目录中的同一文件。

### 慢页面、超时与会话恢复

- 该来源网页及其受控浏览器回传可能需要约 20 秒。每次浏览器调用只执行一个页面动作，再做一个最小状态读取；不在首页执行全页 DOM 快照，不对多个候选逐个 `evaluate`，也不把同一步拆成串行远程循环。
- 页面顶部可能只短暂出现不醒目的细进度条。页码输入或搜索动作后宁可延长一次等待，也不能在进度条、表格加载遮罩或页码状态尚未稳定时重复点击；稳定判据是目标页、预期行数、进度信号消失和首末 RWID 连续两次一致。
- 点击后到达调用超时不等于点击失败。先回读当前地址、目标容器或按钮后的唯一状态；来源系统异步打包时即使下载监听在约 3 秒内超时，也要保持单次点击结果并交给 `source await-download` 轮询目录，不能立刻重试。只有确认页面无进度、基线未消费、下载目录没有 ZIP 或临时文件时才允许新建基线并最多重试一次。
- Element UI 的只读选择框偶尔会吞掉鼠标点击。只有已经确认字段语义与范围正确时，才可以使用“聚焦后按键盘确认键”作为打开下拉的回退；随后仍须按精确可见文字选择并回读字段值。
- 页面操作异常导致控制连接重启时，先从当前内置浏览器的受控标签列表恢复已有来源页；若该页仍存在，不要求用户重复登录。日期填写、翻页或选择动作超时后也遵循这一规则：先恢复并回读当前值，不能假定失败后重做。只有可见页面实际回到登录页、无权限页或会话过期页时才暂停请求手工登录。
- 将每个阶段的“目标控件、开始时间、最小成功信号、重试次数和断点原因”写入批次状态或操作摘要。出现重复文字、下拉未收起、总数未刷新、叶子未全选、多 ZIP、下载不稳定或项目编号不一致时，停止当前案卷并保留断点，不用猜测继续。

## 分页清单与稳定性

- 来源页面报告的 `总数 N` 是文书记录水位，必须逐条保留并满足各页原始条数之和等于 `N`；同一 RWID 可因初查、复查而出现多次，不能把去重后的 RWID 数冒充页面总数。RWID 只是详情导航键，项目编号是进入详情后确认的最终案卷键；不得把 `runId` 当作身份键。
- 每条文书记录保存文书名称、创建时间、页码、行号和来源顺序。同一案卷名称按尾页开始的实际处理顺序，第 1 条标 `INITIAL/初查`，第 2 条标 `RECHECK/复查`，第 3 条及以后标 `ANOMALY/检查记录次数异常`。次数异常写入非阻塞 `anomalies`，继续详情、下载、提取和上传，不进入 `conflicts`。
- 遍历页面报告的全部页码后形成一轮文书记录集合。再次完整扫描；只有连续两轮全部文书记录及其 RWID 映射一致，才把 `BrowserCaptureV1` 标记为稳定。
- 集合发生变化时最多执行三轮完整扫描。第三轮仍不一致则保存每轮差异和最后完成页，水位标记“清单变化中”，本批次不得宣称完整。
- 完整文书清单稳定后即可按尾页顺序逐个处理不同 RWID。每个 RWID 必须进入“关联项目／案卷名称”详情读取项目编号；同一项目编号对应多条 RWID 时保留每条初查/复查证据，但案卷包只下载一次。项目编号或详情关键身份字段冲突时才标记“需人工处理”。
- `CaseWaterlineV1` 只按详情项目编号判断。项目已完成且上传与飞牛均为 `VERIFIED` 时跳过下载；次数异常、文书时间差异或列表指纹差异不能单独重开或阻塞案卷。
- 翻页后重新核对当前页码和首末条目标识，防止加载延迟导致重复读取上一页。单页失败只保存断点，不跳过后仍宣称清单完整。

## 详情采集

打开案卷详情后，直接读取页面表格和文书树中的结构化字段：

- 项目编号、单位名称、单位类别、单位地址；
- 受理日期、检查情况、消防监管机构、承办人和所属大队；
- 产品名称、生产单位、数量、市场准入/质量结论和检查结果；
- 文书目录、创建时间、审批状态以及能明确判断的初查/复查关系。

项目编号必须与列表条目一致；不一致时停止该案。把可确认值和来源位置写入 `SourceEvidenceV1`，未知值留空，不从截图 OCR 猜测。依据产品结果和文书目录生成可重叠标签：`现场检查`、`抽样送检`、`不合格`、`复查`、`合格`、`待确认`。

每个新增或变化案卷保存一张完整详情截图到 `原始案卷/待处理案卷/<项目编号>`。截图是核查证据，不是 manifest 文件，也不能替代结构化字段。

## 打包下载与交接

1. 在详情页点击“打包”。
2. 点击“全选”，再读取文书树的选中状态，确认所有可下载叶子文书均已选中；只看到按钮变化不足以证明全选成功。
3. 每个案卷点击前运行 `source snapshot-downloads --batch-id <批次> --rwid <RWID>`，保存绑定当前批次、RWID 和项目编号的下载目录基线；不能跨案卷或跨批次复用。
4. 点击“开始打包”后先监听新下载；监听必须挂在受控标签的 `playwright` API 上，而不是标签外层对象。监听只用于快速提示，未在短时间收到事件时仍继续运行 `source await-download --download-baseline <基线> --attach`，由它等待临时扩展名消失、文件大小连续 3 次稳定并能作为 ZIP 打开后自动绑定。
   该命令只监测 `workspace.toml` 配置的下载目录，默认最长等待 30 分钟、每 5 秒轮询；`--attach` 成功后会生成不可覆盖的基线消费回执，并只保留工作根中的原始 ZIP。不得从浏览器临时目录或其他目录挑选同名 ZIP。
5. `.crdownload` 等临时文件表示下载仍未完成；文件持续 5 分钟无变化时标记 `STALLED`，总等待超时标记 `WAITING`，多个新增 ZIP 或 ZIP 与临时文件并存标记 `AMBIGUOUS`。这些状态都不消费基线、不运行 `attach-package`、整理或上传。只有确认页面无进度、下载目录没有 ZIP 或临时文件且基线未被消费时，才允许新建基线并最多重试一次；两次均未交付文件才记录“下载交付不可用”，不得第三次点击“开始打包”。
6. 一次动作只接受一个相对本案基线新增的完整 ZIP。没有新文件、出现多个候选、下载超时、ZIP 不完整或浏览器会话过期时，保持“采集失败/待重试”，不得猜测文件归属。
7. 计算 SHA-256，按 `<项目编号>_案卷包_<哈希前12位>.zip` 移入 `原始案卷/待处理案卷/<项目编号>`；在 `SourceEvidenceV1` 记录浏览器建议文件名、规范文件名、完整哈希、大小、基线指纹、候选属性和下载清理结果。乱码建议名只作审计，不参与案卷识别。
8. 工作根内的原始 ZIP 不覆盖、不改内容、不删除；只有下载目录中的同一临时副本会在哈希复核后删除。`attach-package` 随后由 `inventory` 安全解压和清点；浏览器不直接解压或上传。

## 中断与恢复

- 每个页面、详情和下载步骤完成后更新批次断点。重新运行必须核对同一工作根、筛选快照、RWID、项目编号及现有包哈希。
- 会话过期时提示用户重新登录，随后从最后一个未确认步骤继续；不得因为重新登录而新建重复案卷。
- 单案采集失败、下载异常或字段冲突不阻塞其他案卷，但必须保留明确错误摘要和重试次数。
- 来源采集完成不等于 V2 上传完成；最终进度以 `CaseWaterlineV1` 为准，只有登记系统飞牛核验达到 `VERIFIED` 才能进入已完成和自动归档。
- `acceptance` 样本完成只表示“真实浏览器下载和本地接收链路通过”；其证据留在 `工作区/采集批次/<批次>/验收样本`，不进入正式队列，不允许继续执行 `inventory` 或上传。

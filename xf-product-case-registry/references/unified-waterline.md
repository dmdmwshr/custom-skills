# 年度总水位与三个月增量复核

先按监督系统本年完整案卷任务清单对齐年度索引，再优先核实迁移不合格子集；年度基线完成后才将近三个月文书扫描作为日常默认。范围、六类入口和年度身份验收见 [年度基线](annual-baseline.md)。历史本地案数、文书数和 RWID 数都不能代替来源年度案卷数。

## 查询契约

唯一总账是按项目编号键控的 CaseWaterlineV1。ledger status --scope all 是默认；--scope source-year --year YYYY 按来源年度成员筛选；--view all|unqualified|unknown|unfinished 从同一集合派生；--scope batch --batch-id <批次> 限定指定批次。批次原日期、类型和计数不改写。ledger report 是只读本地报告，不意味着访问来源或服务器。

1.9.1 导出的案卷水位记录表包含“所有案卷、不合格案卷、待确认案卷、未完成案卷”四张中文视图，来自同一次总账证据快照；旧断点表保留为隐藏兼容页。五个阶段、活动待办和证据说明分列。未完成视图中的历史回执缺口不自动进入活动队列。

总账累计包括明确绑定的历史归档代际。分别计数来源文书、去重案卷、材料已采集、系统已登记、正文已核验、已归档、全部完成、历史完成。历史没有新版正文回执时为 LEGACY_UNSPECIFIED，不能补写成已深核；保留历史完成，证据缺口单列，日常处理队列不自动重做历史完成案。来源覆盖固定标为已知案卷，不宣称来源系统全部历史。

五阶段互相独立。“系统已有、材料未采集”如实显示两种状态；来源分类未知不当作合格。初查产品按有效结果归类：抽样且申请复检时最终复检未返回属于待确认，最终合格覆盖原抽检不合格；整改复查合格不会从初查不合格子集中剔除该案。年份取初查日期。

## 日期与去重

source scan-plan 只生成只读计划和待办，不打开浏览器；默认 auto 在年度完整身份对齐后切换近期增量，也支持显式 annual-baseline/recent。近期窗口取上海执行日减三个自然月，同日不存在时取该月末日；2026-09-20 对应 2026-06-20 至 2026-09-20，跨年正常。日期筛选是来源文书创建日期，不是初查日期或审批日期。来源年度任务筛选则保存其页面实际字段，两者不混用。

正式筛选使用 selectionMode=RECENT_DOCUMENT_ACTIVITY、显式 startDate/endDate、dateFieldLabel=创建日期、documentType=ALL、全部管辖单位及全部大队；页面回读证据路径 queryEvidencePath 必填。不要从计划假造页面已选择。旧年度通知书批次保持原筛选契约，可查看或续跑，不移作日常默认。

两轮稳定的是本窗口清单。文书集合指纹排除页码、行号、抓取时刻等位置噪声；同 RWID 的已知文书指纹取累计并集，窗口移出旧文书不等于删除。RWID 必须已由详情证明对应唯一项目；身份冲突时停止该案。新文书只打开关联案；往年案的近期复查照常发现。

source.lastObservedAt 是来源复查时刻，latestDocumentCreatedAt 是文书日期，workflowUpdatedAt 是本地工作时刻。上传、对账或归档不能把本地时刻冒充来源更新。

## 历史索引与恢复

ledger index-history 仅复用已保存的正式批次，默认报告；--apply 合并经详情项目身份确认的索引。未关联项目的 RWID 单列，不猜测身份、不下载包、不打开来源页面。先执行一次索引合并，再开始日常窗口扫描。

已保存的来源详情可补充最小分类索引：仅明确只有初查、状态为“已结案[合格]”、每项产品的市场准入及现场质量检查均为“未发现不合格现象”，且没有冲突结果时判合格。分类绑定该项目证据文件摘要；模糊、复查或相互冲突的详情不据此归类。预定检查日期和文书创建日期不能填作实际初查日期，缺失时年份保持待确认。

稳定批次后 source scan-plan --batch-id <批次> 给出跳过、续跑、读取详情或身份冲突。已完成案文书未变复用原证据；合格最小索引也不默认收全包；未完成案即使滑出窗口仍保留，不合格优先。归档后新增文书记为来源变化，保留原归档及原系统绑定；按变化证据对账并处理差异，不新建完整导入任务覆盖旧案。

ledger reconcile --api-base <系统地址> --project <项目编号> 默认只报告；加 --apply 才保存服务器已证明的本地进度。总账及上传状态原子落盘，写前重读摘要以防同案并发。服务器已终结且临时接收清单为空时，使用正式目录、清单槽位及归属关系确认；不能据此补传或再次 finalize。对账不下载正文，也不会生成正文核验回执。

CaseImportStateV1 的检查日期及产品结果位于 fields.<字段>.value，读取时展开来源包装再判断初查有效结果。不能把顶层不存在的 result 或 inspectionDate 当成真实缺失。系统快照摘要或分类变化单列报告；系统确认的大队身份可补充本地索引，不冒充来源已采集。

1.9.2 对账同时保留服务器文件 ID、哈希、大小和内容代际。最新已核对的正式业务结果优先于旧清单分类，明确的新来源变化证据再进入待办分类。正文回执与已核对的当前文件集合不符时，旧归档保留，但当前正文完成撤销、只把关联案加入对账待办；确认正式案已不存在时也不再显示“系统已登记”。默认报告阶段仍不写本地或服务器，执行阶段只保存查询证明的事实。

已归档案的新活动另存 SourceChangeV1，绑定原归档、文书集合指纹、只新增的文书清单及证据摘要。相同观察重复落盘时复用原文件，多份变化证据均保留；若必要的初查证据更新，不合格优先级按新证据计算。source scan-plan 在原项目待办中列出这些变化，原材料和导入断点保持原样。该阶段只证明“已发现变化”，不代表新文书已补录；需要继续按差异证据核对既有 V2 文书/字段入口及正文代际。历史冲突专用 supplement 不能冒充新文书增量导入；未完成差异核验与归档前保留 changePending。

正文回执 ContentVerificationV1 保存在项目工作区，绑定项目、系统 origin/caseId、当前 manifest 摘要和每份 fileId/SHA-256/size/contentGeneration/核验时间。只有文件身份及代际完全一致才复用；每核验一份即原子保存，中断后只补未核验文件。全部下载完成后再次读取目录身份，防止途中发生变更。旧回执不充分时保留未确认，不重新上传、归档以凑统计。

1.10.2 保留五阶段独立性：原系统案卷即使缺少本地 V6 上传断点，只要当前服务器绑定、完整清单摘要及全部文件身份和代际与正文回执一致，也可以显示“正文已核验”。这不会生成上传状态或将归档标为完成。原系统人工字段与历史清单不同，须留存差异并按服务器当前事实对账，不为通过核验改写业务字段。

1.10.3 新增 verify-existing --manifest <完整清单> --api-base <系统地址>：用于服务器原有、没有本地 V6 上传任务的正式案卷。先按服务器事实对账，再逐份正文续核；加 --archive 才收口本地材料。归档回执分别绑定历史导入清单的包摘要和本次实际采集包摘要，保留原任务，不创建上传状态。重复核验且身份、清单和内容代际均未变化时保留原正文完成时间及回执字节，复用明确归档，不产生重复完成代际。

来源明确缺少材料时在 source.materialGaps 保存缺失文书、理由和证据绑定。此时材料已采集为否，即使系统已登记、正文已核验也保持未完成；归档前同时检查材料缺口和 changePending。已经归档的历史代际仍保留，不能因当前缺口抹掉历史事实，也不能把当前阶段标为全部完成。

1.10.4 按证据时序计算当前系统状态：上传前读到“系统尚无此案”的观察不能否定后来服务器正式建案回执；正式建案之后的新对账仍可撤销不存在或已变更的状态。未确认时序保守保留，不用本地处理时间冒充来源变化。

1.10.6 支持来源市场准入结果后附认证编号的明确格式，例如“1项不合格(2021081810000043)”或“1项不合格(认证证书编号：Z2016081814000269)”。编号仅允许已验证的 16 位数字及可选 Z 前缀，仍须同时满足初查标记及错误图标；零项、抽样、整改复查、待复检文字均不据此确认。总账表逐案标明是否属于当前年度已核实范围，文书候选与确认不合格分列；年度覆盖页同时展示各类清单稳定性及所有案卷、不合格子集的独立进度。正文已核验但来源材料缺失时，在证据说明中明确列出缺件和不能归档。

初查现场结果显示“1项不合格”等正整数项数时，仍需同时具备初查标记、明确错误图标及没有冲突的结果，才确认不合格；“0项不合格”、待复检或模糊文本不据此归类。整改复查合格不清除初查不合格。

同一项目和 RWID 的结构化详情完全相同，仅因页面时钟、滚动或重新登录产生不同截图时，保留原截图并追加新的不可覆盖截图证据，不触发来源变化或重新采集。旧截图必须物理存在且摘要一致，真实字段变化仍阻止覆盖。可复核后只解除该案旧版截图误报，其他身份、材料冲突保留。

## 验收与报告

隔离验证包括同案跨列表/批次、跨年窗口、老案新增文书、未完成案滑出窗口、复检改判、整改复查独立、归档累计及正文中断恢复。真实验收另记录来源页面是否通过、3 案完整流程结果和第二轮零重复处理计数。

日常 ledger report 默认只展开活动待办及明确异常，保留分类/阶段总数和历史覆盖缺口，不反复列历史案号和旧日志。需要所有明细时显式 --all-cases，或打开四视图总账表；三个月窗口未实机完成或登录中断时明确标注，不把历史年度两轮稳定当成本轮完成。

# 从业务需求到可复用查询

目标是取得用户需要的统计数据。来源监督系统当前按用户已知条件没有可用的数据获取接口，因此用受控页面自动化采集；自建案卷系统负责结构化保存和后续查询。不要把“下载全部文件”当作每个问题的第一步，也不因统计目标自行新增系统功能或部署。

## 需求路由

1. 先明确需求中已有的对象、时间、组织、条件和交付形式，例如“本年不合格案卷”是案卷集合，不是通知书份数；“不合格产品数量”还需产品粒度及初查/复查去重口径。使用已有输入与页面事实消解常规歧义，只在会实质改变结果且无法核实时提问。
2. 查看自建系统现有数据覆盖范围、更新时间、查询筛选与导出能力。能用已核验入库数据回答时直接查询；数据不完整先说明缺口，并在用户授权范围内补采。不能把局部采集后的系统总数当成来源全量。
3. 来源查询优先采用精确类型/字段的定向筛选，减少无关详情与下载；依据页面实际控件和关联关系只读探索，不猜接口、隐藏数据或业务规律。候选记录回到详情确认身份，再去重与下载。
4. 当前授权含下载上传则执行完整流水线；只有统计/查看授权时，只读查询已有数据和页面，不顺带写入。自行探索不授权办理案件、改变审批状态或修改生产数据库。
5. 回答统计时说明：来源、时间字段和范围、覆盖组织、统计粒度/去重键、排除规则、数据截至时间、完整性与未决项。界面总数、文书数、项目数、产品数不能混用。

## 已知方法：不合格案卷

- **当前业务规则（2026-09-20）：**年度完整任务清单为总水位基准；文件/法律文书查询中的“责令限期改正通知书”用于优先候选筛选。必须回到初查产品有效结果确认不合格，抽样复检采用最终结果；整改复查合格不抹掉初查不合格。原 2026-09-19 通知书批次保留其筛选含义，不再用通知书存在替代有效结果判定。
- **当前已实现的程序支持：**`ANNUAL_RECTIFICATION_NOTICE` 接收精确类型、现场页码、日期字段标签与查询证据引用；两轮清单稳定、RWID 到项目编号去重沿用已有流程。通知书数量不生成初查/复查标签。
- 初查现场不合格可复用经身份核验保存的详情结构化证据：必须同时确认初查阶段、非送检/复检标记、错误结果图标和明确不合格检查文本。来源内部的 `SFHG` 单值含义不能跨初查和复查套用。送检或复检仍按对应最终文书确认，通知书标题或整改复查不合格不单独决定初查分类。
- **页面验证状态：`UI_VERIFIED`（2026-09-19 20:54 CST，案卷执行任务回读）。**在“法律文书类型”选择器输入精确名称“责令限期改正通知书”并搜索，出现唯一同名选项；选中后按创建日期本年、全部管辖单位、执法单位空查询成功。选择器搜索结果的实际页码须现场记录，不沿用旧默认第 2 页。日期明确表示通知书创建日期，不是项目创建、检查或结案日期。该次快照为 69 份文书、50 条/页、2 页；只是当次页面事实，不能硬编码成年度案卷数。此验证证明查询路径与日期含义，尚不代表两轮清单完整、去重完成或全年度正式入库已通过。真实筛选证据保存在执行任务工作根，按批次 `queryEvidencePath` 回查。
- **执行步骤与正式放量：**见 [年度不合格案卷](annual-unqualified.md)。结果表先列文书记录数，再列 RWID 和合并项目数；只对已确认项目开展后续整理入库。

## 沉淀方法

每条可复用方法保留：需求名称、用户定义、页面入口和筛选组合、日期字段含义、结果与案卷/产品的关系、去重键、最小验证案例、覆盖限制、验证时间和状态。状态分 `USER_DEFINED`（用户给定）、`UI_VERIFIED`（页面验证）、`INFERRED_PENDING`（推断待验证）。相似术语或一次相关性不自动升级为业务规律。

真实截图、业务清单和运行回执留工作根；账号凭据只经既有本机凭据入口使用，不写入这些证据。Skill 只记录脱敏规则和引用方式。当前执行任务可在已授权范围内完成规则更新，经 CC Switch 受管发布并核验安装副本；同一具体变更保持单一写入者。下一次相同需求直接复用已验证方法并做轻量页面漂移检查。

自建系统的业务统计入口、接口可用性与统计定义要逐项核实；现有上传/核验接口不能推定具备通用统计接口。尚未实现的查询功能记为后续能力需求，不冒称当前 Skill 已交付。


## 年度基线完成后的日常近三个月文书活动

方法编号 RECENT_DOCUMENT_ACTIVITY；状态 IMPLEMENTED_UI_PENDING（尚未完成此筛选的实机验收）。执行日按上海时间减三个月作为创建日期起点，跨年正常；全部管辖单位、执法单位不收窄、文书类型 ALL，两轮稳定仅覆盖本窗口。来源组织以页面实际值为准，不用本地八个业务大队枚举裁剪来源年度覆盖。使用 source scan-plan → 页面筛选回读 → source begin --filter-json → 两轮 add-page/finalize → 增量计划。历史年度筛选验收结果不转用为此方法的实机证明。

来源文书指纹不包含分页位置和本地时间；同案合并到项目唯一总账。不合格由初查产品有效结果判断，抽样复检按最终结果，整改复查独立。合格先建索引，未知先补必要证据，未完成不因窗口移出消失。旧文书无近期活动的原地修改不保证发现，明确线索时定点检查。详见 unified-waterline.md。

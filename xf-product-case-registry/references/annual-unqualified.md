# 年度不合格案卷：筛选、小批验证与放量

适用于用户明确授权将本年全部不合格案卷录入现有登记系统，且指定“案卷文书目录含责令限期改正通知书”为筛选依据。以执行时上海时间的年份为准，记录实际起止日期；2026 年任务为 2026-01-01 至 2026-12-31。来源日期字段沿用浏览器采集契约并记录，不把检查日期、结案日期或下载日期互换。

## 1. 恢复与登录

1. 回读工作根、水位、现有批次、下载/上传断点和当前服务状态。已有案卷按项目编号对账；不得因本轮任务新开而重新下载或创建重复导入任务。
2. 用户授权指定账号自动登录时，使用 `playwright-browser-control` 的现有命名会话和 LocalVault 标准输入入口。先回读页面账号身份与业务权限；仅看到菜单不足以确认指定账号。若只显示姓名，使用已核实的账号与姓名对应证据或页面个人信息核对，不猜账号，不自动退出用户其他会话。
3. 登录失效时自行处理用户已授权的普通图形验证码、一次填密提交和结果回读；不在填密后单独生成快照。验证码错误可清空密码并刷新验证码后重新辨认；认证失败先辨明原因，不循环撞密码。遇工具强制停止仍遵守工具边界。

## 2. 全年清单与精确入选证据

1. 优先自主核实用户给出的直接查询法：在产品监督的文件/法律文书查询中，精确选择“责令限期改正通知书”，限定本年和全部 8 大队，直接取得不合格候选。回读实际选项、日期字段含义、筛选值和关联案卷入口；不照抄原默认“消防产品监督检查记录”。默认不加已结案或最近 90 天限制。每页 50 条、一次读取结构化行，两轮完整清单一致；最多三轮仍不稳则记录范围缺口。逐案操作按已验证页面布局切回 20 条。
   - 该正式分支的 filters 使用 `selectionMode=ANNUAL_RECTIFICATION_NOTICE`、精确 `documentType=责令限期改正通知书`、现场回读的 `documentTypePage`、实际日期字段标签 `dateFieldLabel` 和工作根内筛选证据引用 `queryEvidencePath`，其他年度/管辖条件沿用现有契约。选择器页码不可照抄旧默认值 2；文书查询支持新分支不等于页面已实测。
   - 程序仅检查这组筛选元数据，不会替执行者读取证据文件或验证页面真的选中通知书。必须在页面回读精确类型并抽核真实结果；`queryEvidencePath` 指向实际保存的工作根证据。现有列表提取器要求“创建日期”等列，若新查询布局不同先确认实际结构并适配，不伪造列名或将其他日期改称创建日期。
   - 本年文书日期、项目受理日期、检查日期属于不同口径。先记录当前查询实际含义；需要按项目年度覆盖跨年文书时再依据真实字段补漏，不能直接将文书日期当作项目创建年份。直接类型筛选不受支持或只有模糊搜索时，才回到宽清单逐案目录核对，并记录覆盖限制。
2. 每个不同 RWID 读取详情项目编号后合并同案。展开并完整读取实际案卷文书目录，核实目录加载结束，按文书 ID 去重。
3. 入选状态分三类：
   - `INCLUDE`：本案实际目录类型或文书标题明确为“责令限期改正通知书”。允许去除排版空白，不用模糊关键词代替。目录仅显示“某某消限字…”等文号时，读取实际文书类型或正文标题再判定。复查合格、后续整改或结案均不改变入选。
   - `EXCLUDE`：身份无歧义且目录完整，确认没有该文书。
   - `UNKNOWN`：目录未完整加载、项目身份不符、标题或类型无法确认。待补读，不计作排除或完成。
4. 在业务批次目录保存逐案轻量筛选回执，至少含：筛选口径版本、年份/日期字段、RWID、项目编号、单位、目录是否完整、实际标题/类型、文书 ID 或文号、证据路径、采集时间和上述状态。没有该文书时保留完整目录证据。不要把真实回执提交进 Skill 仓库。
5. 现有 `_derive_tags()` 只做全文标签，不能实现本项筛选；文件名或标签也不能决定 51 槽位文书分类。入选后仍按正文和文书分类契约整理。
6. 通知书清单中的多份文书只计来源记录，按 RWID → 详情项目编号合并案卷，不依通知书出现顺序猜初查/复查或检查次数。该查询分支不生成检查阶段标签，阶段事实另由真实详情/正文取得。

## 3. 三案正式端到端验证

1. 从 INCLUDE 且尚未完成正式入库的案卷中选 3 个；优先覆盖不同目录结构、有复查等情形，但不为凑样本重复导入。全年实际待办不足 3 个时完成全部待办即可，无需制造样本。
2. 使用正式采集批次，逐案执行：身份核对 → 精确文书 ID 集合与全选核对 → 新下载基线 → 单次打包 → 原生完整 ZIP 接收 → inventory/识别/拆分/compose/validate → dry-run → finalize → 上传及飞牛核验 → 归档。
3. 两案以上上传用 `upload-batch` 共用认证。记录各阶段耗时、文件数/字节数、ZIP 哈希、服务器任务及案卷 ID、正式建档结果、上传 VERIFIED、飞牛 VERIFIED 和归档结果。
4. 单包下载成功、离线测试、历史已完成案或 SAMPLE_ONLY 均不能充当本轮正式三案闭环。SAMPLE_ONLY 不直接整理上传；正式流程按现有水位/身份契约接收材料，不手改样本状态绕过隔离。
5. 三案全部闭环后写明放量依据，自动继续；不另向已授权用户索要批量确认。该条件是执行者核验的流程约束，CLI 未内置自动三案门禁。

## 4. 批量、模型分工与异常处理

- 每批最多 10 案，每批完成后回读水位与服务器结果。已上传且飞牛 VERIFIED 的同一案卷计入已完成，不重复下载导入；其他状态按对应契约续跑。
- 仅一个浏览器执行者；同项目仅一个写执行单元。协调者负责账号、身份、槽位歧义、未知结果和异常判断，保持高思考强度。用户允许时，把不同案卷的清点、已确认规则的重复整理、目录精确匹配和结果回读交给 Luna；不要让多个代理争用浏览器或同案水位。
- 优先电子文本、已验证缓存和断点，只补未确认项。`ocr --batch` 仍需同类材料关键字段一致后显式选用；不能为省时省略校验或擅自开启批量 OCR。
- 下载事件缺失先按同一基线等待原生文件。点击、创建任务、上传结果未知先回读，不盲重放；历史失败任务不删除、改绑或重新创建来规避错误。
- 单案内容异常隔离后处理独立案；共性认证、错绑、重复创建、上传接收或服务端故障暂停放量，保存证据并定位。执行 Skill 不授权修改业务代码、部署或数据库。
- 最终分别报告年度文书记录数、不同 RWID、合并项目数、INCLUDE/EXCLUDE/UNKNOWN、既有 VERIFIED、新完成、待处理/失败和扫描缺口。只有清单稳定穷尽、UNKNOWN 清零且每个入选项目均正式完成，才能声称全年全部录入。

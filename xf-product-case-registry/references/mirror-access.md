# 同步资料主操作入口

用于用户明确要求把已有同步资料的一端作为主要直接操作入口。同步方式、唯一项目编号总账和既有采集、识别、上传、归档断点保持原语义；主操作盘不等于新业务根，不重新初始化水位或复制材料。

1. 先核对当前同步配置、后台实际加载行为、最新结果和目标文件。两端必须是同一逻辑资料的已核实配对，不能仅凭同名目录或替换盘符认领。保存当前 workspace.toml 和项目规则的精确备份，确认同一项目只有一个写执行者。
2. 使用 `workspace switch-mirror --work-root <目标主操作资料目录>`。命令检查两端已有布局、同一水位身份、完整业务文件集合及逐文件摘要，取得两端水位锁后才仅改本机工作配置。只有协调锁文件不参与内容摘要。任何缺失、差异、重解析点或核验期间变化均停止；不强制同步或覆盖差异，也不因历史未完成批次创建替代批次。
3. 配置的 root 是实际文件读写入口，identity_root 保留原始逻辑身份，reference_roots 记录已验证的历史入口。工具把旧回执中的绝对路径映射到主操作端后再按原项目目录、文件摘要和内容代际检查。原水位、原包、OCR 回执、清单、上传断点及归档回执不因切换改写，摘要不变。
4. 回读 `workspace doctor`、总账四视图和来源覆盖，对比切换前项目集合、五阶段状态、分类、历史完成与失败断点。检查旧批次、历史归档及 OCR/上传文件映射在新入口可用。已完成案卷不重下、重识别或重传。
5. 更新项目唯一规则、管理记录和交接入口，明确主操作端、同步备份端及真实双向传播事实。默认命令使用当前配置；历史脚本中的硬编码旧根不直接复跑，按原任务参数和新入口核对后继续。

这是一次本机访问配置变更，不修改 FreeFileSync/RealTimeSync 的双向配置，不创建新同步任务，也不改变浏览器既有会话归属。同步写入与另一端回读仍遵循本项目当前授权和同步异常处理规则。恢复时只回退本机配置和相应规则，不回退已经推进的业务资料；以后再切换主操作端仍须重新检查两端完整一致性。

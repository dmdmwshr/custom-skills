# V2 文书分类与规范化规则

先读取 `CaseImportManifestV2.schema.json` 的 `slotCode` 枚举。该枚举是现有 51 个固定文书槽位的唯一编码来源；不要在本地另建槽位、沿用 V1 文书类型，或凭文件名创建“待审核”槽位。

## 文书属性与本地引用（最小映射）

整理后每份文书在本地记录：来源形态（电子 PDF 有文本层 / 扫描 PDF / 图片 / Word / 补采预览，组合件需拆分）、文书用途类别（检查 / 抽样送检 / 限改复查 / 处罚 / 通报 / 送达 / 审批 / 证据保全 / 主体与资质 / 卷内备考）、文号、文书日期、页数、原包摘要、包内成员路径、成员摘要、稳定本地引用键（`LREF|<项目编号>|<成员摘要前16位>`）、材料状态（下载 / 接件 / 身份 / 材料齐全 / 本地整理 / 飞书同步分轴）和未知原因。用途类别只有在正文标题可确认时才算确认；仅凭文件名的记为 `FILE_NAME_ONLY`，无文本层的扫描件不推断日期与文号，待本地识别。引用键映射本地唯一对象，不向云端暴露路径。

## 分类依据

按以下顺序确认文件归属：

1. 电子 PDF 正文中的标题、文号、日期、检查阶段和产品对象；
2. 本机 MinerU 处理的扫描页中的可确认内容；
3. 已确认的同案关联信息。

文件名、页码编号和目录位置只能辅助查找，不能单独决定槽位、阶段、产品归属或版本类别。无法确认时保留在本地，不上传、不列入 manifest。

## 正式版本

- 电子版：优先选择有可靠文本层且正文完整的 PDF。
- 扫描件：用于签字、盖章、手写更正或现场照片；只使用本机 MinerU 作为辅助识别，不能由外部 Zerox 替代。
- 每个普通槽位最多各保留一份电子版和扫描件；现场照片仅允许一份扫描件。
- 原始 ZIP、截图、组合件、重复副本和无法确认的来源都不是正式槽位版本。

## 字段裁决优先级

文书是否归入槽位与哪个来源决定案卷字段是两件事。原始文书只要身份链和正文归属仍能确认，就按实际版本保留；字段差异不能通过删除扫描件、改写 PDF 或把文件移到兄弟案卷解决。

1. `case`、检查和产品字段优先使用项目详情页的结构化采集值；完整详情截图用于证明当时页面显示，不通过截图 OCR 重新猜值。
2. 同一文号、日期和业务对象的电子版与手写或扫描版并存时，正文完整且文本层可靠的电子版字段优先。扫描版继续作为 `SCANNED` 版本保留，签字、盖章和手写内容不被覆盖。
3. 检验报告、营业执照等扫描材料与详情页或对应电子文书不同，只记录为被舍弃候选，不能反向覆盖案卷身份或产品字段；有明确证据表明材料属于另一项目时，仍按身份链冲突停止当前案卷。
4. 两份电子文书互相矛盾、详情页缺失关键值，或项目编号、RWID、单位名称身份链不一致时，不适用自动优先级，保持人工处理。

每次实际应用上述优先级，都在项目工作区的 `field-resolution.json` 记录字段路径、全部原始候选、最终值、权威来源和理由。该文件只作本地裁决审计，不进入 manifest、上传状态或登记系统。

## 多槽位与附件

一个物理来源可包含多个逻辑文书。分割页码范围并为每个逻辑槽位输出独立规范 PDF；即使内容来源相同，也必须建立独立文件引用和相对路径。这样 V2 的每个上传文件只服务一个槽位。

同次检查、同一固定槽位有多份同类文书（例如不同产品的检验结果通知书）时，按文号顺序合成该槽位的一份版本，保留每份完整正文。`split-plan.json` 的对应项可使用非空 `parts` 数组，每段明确 `sourceRelativePath`、`pageStart`、`pageEnd`，输出仍使用唯一 `relativePath`；各段严格按给定顺序拼接，可跨同案清点中的来源文件或选择不连续页。`parts` 与原单段字段互斥，不能混入别类文书或另案材料。拆分索引保留全部分段，核验逐段逐页回到原件比对；单段旧格式继续有效。

只有不属于任何固定槽位、且已确定需要归档的 PDF 才能作为 `OTHER_ATTACHMENT`。不得用其他附件接收未分类、低可信或未关联文件。

## 拆分正文核验

拆分后可运行 `scripts/pdf_split_verify.py --work-dir <项目工作区> --renderer <pdftoppm 路径>`，由现有拆分索引核对来源页范围、规范 PDF 页数和文件哈希，并按相同参数逐页渲染比较。结果只输出小型结构化回执；保存为项目工作区的 `pdf-split-verification.json`，不要将所有页面图片回传会话。

渲染器输出写入独立临时文件，退出后检查 PPM 像素数据长度完整，再比较原页与拆分页；不使用可能截断的标准输出管道，也不把截断回执误判为原 PDF 损坏。正文一致性核验不替代文书分类、阶段和产品归属判断。


## 自动候选、证据等级与日期角色（2026-11-06 一次本地批次的观察，其中真实页面与云端部分未验证）

- 类型分层：**自动文本候选**（页首标题/固定栏目结构/正文正则命中，如送达回证的“送达的文书名称及文号/受送达人”、审批表的“领导审批意见/审核部门意见”）、**独立视觉或人工确认**（绑定具体文件 SHA、页码、观察人和时间，只适用于该页，不推广同类）、**仅文件名**、**未确定**。自动命中不得称“已核实”；统计时分层报告，不合并为一个“已确定”数。
- 文件名不可靠：文件名所指类型在正文中未出现、组合件名与内容不符（如名为“责令限期改正通知书、送达回证和审批表”而内容为通报函、送达回证、审批表）时，以正文为准并记疑点。
- 日期：段内首个匹配日期只是**候选**，不是文书日期；同段出现多个年份或原件内部日期并存时保留为原件疑点，不猜生产日期、不自动改年；日期角色（落款、检查、送达、生产等）须单独判定，未判定即未知。
- 组合件边界：只有每段起点都有页首标题或结构特征证据时才可进入正式 `split`；进一步以文件名类型序列与内容序列印证，或原页视觉确认。起点未被证明的页（封面、二维码页、无字页）保持候选并保留原页集合，不因“页面连续”就认定边界；同类型多份文书按槽位合并规则保留，不按页强拆。
- 识别噪声：MinerU 对二维码/印章块可能返回英文“图像说明”文字，抽取正文时应剔除该块而不是丢弃整页；仅有扫描痕迹的空白页是“原页无字”，不记为识别失败或来源缺件。MinerU 单个任务可能 `engine_error`，原失败保留不重发，可改用 docling-local 在本地逐文件替补。
- 处罚字样与“责令限期改正”只作备注或定位线索，不据此判行案或确认不合格；确认仍以初查/最终产品结论为准。

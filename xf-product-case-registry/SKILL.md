# 消防产品案卷采集、整理与 V2 导入

执行平台：本技能当前交付流程为 Windows。先核对实际目标主机、原生依赖及用户配置；Linux/WSL 不安装或执行 Windows 分支。平台名称指执行端，不因被管理对象是 WSL 而改变。独立远程载荷须另核对目标系统。验收按阶段区分：2026-09-19 的 Windows Edge 登录及单案 ZIP 下载已实测，年度筛选至正式批量入库仍须本轮端到端验证，不用一个下载样本代表全流程。

只适配现有消防产品监督来源网页和登记系统 V2。来源网页负责查询下载，Skill 负责本地整理和调用现有接口；执行本 Skill 不授权修改网站、数据库、接口或部署。飞牛是正文长期存储库，Meifu 仅作临时接替或取回中转，不称为备份。

长期目标是快速、可追溯地取得用户需要的统计数据：把需求转成来源查询和明确统计口径，按需采集并进入自建系统，再利用现有查询能力回答。当前脚本主要覆盖采集、整理、导入与核验，不声称已实现通用业务统计。特殊需求先按 [需求与查询方法](references/query-recipes.md) 自主探索现有页面/系统能力，把已验证方法沉淀回本 Skill；不把一次全量采集模板套用到所有需求。

## 共用边界

- 开始时运行 `workspace doctor`。工作根按本次 `--work-root`、本机工作配置解析；均缺失时报错。首次配置或切换才用 `workspace configure`，不迁移活动批次或旧资料。
- 真实材料、截图、OCR 原文、水位和状态只留在工作根；Skill 只存程序、规则、测试、Schema 和空值示例。优先复用用户已登录的来源浏览器；用户明确指定账号并授权自动登录时，配合 `localvault-credentials` 与 `playwright-browser-control` 的标准输入登录入口，不读取或导出浏览器密码库、Cookie、令牌和配置。无登录授权或工具强制接管时暂停。登记系统认证只由 CLI 使用本机认证配置，不与浏览器登录混用。
- 案卷身份链为“稳定清单可见三元组 → RWID → 详情项目编号与单位 → 本案目录 → 本案下载基线 → ZIP 哈希 → 工作区与清单”。页码、行号、建议文件名和 staging 不能决定归属；冲突只停当前案卷，禁止跨案改绑。
- 同一项目只允许一个写执行单元；输入限本案待处理目录和项目工作区，不读兄弟项目或批次 staging 作为整理输入。已接收 ZIP 的其他项目可在不争用同案的前提下并行处理。
- 优先电子文本层；扫描材料只在本机用现有 MinerU。外部 Zerox 默认禁用，需另获第三方传输授权。识别结果是辅助证据，不替代文书分类和身份核对。
- `CaseWaterlineV1` JSON 是业务事实源，Excel 与报告只是投影。只读查询不得触发识别、上传、归档或更新水位；下一步提示不是执行授权。

## 主流程

1. **先看断点。** 回读 `ledger status`，区分文书记录、详情、案卷包、上传任务、文件接收、正式建档和飞牛核验；不能把截图、目录或状态文件数量互相替代。
2. **采集来源。** 先按本次需求选择已验证的查询方法，再按浏览器契约完成上海时间本年、全部 8 大队和精确文书类型筛选。默认检查记录查询与通知书定向查询分支分开，不伪造文书类型通过校验。全量清单连续两轮一致，最多三轮；每个不同 RWID 先读详情项目编号，再合并同案。第三条及以后检查记录仅作非阻塞告警；通知书条数不推断检查阶段。只有项目已完成且上传、飞牛均 VERIFIED 才跳过下载。
3. **单案下载。** 详情身份连续两次一致后截图；逐案建立基线，核对全部叶子文书已选，再点击开始打包。以 `source await-download --attach` 的唯一完整、稳定 ZIP 回执为准。每案最多两次打包，第二次须满足参考资料的无在途文件和未消费基线条件；Blob/Edge 流恢复仅在对应故障分支启用，不追加重试额度。
4. **本地整理。** 对完整 ZIP 运行 `inventory → ocr/split → compose → validate → upload --dry-run`。当前默认保留逐文件 `ocr`；`ocr --batch` 是显式批量选项，只有同类材料的关键字段一致性通过后才采用，不能因速度更快自动切换。两种模式都逐份保存校验断点，续跑只补未确认项。字段先用详情结构化值，同一文书电子版与扫描版矛盾时用完整电子版；实际裁决写入 `field-resolution.json`，原始版本完整保留。
5. **按当前授权写入。** 新案单案用 `upload --finalize`，两案以上用 `upload-batch --finalize` 共用一次认证会话；不得循环调用单案命令重复登录。既有唯一案卷不重跑完整导入；仅满足服务器实时缺失与历史冲突契约时，才用 `supplement --plan` 后执行缺失补录。始终续用可对账的同一任务，不另建替代任务绕过失败。
6. **核验、归档、交付。** 目录哈希、文件计数、飞牛 AVAILABLE 和落盘时间均确认后才记 VERIFIED；完整导入还须无冲突、无跳过且 created=true。补录按其专用计数和无替换规则判断。上传和飞牛均 VERIFIED 后才归档，归档成功才称完成；批量结束回读水位并生成报告。

用户以“文书目录存在责令限期改正通知书”界定不合格时，按上述年度执行参考逐案记录实际文书类型/标题证据，复查合格仍纳入。全文关键词产生的 `合格/不合格` 标签不能决定入选；目录不完整记未知，不能当作无该文书。先完成 3 个正式案卷端到端验证，再按每批最多 10 案继续；这是执行流程约束，现有 CLI 不会自动代替执行者核验这道放量条件。单案 SAMPLE_ONLY 下载验收不能代替正式入库验收。

## 保持原件与可恢复性

- 原始 ZIP 不覆盖、不改内容。只有下载目录中的同一临时副本会在工作根副本哈希确认后删除。解压、路径边界、重名和资源限制由现有程序校验；异常不跳过校验。
- 固定根级控制文件、规范 PDF、识别缓存和诊断子目录遵守本地格式；不得手改 V6 状态、复制第二套完整清单或把旧 V4/V5 自动升级为可续传状态。
- 浏览器截图、来源地址/RWID、HTML、OCR 原文、水位和人工笔记不进入 manifest 或上传状态。V2 固定四步，不使用 V1，不增加审核项或第五步版本同步。
- 上传中断先回读同一任务的接收清单，保存可核实断点后停止；发送字节不等于服务器接收。认证、限流、慢上传及服务端故障按 V2 工作流分支处理，不把历史排障步骤当作每案必做事项。
- `verify` 默认低流量核对目录与飞牛状态；仅显式 `--deep-content-verify` 才取回正文。网络失败或飞牛离线保持未完成，不能误报哈希不一致或自动归档。

## 隔离验收

真实下载测试使用 `source begin --acceptance-sample`，记录实时总数、样本数 1 和 `SINGLE_CASE_DOWNLOAD_PROOF`。样本为 SAMPLE_ONLY，详情与 ZIP 仅进批次验收目录，不更新正式水位、不整理、不上传、不归档。已经达到打包上限的历史案卷不得重开测试。

用户明确要求“最近已办结案卷”时，按 [Playwright 单案验收](references/playwright-single-case.md) 使用已结案任务列表并记录实际查询日期、结束日期倒序与实时总数；只在 acceptance 范围使用 `LATEST_CLOSED_TASK`，不伪称年度法律文书清单。CLI 扩展的下载事件可能缺失，仍以本案基线和 `source await-download --attach` 的完整 ZIP 回执为准。

对 Skill 的改动按 `cc-switch` 的源仓库、测试、独立提交推送、同步预检、备份和安装副本回读流程发布；未通过真实验收或尚未同步的项目分别报告，不用代码测试代替运行态验收。

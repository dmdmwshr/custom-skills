# 消防产品案卷采集与统一水位

执行平台为 Windows。先核对实际主机、原生依赖和本机配置；Linux/WSL 不执行 Windows 分支。来源网页使用用户已登录的受控浏览器；Skill 负责来源证据、本地整理和调用现有 V2 接口。飞牛保存长期正文，Meifu 仅为临时中转。浏览器证据、OCR 原文和本地采集账本不上传业务系统。

所有案卷按项目编号共用 CaseWaterlineV1。不合格案卷只是筛选子集；来源已登记、材料已采集、系统已登记、正文已核验、归档已完成分别表达，不能互相代替。先读 [统一水位与增量规则](references/unified-waterline.md)。

## 每轮执行

1. 运行 workspace doctor，回读总账及活动待办。首次接入先 ledger index-history 查看本地历史索引差异，当前维护授权内带 --apply 合并；不重新打开全部历史来源页。工作根由本次参数或本机配置解析，缺失时才配置，不迁移旧材料。
2. 用 source coverage 和 source scan-plan 判断年度基线。未完成时先按来源“本年”、全部管辖单位、全部状态核对六类案卷任务清单，两轮稳定后逐项关联项目编号；历史文书标识数不能代替年度案卷数。来源不可用、类别缺失和身份缺口分别保留。年度基线完成后默认扫描执行日向前回推三个自然月创建的全部相关文书，支持跨年。所有筛选先在页面提交回读再保存证据，不使用计划值冒充实测值。
3. 稳定清单先按 RWID 和历史项目身份对账。同一项目跨列表、跨批次合并；近期文书关联往年案时仍进入该案断点。指纹未变且已有有效完成证据，跳过详情、打包、识别和上传。超出窗口的已完成案且无变化线索不处理；未完成案保留，优先其中的不合格案。
4. 仅新案、文书变化或未完成案进入详情。按“清单可见三元组 → RWID → 详情项目编号及单位”闭合身份；页码、行号、文件名和 staging 不能决定归属。初查任一产品有效结果不合格即入子集；抽样复检用最终结果；整改复查只决定案卷类型，统计年份用初查日期。合格案只登记最小索引，分类未知时补必要证据，不能以全文关键词或通知书存在替代判定。
5. 需要完整材料的案卷逐案下载。详情身份连续两次一致，核对全部可下载叶子已选，建立本案基线，再点击一次打包。以 source await-download --attach 的唯一完整稳定 ZIP 回执确认收件；每案最多两次打包，重试及 Edge 流恢复严格按浏览器分支。原始包不可覆盖，工作根副本哈希通过后才清理同一下载临时副本。
6. inventory → ocr/split → compose → validate → upload --dry-run。先复用原文件摘要、电子文本和确认过的 OCR；仅处理新增或变化内容。默认逐文件 OCR，ocr --batch 仍需显式选择且关键语义一致。扫描件用本机 MinerU，外部 Zerox 需另有第三方传输授权。字段裁决留在 field-resolution.json，保留全部原件。
7. 写入前按现有状态执行。ledger reconcile 默认仅报告服务器差异，--apply 只推进可证明的本地断点，不补传、不 finalize、不新建替代任务。新案按当前上传授权使用原 V6 任务；多案共用一次认证，批次最多 10 案。既有正式案先对账，仅确有缺失时按 supplement --plan 的缺失补录契约执行。不要重新完整导入历史案。
8. 新完成案必须逐份取回正文并计算 SHA-256。verify 默认执行正文核验；用绑定文件身份、清单摘要和内容代际的 content-verification.json 续跑，只取未完成或变化文件。正文、正式目录、飞牛状态及无冲突结果全部满足后才归档。旧的 VERIFIED 不能自动升级为新版正文核验证据；保留历史完成，证据不足单列。
9. 先收口现有待核验案，再以 3 个尚未完成的不合格案完成正式端到端验收，通过后按每批最多 10 案继续。再次执行窗口扫描，已完成且无来源变化的案卷应零重复下载、识别、上传。日常只报变化、待办和异常；全量总账通过只读查询取得。

## 身份、授权和恢复

- 同一项目只有一个写执行单元；输入限本案待处理目录和工作区，不用兄弟项目或 staging 材料。样本批次 --acceptance-sample 为 SAMPLE_ONLY，不更新正式水位、不上传、不归档。最近已结案单案验收另读 [单案验收](references/playwright-single-case.md)。
- 不读取或保存浏览器密码、Cookie、令牌和配置。来源掉线先恢复已有受控标签；当前会话已授权账号自动登录时，沿用 LocalVault 标准输入入口自行登录、识别普通图形验证码并回读，不再要求用户手工登录。只有缺少必要登录授权或遇工具强制人工接管时才请用户处理。登记系统认证由 CLI 内部使用本机认证配置，不在输出、参数或日志展示凭据。
- 只读查询不触发上传、OCR、归档或更新水位。当前用户明确授权相关 Skill、系统修复和发布时，可在该范围完成实现、验证、发布及回读；不得把历史交接限制或岗位名称当作新的审批要求。
- 网络中断、超时和服务端状态未知时，先回读原任务；发送字节不等于服务器接收。终结后临时接收清单可能清空，须以正式案卷目录和文件归属核对，不能盲目补传。
- 保留目录、哈希、内容代际检查、容量限制和权限检查。整卷保留租约默认闲置 15 分钟、总期限 4 小时，准备轮询及顺序核验续期，成功释放；重启从原租约及正文回执续跑。到期先对账，再准备尚需取回内容。来源明确缺件时保留 materialGaps，材料采集不能标为完成；已登记部分可正文续核，缺件未清零不归档。
- 来源原地修改旧文书且没有近期文书活动，窗口扫描不能保证发现；收到明确线索时按项目定点核对。来源变化未处理完时保留 changePending，不能用本地处理时间或一次列表刷新消除此标记。
- Skill 修改只在受管源仓库完成，经测试、独立提交推送、cc-switch 同步预检与发布、安装副本及新进程发现核验。隔离测试通过、真实服务已发布、真实采集验收完成分别报告，不互相冒充。

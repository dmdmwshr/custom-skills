# 网站域名解析诊断与最小修复

核对日期：2026-10-06。官方依据：

- [FlClash v0.8.99](https://github.com/chen08209/FlClash/releases/tag/v0.8.99)：DNS 查询记录、DNS/NTP 按键覆写及设置重构。
- [DNS 页面实现](https://github.com/chen08209/FlClash/blob/v0.8.99/lib/views/config/dns.dart)：覆写项目、添加/移除、快速编辑及输入验证。
- [配置合并实现](https://github.com/chen08209/FlClash/blob/v0.8.99/lib/common/task.dart)：仅在 DNS 覆写启用或原始 DNS 未启用时合并选中键。
- [DNS 模型与合并函数](https://github.com/chen08209/FlClash/blob/v0.8.99/lib/models/clash_config.dart)：`nameserver-policy` 是整项替换，只有 `fallback-filter` 子键进行浅合并；快速编辑里的键集合成为实际覆写集合。
- [Mihomo DNS](https://wiki.metacubex.one/config/dns/)：策略优先级、节点解析、直连解析及解析连接的路由参数。

## 先分清三个地址问题

1. 网站域名解析：决定访问哪个网站地址。
2. 代理节点域名解析：决定如何先连上节点，可能使用 `proxy-server-nameserver` 及其独立策略。
3. 加密 DNS 服务域名解析：由启动解析器解析，不能依赖尚未连通的同一链路。

`nameserver-policy` 命中后优先于普通 nameserver/fallback；`direct-nameserver` 非空时还要检查是否跟随域名策略。`#组名` 可指定 DNS 连接出口，但应先确认节点启动解析不会形成循环。

## 排查顺序

1. 记录准确域名和当前时间；运行本机连接诊断及显式域名诊断。先看核心 A/AAAA 状态与候选规则，地址默认仅保留数量/指纹。
2. 用至少一个可信加密 DNS 或权威服务器查询同一域名。可与受控服务器的解析比对，但服务器缓存本身不等于权威记录。TTL、CDN、多地区地址可能合法不同，不能仅凭数量不同判污染。
3. 如果有可信目标地址，用原始 URL、原域名 SNI 和证书校验做 `--resolve` 对照。禁止 `-k`。只绑定本次请求，不改永久 hosts。
4. 同时检查服务器自身的健康响应与网站入口；内部入口要求的协议必须满足。网站正常且本机按可信地址成功、正常 DNS 失败，才把故障定位到本机解析路径。
5. 在偏好、当前档案源、数据库覆写和生成配置中追溯该域名的策略。不要输出整份 YAML/订阅/节点。

系统代理开启、TUN 开启、规则命中 DIRECT 可同时成立。显式 HTTP 代理探针最终也可能走 DIRECT；`--noproxy` 也可能仍受 TUN 接管。必须分开写证据。

## 配置修复

1. 用户已要求修复时，在范围内直接准备精确变更与可恢复备份。先检查既有覆写键，避免启用旧的整组默认值。
2. 全局 DNS 按键覆写适合明确需要跨档案生效的设置。0.8.99 的 `nameserver-policy` 会整项替换，所以必须保留无关域名项；但复制当前档案的整张策略表到全局，会让其他档案也继承这些策略及其中的组名引用。只修复一个档案时，优先用该档案的官方脚本覆写，逐域名合并原有策略；不把现有组名引用带入没有这些组的其他档案。检查更精确的旧键是否遮盖新增后缀键。
3. 仅保留已经验证正确且可达的解析通道；混入明文 DNS 可能让较快的错误回复继续胜出。加密只保护传输，仍需验证答案。最好用与核心一致的 DNS wire-format DoH 请求测试实际端点；同服务商另一个 JSON 查询接口返回正确，不能代替该端点的结果。不要仅添加一个正确解析器就宣称解决。
4. 源档案、全局 DNS 覆写、脚本覆写需选择一个合适持久入口，不能同时到处打补丁。不得直接改生成配置/运行中偏好/数据库。
5. 应用保存后先比较生成差异，再查询核心 DNS。只有证实旧缓存仍在时，才使用该版本公开支持的缓存清理；清缓存不等于重启，也不等于修复来源。
6. 测试实际 URL、页面静态资源和必要公开健康接口，并确认组选择、系统代理及 TUN 状态与任务范围一致。

## 可复用故障模式

2026-10-06 的一个受控站点：权威记录与服务器解析一致；Windows/核心均返回另一组地址；正常访问 TLS 断开，而保留原域名并绑定可信地址的同机请求通过证书校验且返回 200。该域名存在 DIRECT 规则，旧域名 DNS 策略同时包含 HTTPS 与明文解析器。

这证明访问故障在解析路径，并排除了当时“网站未部署成功”的解释；没有证明具体是哪一台中间设备注入错误答案，也没有证明切换代理出口导致了错误策略。Skill 不保存真实地址、订阅或节点信息。

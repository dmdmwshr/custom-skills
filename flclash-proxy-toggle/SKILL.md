# FlClash 配置与连接排故

执行端为 Windows。Linux/WSL 不运行 Windows 分支；远程服务器检查只在任务需要时单独核对目标主机。2026-10-06 已核对 Windows 安装版 0.8.99+2026100301、官方 v0.8.99 源码及本机只读诊断。源码证据、安装版本、实际核心状态和 UI 实测分别记录，不互相代替。

## 先判断目标与授权

- “查看、诊断、评估”只做只读检查；“修复网站访问、修改配置、切换某组”等授权覆盖明确范围内必要且可恢复的实现、验证和回读，不逐步骤重新确认。
- 暂停、退出、重启、结束进程、修改全机路由等会中断其他业务的新增动作，不能从一般配置维护推导。必要时一次说明精确对象、影响及恢复方法，再确认。优先通过应用正常保存/应用，不以杀进程代替应用配置。
- 用户当前指令优先于本 Skill 的流程建议。仅因工具暂未暴露，不宣称软件没有该能力；核对正式工具和同版本官方文档。
- 保护现有配置与运行态。修改前保留精确对象的可恢复副本，失败留在原断点，不清空配置、不刷新订阅、不批量测速来掩盖问题。
- 不输出订阅 URL、节点地址和端口组合、UUID、密码、令牌、控制器密钥或访问正文。密钥在本机内存中读取并直接用于回环请求，禁止写入命令参数、报告和仓库。

## 最短诊断路径

用已有可信 Python 3.11+ 解释器运行，不向系统 Python 安装依赖：

~~~powershell
<python> scripts/flclash_state.py --connectivity
~~~

该命令只检查本机文件元数据、系统代理、混合端口监听、回环控制器和汇总连接，不主动访问公网。输出区分安装版本、偏好中的 TUN、生成配置中的 TUN、核心当前 TUN；发生差异时以核心运行态说明当前行为，随后检查持久来源。

用户提供具体故障域名且授权诊断时，可主动查询一次：

~~~powershell
<python> scripts/flclash_state.py --connectivity --target-host example.com
~~~

--target-host 可能引发核心向外部 DNS 请求；它只输出 A/AAAA 地址数量、指纹、域名规则候选及同域名活跃连接的分类，不输出解析地址、节点或正文。查询成功不代表答案正确，仍须与可信加密解析或权威记录比对。没有活跃连接时写“实际路径未观察到”。

1. 先确认本机入口可用，避免把端口未监听误当服务器故障。
2. 对准确域名检查实际规则和连接。全局组选择 Meifu 不意味着该网站经过 Meifu，域名可能命中 DIRECT。候选域名规则不能替代实际连接证据，前面可能还有 IP、规则集或逻辑规则。
3. 查询核心 DNS；与权威/可信加密 DNS、服务器解析对比。只清理 Windows 缓存不能修复核心错误答案。
4. 保留域名、SNI 和证书校验，用可信地址做短时对照请求；恢复访问说明 DNS 是重要故障环节，不自动证明污染的具体来源。
5. 再检查网站服务或协议日志。按同对象、同时间窗对照，不因一次超时就修改服务器。

## 五层配置与正式修改入口

| 层级 | 内容 | 正式操作与验收 |
|---|---|---|
| 应用持久设置 | DNS/NTP 逐项覆写、端口、系统代理、TUN | 应用设置 UI；回读偏好中的开关与被选中的覆写键 |
| 档案与覆写 | Profile、附加规则、脚本、providers、自定义代理 | 档案/工具中的官方 UI；数据库只读确认来源和 schema |
| 原始配置 | 文件/订阅 YAML | 维护获授权的原始来源，经应用正式导入/编辑/应用；不把订阅缓存当永久事实源 |
| 生成配置 | 合并后的 config.yaml | 只读核验实际变化，不能直接编辑后宣称持久修复 |
| 核运行态 | 当前配置、规则、组选择、连接、DNS | UI 或已启用的回环控制器回读；文件变化不能证明核心加载 |

当前常见目录为 %APPDATA%\com.follow\clash，升级或换用户后先核对路径。数据库属于内部 Drift 实现；不直接写库完成日常维护，不修改运行中的 shared_preferences.json，不调用未公开 helper/service IPC。

## DNS 修改的关键约束

- 0.8.99 的 DNS 页按键覆写。仅打开“覆写 DNS”可能启用以前保留的多个默认键；先检查快速编辑/覆写项目，再启用并核对生成差异。
- 仅修复某域名时，保留其他域名策略以及 DNS 模式、监听、TUN、代理组选择。新版 nameserver-policy 的合并行为必须按同版本源码和实际生成结果确认。
- 域名策略命中后优先于普通 nameserver/fallback。混用明文与加密解析不能保证选中加密答案；真实错误答案也不是 Fake-IP。
- 网站解析、代理节点启动解析、DNS 服务器自身解析是不同路径。让解析经过某节点前，先确认节点域名的独立启动解析，避免循环依赖。
- 先验证解析，再验证带原域名和证书校验的 HTTPS，最后回读持久层/生成层/运行层。不要把固定 IP 写进永久 hosts 作为默认解决方案。

## 桌面操作

优先使用当前可用的原生桌面工具，限定到唯一 FlClash 窗口。最小化时只还原原窗口，不启动第二实例；工具返回“已聚焦”后仍要截图/可访问文本回读。

- 导航、打开设置、查看表单属于常规操作，无需另行确认；读取与写入动作分开。
- 按当前页面标题、控件文本、角色及截图定位，未标注图标不可凭旧坐标猜测。
- 需要持久修改时从官方 UI 保存/应用，随后核对精确变更与核心状态。
- UI 无法还原或输入被权限限制时，明确说明实际失败；请求用户完成必要的窗口动作，同时继续独立工作。不要伪造成功，不绕过权限写应用内部状态。

## 控制器与策略组

控制器须已启用且仅回环监听。诊断脚本禁用系统代理与重定向，防止认证头外泄。

- GET /configs、/version、/proxies、/rules、/connections 只读获取运行态；/dns/query 是可能向外部发出请求的 DNS 查询。
- 已授权切换组时，精确核对候选后用 PUT /proxies/{group}，回读组选择及必要的持久 selected_map。目标不存在不选相似名称。
- Mihomo 的核心 API 不等于 FlClash 桌面持久设置 API。不得用运行态 PATCH 或生成文件热加载冒充持久修复。
- Windows 入口已接收参数，不等于已有官方 Windows 管理 CLI。未文档化的参数、数据库、内部 IPC 均不能包装成“官方 CLI”。

## 探针与证据

- --noproxy 仅绕过命令自身代理；TUN 开启时不能称为物理直连。
- 显式连接本机 HTTP 代理只证明进入核心；最终出口仍由规则和选择链决定。
- 公网探针不带 Cookie 或账号；OKX 仅允许公开接口，不读取交易凭据。
- 禁用 TLS 校验的成功不证明证书有效。curl 的 ssl_verify_result=0 在未使用 -k/--insecure、退出码为 0 且 TLS 成功时才是该次校验成功的证据；它与某工具的 VERIFY=0 环境开关不是一回事。
- HTTP 403/400 可能证明到达应用层，但不证明登录态或应用整体健康。
- 服务器内部端口如要求 PROXY protocol，探针也须遵守该协议；缺少前导头的断开不能判定为服务故障。

## 完成标准与交付

说明已定位的故障层、具体修改、当前网站/网络验证结果，以及尚未核验的范围。配置修复应有持久层、生成层、运行层和实际请求四项证据；源文件、UI、核心不一致时继续定位，不能只凭“保存成功”收尾。

保留必要备份和脱敏回执。说明是否改变代理运行状态；无须在普通答复中机械输出冗长安全清单、内部 ID 或完整路径。技能维护按 cc-switch 完成源码测试、精确提交推送、受管同步、三方哈希与新进程发现验证，不直接编辑安装副本。

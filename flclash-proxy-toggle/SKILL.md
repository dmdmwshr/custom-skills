# FlClash 安全配置与代理控制

先确认用户要处理的是哪一层，再执行最小动作并回读。配置维护不等于允许改变代理运行状态。

执行配置诊断或变更前，完整读取 [references/configuration-layers.md](references/configuration-layers.md)。

用户报告“开启代理后无网络”、浏览器无法连接代理、节点延迟与实际访问不一致、协议或 CN2/Meifu 流量异常时，还必须完整读取 [references/connection-troubleshooting.md](references/connection-troubleshooting.md)。

任务涉及 Windows 桌面界面、按钮盘点或 UI 设置定位时，还必须完整读取 [references/windows-desktop-ui-map.md](references/windows-desktop-ui-map.md)。该参考记录的是版本化实测，不替代当前窗口截图与可访问文本。

## 最高优先级安全边界

1. 未经用户在当前任务中明确要求，绝不点击暂停/启动按钮，绝不关闭窗口、退出托盘、重启应用、结束 `FlClash`、`FlClashCore` 或 `FlClashHelperService` 进程。
2. “查看、核对、更新规则、切换节点、修改配置、测试网络”均不包含暂停、退出或重启授权。
3. 即使修改需要重新应用配置，也优先使用 FlClash 自身的保存、预览、应用或配置切换流程；不得用关闭应用或杀进程代替“应用配置”。
4. 用户说“关闭代理”时，只处理代理暂停，不自动退出应用。用户说“关闭应用”时，仍须先只读确认系统代理、TUN 与核心状态；无法安全确认就停止，不强制关闭。
5. 只有用户明确授权“结束进程”，且代理已安全暂停、系统代理/TUN 已解除、替代网络路径已验证时，才可讨论强制结束；普通维护永远不使用 `taskkill` 或 `Stop-Process`。
6. 状态不明时只读检查，不猜测、不连续点击、不尝试靠重启恢复。
7. 不输出订阅 URL、节点服务器、端口组合、账号、密码、UUID、密钥、Cookie、令牌、短 ID 或可复用代理凭据。
8. OKX 网络探针只允许公开 REST/WebSocket；不得读取交易凭据或触发账户、授权、下单操作。
9. 连接故障先核验 Windows 本机系统代理与混合端口监听，不能仅凭节点延迟、订阅条目数量或某个协议失败就修改服务器、刷新订阅、切换路由或重启核心。

## 五层配置模型

| 层级 | 含义 | 常见载体 | 维护原则 |
|---|---|---|---|
| 桌面应用持久设置 | 端口、TUN、系统代理、外部控制器等 UI 设置 | `shared_preferences.json` 及应用状态 | 以桌面 UI 为正式入口，不直接手改文件 |
| 配置档案与覆写 | 订阅档案元数据、标准/脚本/自定义覆写、附加规则、策略组选择 | `database.sqlite`、`scripts/` | 以“配置档案 → 覆写”UI 为正式入口 |
| 订阅或文件源 | 下载/导入的原始 Mihomo YAML | `profiles/*.yaml`、provider 缓存 | 订阅更新可能覆盖；不要把客户端覆写误写回源 |
| 运行时生成配置 | FlClash 合并上述输入后交给核心的有效 YAML | `config.yaml` | 只读核验；禁止当作长期事实源直接修改 |
| 核运行状态 | 当前策略组选择、连接、流量、规则命中 | FlClashCore 内存；可选 external controller | 文件变化不等于核心已加载，必须回读运行态 |

本机常见数据目录是 `%APPDATA%\com.follow\clash`，但必须以当前安装实际目录为准，不把该路径当作跨版本绝对契约。

## 工具顺序

1. 用户报告连接、超时、无网络或流量归属异常时，先运行只读诊断：

   ```powershell
   <项目或可信 Python 解释器> scripts/flclash_state.py --connectivity
   ```

   它只读取 Windows 本机代理设置、本机混合端口、回环 controller 的只读状态和已汇总的连接归属；不发起外网测速、不读取访问正文、不改变代理状态。

2. 其他配置检查先运行只读脚本：

   ```powershell
   <项目或可信 Python 3.11 解释器> scripts/flclash_state.py
   ```

3. 需要看桌面界面时，先限定到 FlClash 窗口，读取截图与无障碍树；按“页面标题 + 控件文本 + 控件角色”唯一确认，不按旧截图坐标盲点。
4. 需要持久修改时，优先使用 FlClash UI。
5. 已明确启用 external controller 且只需要运行态策略组操作时，可使用本机 Mihomo HTTP API。
6. `database.sqlite` 只用于只读审计；直接写库仅限用户明确批准的恢复性维护窗口。
7. 不使用浏览器自动化，不把内部 helper/service IPC 当作公开 CLI。

只读脚本不得写文件、调用控制器写接口、点击 UI、停止进程或改变系统代理。

## TLS 与公网探针证据边界

涉及证书、HTTPS、ChatGPT/网页报错或“代理是否劫持”时，先读取 connection-troubleshooting.md 中的 TLS 五层和探针分离规则。不要把本机 connectivity 结果、公网探针结果和浏览器表现合并为一个“网络正常/异常”结论。

TLS 证据按五层分别记录：客户端到本机 FlClash 监听、FlClash 到所选出口节点、出口到目标的 TLS/SNI、代理或安全软件的 MITM 重签与信任链、浏览器对最终证书及应用层响应的处理。具体协议可能不经过全部层；缺少某层证据时写“尚不能确认”。

HTTP 403 通常只是未认证探针的应用层响应，不能证明证书、登录态或 Codex 会话健康；VERIFY=0 关闭了证书校验，不能证明证书有效；浏览器证书告警只说明该浏览器路径的信任失败，不能反推代理节点或其他客户端必然失败。三者必须分别保存目标、时间、IP 家族、是否经代理和校验设置，并禁止互相充当证据。

## 桌面界面语义

桌面布局会随版本和窗口宽度变化，按中文语义识别，不依赖固定坐标：

- `仪表盘`：运行状态、流量与网络检测；用于观察，不是配置事实源。
- `代理`：策略组与当前节点；节点切换属于运行态动作，FlClash 会把选择写回当前档案。
- `配置`：订阅/文件档案管理。这里的“配置”是 Profile（配置档案），不等同于磁盘上的生成文件 `config.yaml`。
- 配置档案详情中的 `覆写`：官方源码支持 `标准`、`脚本`、`自定义` 三种模式；规则和策略组持久调整从这里进入。
- `请求`、`连接`、`工具`：运行观测和辅助功能；窄窗口下可能收入“更多”。
- 应用设置中的 `常规`：端口、外部控制器等客户端补丁设置；具体分组名称以当前版本可访问文本为准。

图标无稳定标签、页面与说明不一致或目标项不可唯一识别时，停止并报告，不尝试相邻按钮。

## 桌面 UI 只读盘点协议

1. 盘点前运行 `scripts/flclash_state.py`，至少记录进程、Windows 系统代理、应用偏好中的系统代理/TUN，以及生成配置中的 TUN；这些字段组成运行态哨兵。
2. 只读盘点只允许已确认的主导航、返回、搜索、滚动和窗口尺寸调整。打开页面不等于允许点击页面内的开关、单选项、配置卡片、节点卡片、测速、刷新、重置、添加、清空或关闭连接按钮。
3. 每次输入前重新聚焦 FlClash，先用可访问文本定位；若只能看到无标签图标，保留截图并标记“未唯一识别”，不得猜坐标。
4. `请求`、`连接`、`代理`、`配置`、按需运行等页面可能暴露域名、IP、进程、SSID、节点标签或订阅信息。截图只用于临时核验，不提交到 skill 仓库；文档只保留脱敏后的界面能力。
5. 延迟测试、网络检测、订阅刷新虽不一定改配置，但会产生网络请求或重新加载运行态，盘点任务默认不执行。
6. 页面盘点结束后回到原页面，再运行一次只读脚本并逐项比较运行态哨兵。只有前后值一致，才能报告“代理状态未改变”。
7. 当前版本实测按钮地图、风险等级与未实测边界见 `references/windows-desktop-ui-map.md`；版本变化时按当前 UI 重新核验并更新日期，不沿用坐标。

## 操作授权矩阵

| 动作 | 默认权限 | 必要条件 |
|---|---|---|
| 只读状态、文件元数据、数据库表/数量、公开网络探针 | 允许 | 全程脱敏且不改变状态 |
| 本机连接与流量归属排故 | 允许 | 仅使用 `--connectivity`、回环 controller 和只读路由检查；不触发外网测速、不关闭连接 |
| 切换现有策略组节点 | 仅用户明确指定时 | 精确组名与目标存在，切换后回读 |
| 修改桌面设置或 Profile 覆写 | 仅用户明确指定时 | 先定位层级，备份/预览，UI 保存后验证 |
| external controller 写请求 | 仅用户明确指定运行态动作时 | 仅回环监听，认证按当前配置，精确组名 |
| 直接写 `database.sqlite` | 默认禁止 | 恢复性场景、精确对象、用户明确批准、可恢复备份、维护窗口 |
| 编辑 `config.yaml` 或 `shared_preferences.json` | 禁止作为正式配置路径 | 只能只读诊断 |
| 暂停、恢复、退出、重启、结束进程 | 分别单独授权 | 不得由其他配置任务推导 |

## 工作流

### 只读核验配置层

1. 运行 `scripts/flclash_state.py`。
2. 核对进程存在性、生成配置/数据库/偏好/源档案的存在与时间、数据库 schema/表计数、TUN/系统代理元数据、external controller 元数据。
3. 如需核对规则来源，只查询数据库表结构和精确目标的脱敏字段；禁止整表导出 `profiles.url` 或原始 YAML 节点。
4. 报告“哪个层保存、哪个层生成、哪个层正在运行”，不要笼统说“配置文件”。

### 连接、超时与无网络排故

1. 完整读取 `references/connection-troubleshooting.md`，先执行 `scripts/flclash_state.py --connectivity`；未通过本机混合端口门槛前，不检查或修改服务器。
2. 先按诊断结果区分本机代理端口不监听、系统代理端口不匹配、端口被其他进程占用、当前分流未命中 CN2、TUN 默认路由异常和可能的 UDP/QUIC 受限；不能把这些情形笼统归因于“节点堵塞”。
3. 本机代理端口与运行态分流均正常后，才在用户提供的准确时间范围内对照服务器脱敏握手日志；比较 WS/gRPC、Reality 和 Hysteria2 的协议层表现，不记录认证信息或访问正文。
4. 当前用户已在当前请求中明确列出的节点选择、系统代理、TUN、Windows 路由、订阅刷新、核心重启或服务器配置修复可直接执行；诊断后新增的高影响动作，应一次性汇总精确对象、影响和恢复方式，必要时最多确认一次，确认后不逐项重复询问。诊断本身不包含未授权的修复动作。
5. 报告时先给出故障层级和证据，再给出最小的下一步；CN2 无流量必须同时说明上层分流选择，不能只看 CN2 组内的节点选择。

### 切换策略组

1. 明确 `组名 -> 目标节点`。
2. 只读确认目标组和目标候选存在。
3. 若 external controller 已由用户启用且仅监听回环，可使用：
   - `GET /proxies` 读取当前组；
   - `PUT /proxies/{group}` 精确切换。
4. 控制器不可用时走桌面 `代理` 页面。
5. 回读当前选择，并按用户任务运行短探针。
6. 不暂停、不重启、不关闭应用。目标不存在时停止，不选近似名称。

### 修改持久规则或设置

1. 先判定它属于应用常规设置、Profile 标准覆写、脚本覆写还是自定义覆写。
2. 记录修改前脱敏摘要；优先使用应用内备份或配置预览。
3. 在 UI 精确修改并保存；离开覆写页后按当前版本的自动应用/应用反馈回读。
4. 同时核对数据库持久状态、生成 `config.yaml` 和核心运行态三者是否一致。
5. 若只有生成文件改变、数据库/UI 未改变，判定为非持久修改，不报告完成。
6. 全程保持代理运行状态不变，除非用户另行明确要求对应开关动作。

### 数据库恢复性维护

1. 先说明 `database.sqlite` 是 FlClash 内部 Drift 数据库，不是稳定公共管理 API，schema 会迁移。
2. 用户必须明确批准精确修复对象；普通增删规则不进入此流程。
3. 若 FlClash 仍在运行且无法证明并发写安全，停止数据库写入方案，改走 UI；不得为了写库自行关闭代理。
4. 在安全维护窗口使用 SQLite 一致性备份，不直接复制可能处于 WAL 写入中的单文件。
5. 只执行带唯一键/精确条件的事务，记录修改前后行数与完整性检查；不得通配删除。
6. 由 FlClash UI 重新加载/应用并回读。若用户不允许维护窗口，保留诊断结论，不强行修复。

### 暂停、恢复与关闭

- 只有用户明确说“暂停代理”才点击暂停，并至少用两项证据回读。
- 只有用户明确说“恢复代理”且当前确为暂停态才恢复；运行中不重复点击。
- “关闭应用”与“暂停代理”是两个动作，不能合并授权。
- 配置任务完成后保持原运行状态，不做“顺手重启”。

## 数据库、API 与 CLI 结论

- 有数据库：当前官方源码使用 Drift/SQLite，保存 Profiles、Scripts、Rules、ProfileRuleLinks、ProxyGroups 与 IconRecords 等应用数据。它是内部持久层，不是官方稳定 CLI。
- 有运行时 API：启用 external controller 后可使用 Mihomo 兼容 HTTP API读取状态和切换策略组；它不等于 FlClash 桌面持久配置 API。
- 没有已公开的 Windows 管理 CLI：官方 README 只列出 Android 的 START/STOP/TOGGLE 动作，Windows `main()` 不接收命令行参数。不得把 `FlClash.exe`、helper service 或数据库写脚本包装成“官方 CLI”。
- UI 是正式持久配置入口；`config.yaml` 是生成结果；核心回读才是运行事实。

## 输出格式

按以下顺序简洁报告：

1. `故障定位`：先说明本机、分流、协议、路由或服务器中的已证实层级；证据不足时明确写“尚不能确认”。
2. `运行状态`：只读判断及证据。
3. `配置层`：本次检查或修改属于哪一层。
4. `执行动作`：精确说明；没有动作就写“未修改”。
5. `一致性`：UI/数据库/生成配置/核心中已核对哪些。
6. `安全确认`：明确写“未暂停、未退出、未结束 FlClash 进程”，或如实写出用户授权的对应动作。
7. `敏感信息`：只说明已脱敏，不输出值。

# 每次浏览器执行的结束职责

本规则管理一次完整执行的生命周期。会话是实际 Codex 身份，项目是长期归属，本次执行是新建的物理连接、原生组和页面；会话继续存在不意味着浏览器组需要继续存在。

## 必须检查的对象

| 现场事实 | 分类与职责 |
| --- | --- |
| 本次精确组、连接和页面成员一致 | 本次在用；业务完成后按正常流程清理 |
| 其他当前连接，原生组、成员及同一浏览器实例的登记一致 | 其他项目在用，报告并保留 |
| 当前连接存在，登记不足或成员变化 | 活动但归属待核实，不按标题认领 |
| 无连接的原生组或控制页 | 待对账对象；没有原执行证据不能自动删除 |
| 同一浏览器实例中，历史已登记的精确页仍存在 | 历史页面残留；沿原执行和保护规则处理 |
| 保存记录存在，没有当前原生执行绑定 | 保存历史或同步记录；本地标记缺失不能证明关闭 |
| 没有自动化连接或历史精确绑定的普通未分组页 | 用户普通页面，不作为自动化残留 |
| 主机、资料或浏览器进程实例变化 | 原 ID 只保留历史；先建立新鲜身份，不沿用旧归属 |

浏览器实例包括进程启动身份，避免重启后原生整数 ID 被再次使用。项目登记只提供归属线索；组标题、网址相同、保存记录的本地标记以及空 CLI 清单都不能单独证明运行或删除。

## 收尾与回读

1. 在释放连接前获取原生组、页、连接快照，结合资料级执行登记和只读保存记录，形成 `BrowserEndAuditV1`。仅记录页面站点来源、原生 ID 和连接状态，不记录完整查询地址、令牌、Cookie、正文或网站存储。
2. 处理当前精确自有范围，保留未知动作、未完成输入、下载及对话框。解除原生分组后核实保存记录移除，关闭精确自有页及辅助页，释放本次连接。
3. 回读保存记录和连接释放。最后辅助页若只有“已请求关闭”，继续记为 `cleanup_pending`，明确缺少物理关闭证据。
4. 在同一浏览器实例内，用下一轮新鲜原生查询或范围已验证的独立只读清单补证。只有原真实会话、原执行、已知清理以及精确组、页和保存记录都对上时，才能将其结清为 `completed`。他会话和未知业务不自动结清。
5. 最终交付说明本次组和页是否移除、普通页及其他活动项目是否保留、之前残留的分类及未决项。审计历史留在仓库外，不恢复为工作页面。

Windows `connect`、`audit` 和 `finish` 进行原生巡检，执行登记位于受管 runtime 的资料级 registry；`audit` 在未知状态下只读取，不解除未知状态。WSL 的 `attach`、`inventory`、`tab-list`、`finish`、`detach` 由共同控制层执行同一巡检，状态及资料级 registry 留在其受管状态目录。已经完成的幂等结束回执会明确标为历史回执，不伪称本轮重新扫描。

## 主动验证样例

一次新执行创建自有页，打开用户要求的 X 首页。只核对实际页面地址、标题、页面可见及界面就绪，不发帖、关注、点赞或读取时间线正文；首页加载成功和账号操作能力分别说明。

在授权的隔离测试中同时保留第二个自有测试连接，核对两组可分别识别，结束第一组后以第二组补证其精确页已消失。第二组也必须正常结束；可用的独立清单补证最后辅助页，避免观察组自身继续产生残留。普通页精确身份前后一致，历史保存记录单独计数。

测试代码使用浏览器侧 `evaluate` 读取站点和路径；不能假定官方 run-code 外层具有 `URL` 等浏览器全局对象。失败的只读探针也保留原回执；仅在原源码、无副作用、实际身份和新鲜只读回读全部核对后，进行当前失败的窄对账，不把未知业务错误套成无副作用。

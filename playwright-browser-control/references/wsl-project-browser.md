# WSL 项目浏览器控制

适用已发布 ProjectBrowserV2 的 WSL 主机。先按全局主机索引读取 browser-control.md 顶部，核对当前部署、项目登记、账号范围及真实执行者；路径、Node/MCP版本、显示和profile只读取本机部署配置，不照搬Windows或别的机器。

本机唯一契约为 `/srv/workspaces/codex-host/docs/project-browser-v2.md`，统一入口 `/usr/local/libexec/codex-host/shared_playwright.py --project <登记项目>`。若路径已迁移，以本机索引为准。不在Skill复制实现或另建连接管理脚本。

- 一项目一个受管常驻MCP连接/原生组，名称 `Playwright · <真实电脑名称> · WSL/<实际发行版> · <正式项目名称>`；同电脑 Windows 分组写 `Windows`。共同控制层在原连接内核对唯一连接与原生组后规范标题，返回 `BrowserGroupIdentityV1` 溯源字段；MCP客户端登记名、项目身份和原生组ID保持独立，不为改名重建业务连接。旧组在正常可写接续时按同一原生身份改名；只读核验与故障对账不改标题，旧规范标题可暂待迁移，任意其他标题漂移仍按现行归属规则处理。每组可有多页，各项目竞争同一主机进程锁。CLI过渡项目依登记继续原后端，迁移先结束旧连接。所有接入ProjectBrowserV2的项目共用进入、页面集合变化及退出时的归属核对与清理；业务只声明用途、留存和完成情况，由共同控制层执行，不通过多建连接或原生组绕过遗留页。
- 原生页面、连接和保存组分别验收。共同控制层回执包含来源字段，不以页面空或finish成功声称Google保存组已删除。同步显示的外端组和关闭后仅剩保存记录的旧组，不按Playwright前缀批量处理；受管接口未核实保存记录时明确报告待核实。Windows临时页收尾流程不能覆盖WSL经实际复用证明的业务留存规则。
- 在登记根以当前真实任务身份启动入口，保持同一入口处理本段请求，先 `attach`，用 `page-ensure` 按用途复用或创建页面；不要绕开入口直接连接官方服务。
- 入口是逐行协议：先独立消费首行 `ready` 握手，随后才把每条请求对应到其业务回执；不能将 ready 当首条 inventory/attach 结果而使后续响应错位。Node REPL 启动子进程时显式传递当前工具提供的真实任务元数据（含 thread ID），不假定父进程环境已含身份；不能使用历史或其他任务ID。进程退出/启动失败应有界返回退出码与脱敏错误，让等待中的调用结束；先核对是否已发送请求，再区分本地启动失败与未知效果，不能无限等待或重放。 重建 Node REPL 子进程适配器时，将进程、队列、等待器与回调放入同一个稳定对象，避免旧闭包继续等待旧队列；等待超时先回读原队列和受管 pending，已返回的 ready/完成回执只消费一次。
- 页面按用途reuseKey取得，旧tabId/UUID不是永久前置。已关闭或浏览器实例改变时接受新身份；目标URL变化使用契约的keep/navigate/new策略和可行动回执。替换必须先建新再清旧，防最后页关闭导致扩展断连。契约2.1.4起，成功受管操作后的正常导航由共同控制层按真实原生页面身份刷新完整URL指纹；无匹配身份则为null，不能用请求目标URL补造或沿用旧指纹。
- 只有实际下一轮会复用、且经过跨次同页核验的页面才登记 `page-retain`；用户明确交付页使用user留存。下次会新开的页面，本轮完成后应 `page-release`。
- 正常结束显式 `finish` 并读回 closed/retained/protected/unknown，再关闭入口。EOF自动收尾不能代替项目验收。
- 兼容run-code中直接创建的页面必须在项目确认操作/下载完成后显式释放；优先使用页面接口，使下载、输入保护在操作前已建立。
- 组外遗留页只按原生页面身份、浏览器实例及最新受管完整URL指纹回收。正常受管导航使用已刷新指纹；未解释或外部导航导致与最新受管指纹不符时保留待核实，不将所有导航变化一概视为无法清理。他项目、个人、真实未提交表单、未完成下载或未知页仍保留。不用标题/URL相同作为删除证据。
- 扩展 Welcome 可在异常连接后落到原生组外，不能只查当前 context 就声称清理完成；使用现行契约的精确连接页回收与原生 tabId 回读。CLI通用客户端名不能单独证明项目归属，先核对退役和连接占用。
- 已发布契约2.1.1起，`inventory` 的 `output.managed.retiredPages` 列出由本项目完整退役档案确证的历史页。当前context空不等于历史组为空；未解项应进入 protected/cleanupPending。授权清理时调用 `reconcile-pages`，仅在同浏览器、原生tabId/完整URL指纹、原组或未分组及无其他连接占用全部吻合后恢复归组并回读。相同组名/URL不是认领证据；归组后按返回身份核实用途完成，再 `page-release completed=true` 或有明确下次用途时 `page-retain`，仍保护输入、下载、对话框和未知状态。旧档案完成项由入口持久记录，不删审计或重放旧请求。源码测试与真实历史页清理分别验收。
- 契约2.1.3支持浏览器重启后新tab/group的 `restoredPageCandidates`：候选只证明待对账，不继承旧页面身份。当前context及 retiredPages 为空仍须查看这些候选；用户已授权清理时，按唯一契约用新鲜受管原生回读和历史用途证据生成受保护审计，再 `page-adopt-for-cleanup` 取得新的临时身份，最后正常释放。不得按相同URL/组名直接删除、批量迁移旧组或声称旧ID连续。
- 用户本轮精确指定的组外页可按唯一契约的root保护审计走 `user_selected_exact_page` 清理：记录本轮选择依据、新鲜tab/group/完整URL指纹及真实执行者，明确historicalContinuity=false。认领仅创建临时清理身份，仍须正常release与输入/下载保护；不扩大为按站点或相同URL批量删除个人页、他项目页，也不伪称历史归属。
- 飞书精确Slate编辑器的非编辑placeholder/纯零宽展示节点可由已发布控制层在克隆DOM中排除，避免空编辑器被误报未提交；真实草稿、mention、附件及不匹配结构仍保护。项目不能改真实DOM、清空草稿或绕过输入保护来完成清理。
- 空页收尾应采用统一入口的已验证空状态，避免最后页释放后再调用页面工具触发重连；首次项目启动的临时目录也由全局后台创建及校验，项目不另写初始化流程。
- 页面关闭返回可能早于close事件；等待关闭事件或回读，不能立即把isClosed=false判为失败。MCP工具名称通过实际tools/list核对，不因版本改名断言能力缺失。
- 不假定 `run-code` 外层执行环境具有浏览器全部全局对象；本机已出现 `URL is not defined`。仅需识别站点/路径时，可在 Playwright 侧去掉查询参数后返回地址，在业务进程解析。终结 ReferenceError 或点击可点击性等待失败仍核对原回执；当地契约仅支持经原源码与代码哈希审计的窄只读对账，不能从错误名推定所有前置动作都未发生。
- iframe 的 Playwright frame name 可能来自 HTML id，不等于存在同名 `name` 属性；先按实际 frame 或 DOM 元数据定位。对尚未证实存在的选择器，先 `count`/`evaluateAll`，不要直接等待单元素 `evaluate`。动态面板刷新后应等数值字段加载完成；只有标题已出现不能证明数据就绪，加载超时保留旧业务值。
- 固定任务和Node REPL的子进程可能没有桌面user-bus环境；由全局入口按实际UID核验并补齐，不在项目硬编码。服务管理查询失败不能当作连接关闭；开发shell验收不能代替固定任务真实入口验收。
- 浏览器缺失只恢复已核实的原授权profile和显示，MCP显式绑定同一资料；不拿未登录新资料或历史隐藏实例代替。隔离新资料启动不能当业务登录验证，也不要弹出未登录测试窗干扰用户。原浏览器和项目MCP分属独立服务，项目结束不停止共享浏览器。
- 连接断开或超时先检查精确请求回执；服务退出不自动代表网页请求未执行。known空闲可以受管接续，unknown不重放、不靠重启清除。若精确MCP子进程已退出或僵尸、原请求仅为受支持的观察/导航，当地入口可按原请求/代次/浏览器身份保存未知审计并退役死连接，再新鲜接续；活子进程、点击/发送或身份漂移不能套用。父服务active不是子进程存活证明；退出码和脱敏fatal类别分开记录，SIGABRT本身不能证明OOM。

- 明确终结的MCP工具错误不等于超时，也不等于动作没有发生。对`check/uncheck`返回“checkbox未变更”的已支持情形，使用当地受管`reconcile-tool-error`按精确原request/page/generation只读核验；原结果记工具失败、effects未证实、禁止重放，不为清理再次勾选/取消。已知中止导航仅按当地窄配方只读核验，不泛化到任意点击/下载/发送。持久recoveryFence期间只允许受管状态读取；中断按同原请求恢复，不手删pending/latch、不靠重启解除。检查值只反映当前观察，不证明原动作成功。
- 当地契约另有首操作点击等待超时的窄结算：只有原产品调用的首个异步操作就是精确文本定位点击、MCP终结回执的调用日志仅显示同一定位器等待、root审计绑定原请求与页面身份时，才能按唯一契约以 `reconcile-tool-error` 做只读页面集合回读。结算仍保留原效果未证实、禁止重放。其他点击错误、传输超时、前置副作用或页面身份变化不适用；以本机已安装契约和原终结回执为准。
- 已提交条款checkbox仍与DOM默认值不同，可能继续触发未提交输入保护。先由业务核验提交回执、文件完成/归档或入库证据；当地契约支持时，使用`page-release`的`submittedForm`精确完成声明，附原生页身份/URL指纹、checkbox状态和原证据文件哈希。统一入口持久记录且复核没有其他脏输入、下载、对话框或用户保留，再执行一次正常关闭；不修改DOM默认值、不重放提交、不添加长期保护豁免。证据不足、状态变化或关闭未知仍保留并对账。普通completed标志不能证明表单已提交，业务成功与页面清理分开回读。

已验证：两项目原生分组/互斥/页面隔离、独立调用同页复用、正常服务重启后的原生同页恢复、自有组外页恢复、临时页清理与未提交输入保护。业务站点登录、下载归档、主机整机重启和各项目正式适配分别验收，不由上述测试推断。

全局规则和主机契约由统一维护任务发布；业务项目仅声明用途、保留需求和实际完成证据，并将同一版本同步到开发入口、运维说明与固定任务。

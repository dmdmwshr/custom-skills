# pyweixin 原生界面自动化

本机已安装 Hello-Mr-Crab/pywechat 的 `pyweixin` 模块，发行包名是 `pywechat127`，适配微信 4.x；不要安装 PyPI 上同名的其他 `pyweixin` 包。源码和运行环境独立保存在工具目录，Skill 不携带第二份库代码。

## 本机入口

- 固定运行环境：`D:\Program_Files\pyweixin\.venv\Scripts\python.exe`。
- 上游源码：`D:\Program_Files\pyweixin\upstream`，安装版本和提交见工具目录的 `installation.json`。
- 只读自检：用固定解释器运行 `scripts/status.py`；它检查库版本、微信运行/登录状态及界面可见性，不打开、切换或修改微信。
- API 文档：按需要阅读 [能力与上游 API](references/capabilities.md)。实际调用使用已安装模块，不向系统 Python 安装依赖，不用 Skill 内的旧源码覆盖运行环境。

## 能力和路由

| 任务 | 入口与边界 |
| --- | --- |
| 状态、安装路径、微信版本、数据目录查询 | `Tools`；自检只输出必要状态 |
| 打开微信内部窗口、定位聊天及附件界面 | `Navigator`；部分上游方法会调整窗口位置，调用前核对实际实现并保留原窗口状态 |
| 当前界面消息读取 | `Messages.pull_messages`；读取完整历史才使用滚动方法 |
| 消息监听 | `Monitor`；监听返回内容不自动构成发送或保存授权 |
| 普通文件、图片、视频补下载 | 当前项目的补下载入口；只触发微信本身下载，完成必须同时有实际本地文件证据 |
| 聊天、文件和媒体导出 | `Messages` / `Files`；这些方法会另存副本，仅用于用户要求导出的任务 |
| 发送消息或文件、好友操作、朋友圈操作 | 上游对应类；必须有用户对目标和动作的明确授权，不能用这些操作测试下载功能 |
| 微信设置 | `Settings`；先读现状，仅修改用户已授权的字段 |

`wx-cli` 适合读取本地数据库，但不能替代客户端拉取尚未下载的附件。已经在当前任务取得的数据直接复用，避免为了生成报告再次滚动微信。

## 界面操作

先确认 Windows 主机、显示器布局、唯一微信窗口、登录账号和 UI 树可见性，再执行当前已授权动作。有可用副屏时优先在副屏操作，保存窗口原位置并在结束后恢复；副屏仍需要正确前台和输入焦点。当前账号不暴露 UI 树时报告限制，保留断点；不修改微信内存、注入模块或切换账号来强行使它可见。

每次鼠标、键盘或菜单动作前确认前台及目标控件仍属该微信窗口。一次操作后回读实际界面；焦点转移、布局变化、异常或结果未知时停止该动作，不重复未知点击。保留用户窗口、输入草稿及其他程序；只关闭本次精确创建的临时窗口。

普通文件仅在确认“未下载”时触发下载，已经存在的文件不要点击打开。图片、视频使用微信预览窗口下载，完成后按微信原生缓存核验；截图、缩略图、复制路径和点击成功均不能证明原附件完整。

## 当前补下载项目

项目：`C:\Users\12070\Desktop\项目开发\微信消息自动拉取备份`。

读取项目 `AGENTS.md`、配置和 `docs/WINDOWS_TASK_CATALOG.md`，使用项目 `.venv` 与既有入口。范围是普通文件、图片和视频，每天 22:00；附件只保留在微信原生目录，进度保存在忽略的 `runtime/`。不调用 `save_chatfiles`、`export_videos`、`save_media` 来完成补下载，它们会导出或另存附件。

计划任务负责触发一次运行，脚本不常驻定时；运行失败保存真实断点，下次计划运行按实际文件状态续查。当前一次运行里遇到未知界面动作不盲目重试。扫描范围由项目配置和当前电脑已有消息决定；不把创建定时任务、单类附件测试通过或客户端点击成功说成全类型完整验收。

# 项目唯一交接文档与冻结启动包

每个项目只维护一份活动交接文档。项目规则已指定路径时遵循精确路径；未指定时使用项目根目录的 `PROJECT_HANDOFF.md`。Git 项目以仓库中的唯一相对路径和提交历史为事实源；不同 worktree 只物化同一路径，不得另起名称或形成并行事实源。每次接力原地更新这个相对路径，不创建日期版或任务版副本。

交接文档只保存恢复开发所需的当前事实，不承担路线图、需求池或第二份计划的职责。通常控制在约 3,000 个中文字符内；复杂项目引用项目事实源，不复制完整聊天、长日志、凭据或运行数据库。

## 项目内唯一交接文档模板

~~~markdown
# 项目交接

> 唯一活动交接文档。后续任务必须更新本文件，不得创建等价副本。

## 交接元数据

- 更新时间与时区：
- 事实核验范围：
- 当前阶段：

## 项目身份

- 项目名称与保存项目：
- 当前目录与 Git 分支：
- 仓库根与项目内唯一交接文件相对路径：
- 项目长期目标：
- 当前阶段：

## 当前有效规则

- 全局规则：只写与本项目直接相关的约束。
- 项目规则：列出 `AGENTS.md`、唯一计划或契约文件。
- 安全与权限边界：写清不可自动扩大的动作。

## 已完成与证据

- 已完成事项：
- 变更文件或提交：
- 已运行验证及结果：
- 当前服务、端口或后台任务：

每项标明“当前回读确认”“历史证据”或“尚待验证”。不要把计划写成已完成。

## 当前工作区

- 已修改未提交：
- 新增未跟踪：
- 敏感/运行态排除：`.env`、凭据、Cookie、令牌、私钥、数据库、日志、缓存、虚拟环境、浏览器资料、下载/上传/输出/构建产物等不得暂存。
- 未知归属：无法证明属于本次任务的路径标记 `HANDOFF_BLOCKED`，不猜测、不批量加入。
- 与用户既有改动重叠处：
- 不得清理或覆盖的内容：

## 未完成工作

- 待办与优先级：
- 阻塞或待用户决定：
- 已尝试但失败的方案：
- 建议下一步：

## 禁止动作与外部门禁

- 未获当前授权不得执行：
- 外部依赖或证据阻断：
- 不得被工程进度掩盖的结论：

## 后继任务启动指令

- 首先读取适用规则、项目计划和当前 Git 状态。
- 对照本交接包报告差异；易变化状态必须重新验证。
- 只读初始化时不修改项目或运行态。
- 发现项目、目录、分支、HEAD、交接文件或文件哈希漂移时报告 `HANDOFF_BLOCKED`，不得自动修本文档。

## 文档维护规则

- 下次接力只更新本文件。
- 本文件不是项目计划；待办状态以项目唯一计划或实际运行证据为准。
- 易变化事实必须重新核验，无法核验时明确标为“尚待验证”。
- 不写入凭据、令牌、Cookie、`.env` 内容、私有会话标识或长日志。
- Git 项目必须使本文件被跟踪并进入最终逻辑提交；最终 HEAD、分支、主机、工作目录、文件路径和精确 SHA-256 写入外部运行回执，不回写本文件，避免自引用。
~~~

## 后继任务精简启动包

创建任务的初始提示只传下面这些定位信息，不重复粘贴整份项目交接文档：

~~~text
这是 <项目名称> 的后继开发任务。

先完整读取适用的 AGENTS.md、<唯一交接文档项目内路径>、项目唯一计划、README 和架构说明，再只读回读实际 Git worktree 注册、项目/主机/目录、分支、HEAD、交接文件精确 SHA-256 和任务标题。交接冻结于 <时间与时区>；规范化指纹仅作辅助，精确哈希必须一致。

起点：从已提交的 <分支或精确 ref> 建立工作树，不依赖原工作树未跟踪文件传播。
首项任务：<用户明确任务；没有则写“只读初始化，等待用户下达任务”>。

对账令牌：<短令牌>；仅用于项目、主机、时间窗口对账，不创建第二个任务。
关闭目标：源任务完整 threadId=<源任务 ID>，host=<源主机>，原标题=<源标题>；只用于门禁通过后的精确改名和归档，不写入项目文件、普通日志或最终用户回执。
固定边界：<只保留会影响本次启动的权限、安全和运行态边界>。
发现任何漂移时只报告 HANDOFF_BLOCKED，不修改交接文档、不提交、不创建第二个后继任务。
~~~

## Git 冻结前检查

1. 读取项目规则、唯一计划和本文件，锁定仓库根与唯一相对路径。
2. 用 `git status --porcelain=v1 --untracked-files=all` 盘点所有变更。把路径分为“本次明确预期”“敏感/运行态排除”和“未知归属”；第三类直接 `HANDOFF_BLOCKED`。
3. 只验证和修正明确归属且预期的源码、测试、文档或配置。不要以“历史改动全部提交”为理由加入凭据、运行态、二进制产物或无关文件；删除也必须属于明确预期。
4. 用户当前明确要求项目任务接力时，该请求授权将明确归属的预期源码和唯一交接文档按职责做逻辑提交，并在已有远端和明确分支均可验证时推送；更严格的项目规则优先。运行相应测试和 `git diff --cached --check`。这不授权未知归属、敏感/运行态文件、创建远端、强推、部署、服务操作或项目外动作。
5. 已有远端时只推送既有远端和明确分支，不强推、不创建替代远端；回读 upstream，确认没有未推送的本地提交或远端领先未整合提交。没有可验证远端时记录边界并按授权处理。
6. 最终提交完成后运行：

   `python scripts/validate_handoff_state.py --repo <repo> --file <handoff-relative-path> --expected-branch <branch> --head <full-head> --sha256 <exact-sha256> --require-clean`

   该验证器的精确字节 SHA-256 是正式门禁；CRLF/LF 规范化指纹只用于诊断，不能代替精确哈希。把 project、host、cwd、branch、最终 HEAD、交接文件相对路径、精确 SHA-256、规范化辅助指纹和时间写入外部运行回执，不能回写交接文件。

## 后继任务验证与关闭

- `clientThreadId` 只表示异步准备中的队列令牌，绝不能传给读取、发送、改名或归档接口。初始标题加入 `H<令牌前8位>`；在有界时间窗口内查询既有任务，并用标题令牌、保存项目和主机共同对账。零个或多个候选都阻断，绝不第二次创建。
- 取得真实 `threadId` 后，把后继任务标题规范化为 `<项目>｜<当前阶段或首项任务>` 并回读；标题设置或回读失败即阻断。
- 只有拿到真实 `threadId` 后，才读取后继初始化结果。必须确认实际 Git worktree 已注册，项目、主机、目录、分支、HEAD、交接文件路径和精确文件 SHA-256 与冻结回执一致，且标题符合启动包。
- 后继任务只读验证；发现漂移直接 `HANDOFF_BLOCKED`，不在后继任务自动修复交接文档。
- 源任务不自归档。后继任务完成全部核验后，才改名源任务为 `已交接｜<项目>｜<阶段>｜<YYYY-MM-DD>`，调用归档并回读标题、归档状态和线程入口。
- 改名或归档任一步失败，保留源任务现状并报告阻塞；不要创建第二个后继任务重试。

## 非 Git 项目

非 Git 项目仍使用同一保存项目目录和唯一交接文件。冻结回执记录保存项目、主机、实际目录、相对路径、精确字节 SHA-256 和时间；不创建 worktree、提交、分支或虚假 ref。后继任务必须在同一目录只读回读这些事实。源任务冻结后不得继续修改项目、交接文档、计划或相关运行态，发现漂移即阻断。

## 冻结回执

Git 项目最终提交后的 HEAD、分支、主机、工作目录、交接文件相对路径、精确 SHA-256、规范化辅助指纹、短令牌、源任务完整身份和时间只写入仓库外的运行回执。最终 HEAD 和本文件自身的哈希不得写回本文件，避免自引用。非 Git 项目至少记录文件存在、路径、精确 SHA-256 和源任务完整身份，并让后继任务在同一目录只读核验。源任务身份只用于后继任务精确关闭，不进入项目文件、普通日志或最终用户回执。

## 排除内容

项目交接文档和启动包均不写入凭据、令牌、Cookie、`.env` 内容、私有会话标识、完整终端输出、完整旧对话或与项目无关的个人信息。

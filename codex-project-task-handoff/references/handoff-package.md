# 项目唯一交接文档与启动包模板

每个项目只维护一份活动交接文档。项目规则已指定路径时遵循项目规则；未指定时使用项目根目录的 `PROJECT_HANDOFF.md`。每次接力原地更新，不创建按日期、任务或阶段命名的副本。

交接文档只保存恢复开发所需的当前事实，不承担路线图、需求池或第二份计划的职责。通常控制在约 3,000 个中文字符内；复杂项目宁可引用项目文件，也不要复制完整聊天或长日志。

## 项目内唯一交接文档模板

~~~markdown
# 项目交接

> 唯一活动交接文档。后续任务必须更新本文件，不得创建等价副本。

## 交接元数据

- 更新时间与时区：
- 事实核验范围：
- 当前阶段：

## 项目身份

- 项目名称与保存项目：
- 当前目录与 Git 分支：
- 项目长期目标：
- 当前阶段：

## 当前有效规则

- 全局规则：只写与本项目直接相关的约束。
- 项目规则：列出 `AGENTS.md`、唯一计划或契约文件。
- 安全与权限边界：写清不可自动扩大的动作。

## 已完成与证据

- 已完成事项：
- 变更文件或提交：
- 已运行验证及结果：
- 当前服务、端口或后台任务：

每项标明“当前回读确认”“历史证据”或“尚待验证”。不要把计划写成已完成。

## 当前工作区

- 已修改未提交：
- 新增未跟踪：
- 与用户既有改动重叠处：
- 不得清理或覆盖的内容：

## 未完成工作

- 待办与优先级：
- 阻塞或待用户决定：
- 已尝试但失败的方案：
- 建议下一步：

## 禁止动作与外部门禁

- 未获当前授权不得执行：
- 外部依赖或证据阻断：
- 不得被工程进度掩盖的结论：

## 后继任务启动指令

- 首先读取适用规则、项目计划和当前 Git 状态。
- 对照本交接包报告差异；易变化状态必须重新验证。
- 未附带首项任务时只完成初始化并等待，不修改项目。
- 已附带首项任务时，在核验完成后按其授权范围继续。

## 文档维护规则

- 下次接力只更新本文件。
- 本文件不是项目计划；待办状态以项目唯一计划或实际运行证据为准。
- 易变化事实必须重新核验，无法核验时明确标为“尚待验证”。
- 不写入凭据、令牌、Cookie、`.env` 内容、私有会话标识或长日志。
~~~

## 后继任务精简启动包

创建任务的初始提示只传下面这些定位信息，不重复粘贴整份项目交接文档：

~~~text
这是 <项目名称> 的后继开发任务。

先完整读取适用的 AGENTS.md、<唯一交接文档项目内路径>、项目唯一计划、README 和架构说明，再回读当前 Git/工作区状态。交接文档更新时间为 <时间与时区>；其中易变化事实必须重新核验，并简短报告差异。

首项任务：<用户明确任务；没有则写“只读初始化，等待用户下达任务”>。

固定边界：<只保留会影响本次启动的权限、安全和运行态边界>。
~~~

## 排除内容

项目交接文档和启动包均不写入凭据、令牌、Cookie、`.env` 内容、私有会话标识、完整终端输出、完整旧对话或与项目无关的个人信息。

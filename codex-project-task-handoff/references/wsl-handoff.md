# WSL 项目接力

适用于 Ubuntu-24.04 WSL。先遵循当前全局及项目规则；以下路径约定不改变其他主机的工作方式。

## 路径、工具与编码

- 本机活动状态为 `/root/.codex`，规则入口为 `/root/.codex/AGENTS.md`；存在 override 时核对覆盖。不得链接或覆盖 Windows 的认证、配置、数据库和会话历史。
- 代码根为 `/root/workspaces/<project>`；保留已有层级，用 `realpath` 和 `git rev-parse --show-toplevel` 确认实际根。交接文件使用项目规则指定的唯一入口，未指定才使用 `PROJECT_HANDOFF.md`。不因非 Git 资料目录而初始化 Git。
- 写入前核对目标用途及真实路径。Windows 挂载盘 `/mnt/*` 仅按任务范围只读引用，接力不得自动迁移项目、改宿主机配置或重绑远程主机。
- 使用本机 Git；纯标准库验证器用 `python3 /root/.codex/skills/codex-project-task-handoff/scripts/validate_handoff_state.py ...`。它不安装依赖。项目测试仍遵循项目已声明的 uv、虚拟环境及锁文件。
- 文档显式按 UTF-8 读写。后继检出使用精确字节 SHA-256，CRLF/LF 辅助指纹不能替代它。
- 提交前回读 Git 生效身份、暂存差异及忽略状态；推送前核对既有远端和分支。接力不授权修改 Git/SSH 全局配置、强推或提交用户未知改动。

## 项目外冻结回执

项目内长期只保留唯一交接文档。每次运行的冻结回执放在 `/root/Documents/work/tasks/<YYYY-MM-DD>-项目接力-<项目名>/work/`；重名任务目录追加短编号。回执只包含定位、哈希、核验结果和精确关闭必需的任务身份，不复制交接正文，不成为第二份活动交接文档。目录权限设为 0700，含完整任务身份的回执设为 0600。

在创建后继任务前确认它能在同一 WSL 主机读取回执路径；否则仅通过受支持的任务初始提示传递精简启动包。项目外回执不进入 Git、公开输出或普通日志。冻结后如发现原任务或后台写入导致漂移，保留源任务并报告阻塞。

## 工具可用性与验收层次

每轮以当前工具发现结果和实际 schema 为准，不把源码中的工具名、CLI 帮助或另一个主机拥有的能力当成当前 Desktop 项目接口。

没有上层会话工具时可以核对本机 app-server 公共协议，先确认版本、帮助和当前生成 schema，再按授权调用实际支持的方法。API 读写必须使用同一目标主机的真实任务 ID，并单独验证项目绑定、worktree 和后继初始化；不把它等同于手改内部数据库，也不因为上层工具缺失自动建议升级。Windows 使用其本机受支持接口及工作树，不跨侧代用 Linux 状态。

| 所需能力 | 缺失时的处理 |
| --- | --- |
| 查询当前绑定和已保存项目、核对主机 | 保留项目盘点和交接文档；不猜 projectId，也不创建替代保存项目 |
| 从已提交 ref 创建同项目 worktree 任务，或在同一非 Git 目录创建任务 | 交付启动包，说明需在同一保存项目手动创建；不调用 fork/handoff 冒充新任务 |
| 取得真实任务 ID 并读取初始化结果 | 对既有候选按令牌、项目、主机有界对账，不重复创建 |
| 设置名称、归档及回读 | 源任务保持可访问；不自归档、不写内部数据库、不伪造完成回执 |

底层 app-server 的 `thread/start` 不单独证明 Desktop 的保存项目绑定、worktree 创建和跨主机路由均可用。只有当前受支持接口能证明全部不变量时才执行自动接力。工具可用后复用原回执和已有候选，先检查漂移及重复，不重建一套交接材料。

区分并如实报告：

- `INSTALLED`：本机安装副本与受管源文件、发布记录哈希一致。
- `DISCOVERY_VERIFIED`：新的 Codex 进程实际发现该 Skill，路径唯一、启用且无相关加载错误。
- `HANDOFF_PREPARED`：项目唯一交接文档及启动包已验证，但自动接力能力仍缺失时同时报告 `HANDOFF_BLOCKED` 和具体缺口。
- `HANDOFF_VERIFIED`：真实后继任务完成只读初始化并由后继任务回读源任务改名、归档结果。

技能迁移只验证前两层和离线验证器。不得为了安装验收而创建、改名或归档用户当前业务任务。

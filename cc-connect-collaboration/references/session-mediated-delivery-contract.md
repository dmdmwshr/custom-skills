# 固定会话代发兼容契约

固定会话代发是停用兼容能力，不是业务自动通知默认路径。当前自动通知必须遵循 [代码触发直接投递契约](code-triggered-direct-delivery-contract.md)：业务项目提交无正文意图，中枢直接调用私有 `/send`，不创建 Timer、不恢复外部 CLI，也不要求桌面 Agent 代发。

只有当前用户明确选择试验会话注入，并且业务仓与中枢计划允许时，才可启用本契约。不得在 `direct_feishu` 失败时自动回退到固定会话，也不得对同一幂等键同时使用两条路径。

## 兼容路径职责

- 业务项目拥有事实、待发送箱、发送条件、幂等键和授权边界。
- 中枢负责 Timer、会话提示、绑定代次、投递账本和脱敏回执；不补全事实、不持久化正文。
- 固定会话只做受控引用读取、轻量格式化和最终回复，不做交易、账户、授权、下单、撤单或事实升级，也不得主动调用 `/send`。
- 每条路由使用独立控制目录、受审 Hook、会话和幂等空间；不得跨路由复用。

## 唯一写入者门禁

启用前必须证明目标固定线程只有一个官方写入者，Codex 运行包组件匹配，并用一次无业务事实探针验证：Timer 被接受、目标线程产生新 turn、解析器执行、一次性发布权被领取且最终回复非空。

出现 active writer、线程存储冲突、模型缓存不兼容、辅助程序缺失、空响应或未领取发布权时，立即停止会话注入并保留业务待发送项。重新命名、重新添加目录、重建绑定、降级或改写 `.codex` 数据库、索引和会话文件都不能绕过门禁。

该门禁只约束 Timer/会话注入，不得据此把通过独立目标核验的 `direct_feishu` 标为不可用。

## 状态与幂等

至少分别记录 `session_prompt_accepted`、`session_prompt_unverified`、nonce 是否已领取、`session_publish_unverified` 和明确失败。Timer POST 一旦开始，任何超时、非 200 或异常回执都可能已经创建，禁止再次添加；未知送达不得重发。

`session_prompt_accepted` 仅表示 Timer 被接受；领取 nonce 只表示会话开始最终输出；两者都不等于飞书已送达或已读。没有可信平台回执时总体保持 `delivery_unverified`。

外部 CLI 写入冲突只限制本兼容路径。自动代码通知、移动入站固定会话、会话换代与人工直接发送必须分别按各自契约和当前授权处理。

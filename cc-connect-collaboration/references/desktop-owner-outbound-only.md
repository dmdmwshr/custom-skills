# 桌面专属会话与出站直送模式

## 适用与选择

仅在路由明确登记 `session_mode=desktop_owner_outbound_only`、`session_owner=desktop`、`automation_owner=desktop_heartbeat` 时使用本参考。不得仅因任务标题、项目归属、侧栏位置或界面中截断的目录名称推断该模式。既有路由缺少这些字段时进入 `mode_unknown`，先只读核验并形成待审登记变更，不得直接按默认模式改写运行态；新建路由才使用默认的 `cc_connect_fixed_session` 双向模式。

此模式把“会话所有权”和“消息出口”拆开：目标 Desktop 固定任务独占会话、桌面能力和 heartbeat；cc-connect 仅核验无正文投递意图并使用 `direct_feishu` 出站。它不是双向模式的降级实现，也不是创建第二任务或新路由的理由。

## 入站、出站与桌面能力

- 飞书入站在平台边界按 `silent_drop` 静默丢弃：不得创建、唤醒、恢复、写入或提示 Desktop 固定任务，也不得把入站改投 Bridge、CLI 或其他会话。
- cc-connect 只能执行已核验的 `direct_feishu` 出站；它不得接管 heartbeat、会话注入、浏览器自动化、桌面 UI 或会话生命周期。
- 依赖已登录 Chrome、浏览器扩展、可见桌面 UI、桌面应用状态或相同本地交互环境的动作，只能由该目标 Desktop fixed task 的 heartbeat 执行。cc-connect CLI、cron、Bridge 和无头/替代运行器不得模拟、复用或绕过这些能力。
- 业务层可用 `NO_REPLY` 表示“正常且无需用户可见内容”；最终平台结果必须转换为原生 `DONT_NOTIFY`，不附加正文、健康提醒或补发消息。

## 项目归属与实际目录

把既有 Desktop 任务加入 Codex 项目只用于整理，不改变其内部任务身份、路由已登记且受审的实际 `work_dir`、Hook 或自动化目标。该目录不要求一律迁入中枢控制目录，但必须与路由登记精确一致。完成项目归属变更后，逐项回读：任务内部身份不变、完整实际 `work_dir` 精确不变、受审 Hook 一致、heartbeat 的内部目标仍精确指向该任务。界面显示标题、公开别名或目录末级名称时，不能代替内部任务标识与完整目录回读。

项目附加要求重建任务、复制任务、迁移会话，或回读发现 `work_dir` 回退到项目根目录时，取消该操作并保留项目外状态；它不影响既有模式继续运行。

## 计时器与换代边界

本节默认不自动换代。用户明确要求同机全部重新部署或更换固定任务时，使用下述“授权换代”步骤；跨主机唯一 Linux 新会话接替时，改用 [WSL 原生部署](wsl-deployment.md) 的接替分支；旧会话仅保留历史，旧扫描者须退出，新 heartbeat 先暂停，不允许新旧同时扫描。原飞书出站目标与新 Desktop 所有者分别核验，不伪造 p2p 会话迁移或要求两个线程 ID 相等。

同一路由的 Desktop heartbeat 与 cc-connect cron 强制互斥。需要周期执行时，只保留 Desktop heartbeat；cc-connect cron 必须不存在或停用。发现两者同时存在、触发源无法唯一证明或已有执行冲突时，记为 `timer_conflict` 并失败关闭：不扫描、不发送、不补跑，也不通过新建定时器修复。

本模式不使用 Bridge、`/new` 或移动入站创建并行执行者。默认双向固定会话协议不适用；用户明确授权的 Desktop 所有者换代按下一节执行。

## 验收与未知投递

分别记录三层事实：业务正常运行、传输层接受、用户确认飞书真实可见。前两层都不能代替后一层。投递意图登记或私有发送结果未知时，保留不确定状态并禁止自动重发；不得以“尚未看到消息”推断未送达。

## 用户明确授权的同机换代

保持出站模式和原目标。先暂停原 heartbeat、证明旧任务空闲且无在途，再用产品创建唯一候选。产品 worktree→正式目录交接可能返回不同的真实 threadId，并可能重置模型设置：必须回读最终 cwd、threadId 和下一普通轮实际模型/effort，不能只沿用创建回执。任务列表暂缺新任务时，按创建工作目录查受限元数据并用官方 thread/read 回读，不因缺少列表项重复创建。

使用项目已安装的 `x_owner_replacement` 事务准备精确变更：只更新 owner preparation、固定任务行和出站所有者哈希；保留飞书目标/路由代次、其他任务与投递去重。新旧任务官方空闲回执、暂停的原定时器、停止的受影响服务和新鲜配对备份齐备后持锁提交，激活标记最后发布。中断先 reconcile，不能再 apply；回退只恢复原计划中的配置。

随后把原 heartbeat 绑定最终新ID，更新共享控制登记的真实执行者并保持暂停，恢复服务。新执行者通过受影响业务验收并正常释放后才恢复原调度；旧任务留历史，不同时运行第二个定时入口。用户只说清理水位时，不据此删除旧发送去重/未知回执或换键补发。会话已创建、配置已绑定、业务已验收分别报告。

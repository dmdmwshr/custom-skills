# 飞书应用显示维护与发布

本流程只处理已经存在且已经绑定 cc-connect 路由的飞书应用展示信息。它适用于应用名称、机器人聊天显示名称或描述与实际职责错位，但 App、通道、路由和固定会话本身仍正确的情况；不得借此新建应用、交换绑定或扩大权限。

## 选择操作入口

1. 先查询是否存在能够完成当前应用管理动作的受控连接器、官方 API 或本机 CLI；可用且能力完整时优先使用，并按其回读结果验收。
2. 没有合适接口、接口不支持当前字段或仍需可见页面确认时，才使用浏览器控制 Skill 操作用户已经登录的飞书开发者后台。复用现有登录态，不读取 Cookie、本地存储、密码、App Secret 或租户令牌。
3. 只有当前用户明确批准最终名称、必要描述和发布影响后，才保存或提交版本。只读核对、截图或旧授权不构成本次发布授权。

## 变更前判断

1. 先核对控制目录、公开路由职责、固定桌面会话工作目录和受审 Hook。只有这些真实绑定都正确时，才按“显示名称错位”处理。
2. 通过当前页面可见信息与中枢既有私有映射在内存中完成一对一核对。不要把 App ID、会话键或其他平台标识写入 Skill、Git、计划、日志或回复。
3. 两个应用必须逐个处理。应用无法唯一识别、出现同名歧义或页面职责与路由证据冲突时立即停止，不猜测、不交换名称。
4. 变更清单只允许列出用户已确认的展示字段：最终名称、必要描述、补丁版本和发布说明。App ID、App Secret、权限、事件订阅、可用范围、机器人菜单、允许名单、工作目录和私有会话绑定必须保持不变。

## 可见后台操作顺序

1. 从应用列表或当前应用的“基础信息”读取应用名称、描述和发布状态，确认当前对象后再进入编辑；不要仅凭浏览器标题判断应用身份。
2. 只修改批准的名称与描述，保存后立即在同一页面回读。若页面要求新增权限、填写密钥、改变事件、扩大可用范围或补充未授权字段，停止提交并向用户说明新增影响。
3. 若平台要求通过新版本发布展示信息，创建最小补丁版本；发布说明只描述本次展示字段校正，不混入通道、权限或业务能力变化。
4. 提交发布后等待并回读平台状态。只有页面明确显示审核通过、版本已发布或“当前修改均已发布”，才可报告发布完成；仅保存草稿、提交审核或页面跳转不等于已发布。
5. 返回应用列表和两个应用各自的基础信息再次回读最终名称、描述与发布状态，防止在相邻应用中写反。移动端名称缓存未即时刷新时，只提示用户重新打开聊天或刷新客户端，不因此重绑或新建会话。

## 发布后的双向验收

1. 回读两个桌面固定会话的标题和实际工作目录；标题只负责显示，目录和 Hook 才是路由身份。
2. 让用户在两个移动聊天发送带不同序号的普通消息，不发送 `/new`。至少一条消息覆盖每个职责；若要验证连续复用，可在其中一个聊天连续发送两条。
3. 通过官方桌面任务接口只读核对：每条入站只进入预期的既有固定会话、顺序完整、产生可验证回复，并且没有出现第三条同职责活动会话。只读取完成判断所需的最近几轮，不复制原文或扫描无关历史。
4. 桌面会话产生回复只证明入站映射与会话执行成功；没有飞书平台独立回执时，移动端回发仍由用户现场确认，不能据此称为已送达或已读。
5. 只有真实工作目录、Hook、路由或会话键错误时，才进入固定会话换代或绑定修复；显示维护失败不得自动升级为重绑。

## 可持久化证据

只记录用户可见名称、职责、描述、补丁版本、发布状态、验收时间，以及“两个既有固定会话分别收到多少条编号消息、是否出现新会话”的脱敏结论。不得记录 App ID、App Secret、会话键、平台用户标识、消息正文、浏览器存储或完整页面导出。

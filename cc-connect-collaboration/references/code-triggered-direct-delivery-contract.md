# 代码触发直接投递契约

本契约适用于业务代码自然产生、无需桌面 Agent 判断的自动通知。固定链路为：业务仓不可变信封 → 无正文 `DeliveryIntentV1` → cc-connect 控制网关 → 私有目标校验 → cc-connect `/send` → 飞书。

## 职责与进程

- 业务数据任务只生成事实和不可变信封；独立轻量消费者负责登记意图与追加回执，不能让数据采集主循环等待飞书。
- cc-connect 拥有凭据、路由、私有目标映射、直接传输和投递账本。业务仓不能持有飞书凭据、调用 `/send`、选择会话键或读取私有映射。
- 自动分发器每个循环原子领取最多一条意图。桌面固定会话、Hook、Timer、Luna 和外部 Codex CLI 不参与自动通知。
- 固定会话仍负责移动双向协作。用户回复自动通知后，入站进入该路由现有固定会话，不因此创建新桌面任务。

## 发送前强制核验

在读取消息内容以及调用 `/send` 前，中枢必须同时证明：

1. `route_key`、来源和事件类型均已登记；
2. 路由业务项目与通知引用归属一致；
3. 当前 `binding_generation` 等于业务已确认代次；
4. 私有目标唯一，且属于数据通知路由；
5. 数据通知与交易授权路由没有共享会话键、工作目录或私有目标；
6. 幂等键未投递、内容哈希匹配、通知仍未过期。

任一条件不成立都必须在 `/send` 前失败关闭。不得以显示名称、桌面标题、目录是否加入项目或“第一个活动会话”选择目标。

## 内容与账本

投递意图不能携带正文或 URL。中枢在投递时通过固定的业务受控只读解析器读取指定通知引用，核对内容哈希后仅在内存生成飞书正文。持久账本只保存哈希、状态、时间、错误类别和不透明引用；日志、命令参数、环境变量和回执不得包含正文或凭据。

## 重试与未知结果

- 发送前可明确证明尚未调用 `/send` 的连接或本地健康故障，最多有限尝试三次，沿用同一幂等键，不复制待发送项。
- 从 `/send` 调用开始，任何超时、非 200、协议异常、畸形回执或进程中断都可能已被平台接受，必须记为 `delivery_unverified`，不得自动重发。
- `/send` 返回 200 只记 `transport_accepted`；没有可信平台回执时不得写“已送达”或“已读”。
- 重启后恢复领取时，已登记、在途、未知、过期和历史兼容状态必须保持原语义；未知记录不回到可领取集合。

## 启用与真实验收

1. 先保持 `disabled` 完成单元、集成、来源白名单、错误路由、代次、幂等、重启恢复和内容不落盘测试。
2. 启用前回读业务与中枢的待发送、在途、未知和 `ledger_epoch`。
3. 真实测试只能选择一条当前用户已授权、仍未过期、业务账本证明从未登记且中枢认证对账证明不存在的历史信封；所有已尝试或状态未知记录必须排除。
4. 测试只允许在目标飞书聊天出现一次，交易授权聊天不得出现。最终可见性由用户确认。
5. 验收通过后才开放下一条自然产生的已登记事件；异常时只关闭直接分发，保留业务待发送箱与全部账本。

外部 CLI 写入冲突、固定会话空响应或 Bridge 会话能力异常只约束会话注入和换代，不阻断通过上述独立核验的直接飞书出口。

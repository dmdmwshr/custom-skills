# WSL 身份、受管加载与发布

当前事实读取项目 PROJECT_HANDOFF.md、LINUX_STARTUP_GUARD.md 及本机浏览器说明。本技能不固化用户名、UID、任务ID、PID或版本快照；旧 CUA/prepare/complete 证明不适用于当前 Playwright 路线。

## 身份和共享连接

生产调度任务与当前执行者分开。开发/验证可由当前已授权任务直接完成；统一部署登记保存阶段、生产任务、临时执行者、代次和项目根。使用当前工具真实任务元数据，不冒用生产任务。进程持有跨项目互斥租约，不能靠超时抢占仍活动的执行者。不同用户/资料的凭据不能复制或强行合并。

部署入口、current 或业务库缺失时先按项目 DEPLOYMENT_BOOTSTRAP.md 的独立受管启动入口 inspect/ensure；恢复成功后才通过已安装的项目入口加载 runtime，再 connectPlaywright。按当地 ProjectBrowserV2 唯一契约，每项目一个受管连接与原生组，跨项目仍持主机互斥租约串行控制；同项目不并开 CLI/MCP，不调用 GPT/CUA/native。

正常 park 先由适配器按当地契约核对同页复用、登记明确下次用途并显式环境 finish，回读 closed/retained/protected/unknown 后释放逻辑客户端与本轮业务守卫。仅有用途声明不算实际复用证明。后续新进程从真实任务身份重新取得租约，并复用精确页面对象/ID；保存 reuseTab 返回的原始句柄，不能手造同 ID 对象。页面/上下文丢失不能按 URL/标题认领：仅已知无在途的绑定失败走受管有限恢复，归档旧连接元数据、断开后建立新连接，再重新观察。连接缺失与正常新进程续接已实测；整机重启和外部崩溃须按实际环境另验，不能据此声称全部通过。

未知请求持久保留，先对账不重放；明确完成的无副作用拒绝可凭精确回执结算，不一概永久阻断。恢复步骤回读已完成阶段，重复调用不重做已完成的退役/建立。用户页面和登录资料保留；废弃授权页按精确归属归档后关闭。
共享控制分离进程租约、请求日志与恢复核对；完成回执先持久化再返回。请求号、项目、页、操作及代次不符仍未知；inspect/reconcile不重放浏览器操作。执行资格失效后仍可释放自己的逻辑客户端，未决请求保留。短暂只读失败有限恢复且共享原截止时间，连接初次绑定的已知上下文失效每次流程最多重建一次；正常退出与整机强杀的验证结果分别记录。

## 加载与收尾

只加载 current 指向的已接受模块，加载代码及签名见项目说明；不要复制旧维护代码或恢复正文。launch 返回立即保存，连接失败时正常释放未使用租约及守卫，不丢弃活跃对象。固定 driver IIFE 返回对象，stdin/control 返回 factory。首次进程或客户端变化完成真实自检。

配对守卫连续覆盖操作到正常关闭。正式业务由 workflow 完成 finish、终态 health、park、清事实、关闭守卫；诊断不得写业务，须依据实际无锁/零在途和停泊回执正常关闭。候选测试、安装、浏览器控制/登录、业务投递和用户已读分别报告。

## 发布与初始化

模块测试按影响，整合后一次回归；driver 分片构建 --check，reader未改则复用原精确证据。runtime-files.json 是显式清单，测试和维护脚本不进生产。

暂停原调度，仅用产品自动化工具；用新鲜静止双库备份窗口及现行受管发布入口，不手改 current 或重用已消费窗口。正式库只经 production_startup_guard 与 SQLiteStore(read_only=True) 正常关闭。回退本次程序/配置，保留之后新增业务数据。

普通 ensure 幂等恢复程序、目录和初始化缺口，不清已有业务数据。缺失 current 的构建安装、二次 ensure 不变、空库与服务中断恢复可分别验证；不能据这些证据声称整机重启、全部历史补采或无登录凭据也能自部署。缺主机权限、账号登录或凭据时准确报告具体条件，不另换浏览器资料。

用户明确要求全新初始化时才按项目受管 reset 入口清历史/水位：使用新鲜静止备份和当前清理清单，保留配置、绑定、账号、其他项目及平台消息。默认旧内容仅建立基线，持久记录本次 notification cutoff；旧观察可参与关联，不作为新通知重发。反复丢库或再初始化须新鲜建立 cutoff，不能沿用旧重置时间。中枢网关历史及防重默认保留，只有用户明确要求历史重新通知时才按精确范围另行处理。保留外部引用的单调序列，新告警编号从该序列延续，避免撞上中枢历史隔离键。备份不是新业务事实来源。

原 heartbeat 缺失时，经产品工具按现行部署登记恢复原 id/目标/调度，维护期间保持 PAUSED，核验业务与绑定后恢复；不直接写 automation.toml。换代创建结果未知与部署缺失分别处理：持久 client 回执不能改作失败。用户明确重部署时，维护登记执行者可用受管 supersede-for-redeployment 在原 owner/browser 未变、无在途/runtime、原任务终态无队列且调度暂停或缺失时隔离旧请求；保留 unknown_may_complete_later，晚到 candidate/ready/switch 拒绝。同旧 cycle 不另建候选，清库后无 cycle 进入 bootstrap，下一新业务周期才恢复正常换代。

当前获准执行者完成新鲜双流、真实投递与增量防重，正常释放临时权限后交还生产任务并恢复原调度。不要强制原任务重复验收，不恢复已退役自动化；长期自然观察不是固定三加四轮的发布门槛。

# X 消息监控

在 WSL 迁移与离线维护时，先读取 [WSL 迁移边界](references/wsl-migration.md)；本机路径与安装入口按该参考执行，真实扫描仍仅属于已验证的唯一 Desktop 固定任务。

本技能共用采集与投递契约，但运行配置按目标主机选择：下段版本及 Windows 快速路径属于 Windows 配置；WSL 的客户端版本、原生入口和发布目录以 WSL 参考为准。两侧配置不能交叉拼接，版本变化还须回读实际发布文件与指纹；安装技能不改变固定任务归属。

当前驱动 3.0.30、标准输入客户端 1.1.0、步骤修订 2026-09-11.9；原固定任务使用用户指定的 Luna/max，任务交流不擅自开启加速或覆盖设置。acquire仅一次，在同次调用立即保存原始结果与本轮租约回执，后续控制只引用该对象；本轮publish-pending预检明确成功后才生成任何草稿，不能随page提前生成或改写时间。独立表情仍须唯一、已加载、Unicode与标准资源匹配及可见性核验；维护诊断只附同次有界拒绝证据，HTML拒绝不放宽。页面分段就绪、水位原样提取、自动分页及回复最多八导航保持。回复展开等待同一可见卡片已无自身展开控件，再严格核验全文；浏览器方法直接输出回执；五项输入动作使用sendKept，在客户端保存同轮原样载荷/真实回执，后续按lease/action读取并在收口后clearKept。锁前完成静态准备；失败登记走固定入口和限定计时字段，连续手动验收整组回传后再整理。有界故障定位仅在已授权维护时读取 [维护诊断](references/diagnostics.md)。

运行只在已登记的唯一 Desktop 固定会话；维护和离线测试可在开发任务完成，不代替固定会话进行真实扫描。

1. acquire前确认已经完整读取当前步骤的 [固定快速路径](references/fast-path-runbook.md) 及 [上下文契约](references/reply-reset-contract.md)。已读步骤修订与工厂版本/指纹分别记录；加载新版工厂或只读维护诊断不代表已读运行规则。步骤变化、已读标记缺失或诊断后首次正式运行，先完整读取这两份当前说明，再复用有效工厂。普通轮次不展开历史、搜索模块、生成浏览器采集代码或试探 API。未知契约才读取 [完整边界](references/heartbeat-and-delivery.md)。
2. 浏览器代码唯一来源为业务项目 `scripts/desktop_monitor_driver.js`。在受支持的 CUA 会话中用普通 `let` 绑定加载原样工厂一次；版本未变、会话未重置即复用。不得使用 `globalThis`、内部模块、独立浏览器控制进程或自建浏览器桥接。用户已批准宿主通过 `scripts/desktop_stdin_client.js` 向原固定校验入口的有限子进程直传标准输入；它不控制浏览器。
3. 流程固定：健康 → 锁与预检 → 主帖采集/分析/提交/登记 → 回复采集/分析/提交/登记 → `heartbeat-finish`。主帖和回复各自事务；回复失败不回滚已提交主帖。共同身份/路由故障停止后续处理。
4. Chrome 优先；仅实例、扩展、登录不可用三类实测失败，经机器授权才用 Edge。结构、水位、父帖歧义不得换浏览器。只操作本轮新标签，不触碰原有标签，不读取密码、Cookie、令牌、浏览器存储或验证码，不保存 HTML、截图、HAR。
5. 两流由sendKept("context-plan",...)的payload内一次draftStream生成草稿，识别新项并补必要上文/引用后，由sendKept("collect-stream",...)的payload内一次rawStream冻结；analysis-plan和scan-analysis依次取kept中的原载荷。新周期不使用兼容send，不独立执行draft/raw或暂存其结果。新回复直接Latest搜索和永久链接核验，上文最多三层、引用最多五个来源，同轮复用；按 [上下文与额度契约](references/reply-reset-contract.md) 执行。程序组装V3，不重写映射代码、不重分析历史。
6. 主帖和回复统一只推送 Codex 额度重置相关的新内容；包括进展、延期、规则和明确否认，相关无时间写明未提供可推算时间。通知分别展示当前消息、直接对象和采用的上文/引用的原文、翻译、时间与链接；引用不能冒充外层作者承诺，其他产品重置不推送。无关/无法判断入账并推进水位，未知送达不重发。
7. 唯一完成依据是 `heartbeat-finish`：完整成功且机器允许才输出精确 `DONT_NOTIFY`。部分完成或未知回执报告简短中文故障。连续四次完整、零可推送的**定时运行**由 SQLite 生成飞书健康证明；手动验收不充数。
8. 保留现有固定任务、自动化身份与计划、工作目录；本任务模型按用户指定 Luna/max。不得新建、唤醒、转移、恢复或并行使用第二个 Codex 任务；cc-connect 只做 `direct_feishu`，入站 `silent_drop`，不创建 cc-connect cron、Windows 计划任务、飞书入口或第三种浏览器。
9. 每轮汇总浏览器到收口的全部失败阶段。首次、实质变化、持续满二十四小时一次、完整恢复一次由账本去重；每个失败周期仍在原任务报告。已经提交的流发生后续投递/回执/标签关闭错误，使用 cycle-failure 追加，不覆盖成功扫描或盲目重发。
10. 标准输入客户端 1.1.0 首次加载或控制会话重置后先完成固定 selfTest，实际 exact_match=true 才使用。完整搜索序列、机器指纹、草稿、计划、冻结事实和分析均保留于同一 CUA 宿主；五个指定动作通过现有 chunks/无回显协议一次性提交。传入后回执未知不重试，小型控制动作及同 lease 两阶段 finish 继续用原入口。模型只读取新项分析事实，不再转抄长字典或 gzip 载荷。

维护任务遇到浏览器启动错配置、扩展控制失败、工厂转写差异，或用户明确要求验证飞书网页登录复用时，调用 `codex-local-state-diagnostics` 的浏览器控制恢复流程。普通 heartbeat 仍只走本技能固定快速路径，不因这条维护入口增加浏览器、任务、重试、登录或发送权限；不要把控制失败误报为用户没有登录。

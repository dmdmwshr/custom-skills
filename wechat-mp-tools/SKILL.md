# 微信公众号文章获取

复用已安装的 WeChat MP Tools 和其本地接口，完成一次性获取、文件核验和交付。当前验证范围是 Windows 便携版；主机入口与接口见 [references/runtime-api.md](references/runtime-api.md)。其他平台不套用这些路径或声称已验收。

## 先确认本次任务

- 用公众号名称和任意文章链接定位目标；同名或无法唯一确定时才补问。记录 `fakeid/biz`、名称、用户给定链接及日期范围。
- 默认只做本次获取。没有用户对持续更新的明确要求，不新建 RSS 订阅、周期任务、自动上传或后台轮询。保留原有其他任务，不为本次任务关停它们。
- 清单、断点、回执和交付物放在当前任务目录，运行数据留在应用数据目录，认证信息不进入成果或源仓。
- 先查已有清单和下载记录，复用成功结果；续接时从已保存水位继续。未知结果先回读，不重复提交。

## 执行流程

1. **检查真实入口。** 运行下方 `doctor`，结合安装记录、端口所属进程及可执行文件核对当前版本。应用未运行时，按安装记录启动已安装版本，不重复安装。版本或接口不符时先核对当前上游和运行态。
2. **确认登录与目标。** 使用原应用登录。需要二维码时只生成一次，保存图片给用户扫码，回读登录状态；不输出 token、Cookie、二维码 Base64 或账号池原文。公众号收藏只是本地目标登记，RSS 订阅是持续任务，二者分开。
3. **逐页获取清单。** `page` 每次仅请求一页，保存请求位置、列表响应和请求前后的账号池摘要。按稳定文章 ID 或规范化 URL 去重，保留首末日期和下一位置。接口可能估算 `total`；`can_msg_continue=0`、空页、固定数量或日期跨度都不能单独证明已经取全。
4. **判断是否继续。** 频率限制、冷却、登录失效、接口错误或结果不明时保存断点并停止本轮列表请求；不盲目循环、切换账号或代理规避限制。只有健康响应及可核验的结束证据才标记列表完整。结束标志与实际分页矛盾时保留“覆盖未确认”，不要无限探测。指定日期范围时，记录越过起始日期的健康页作为覆盖证据。
5. **下载已知文章。** 列表尚未完整也可交付已知部分。先查已有任务、链接重复和标题目录冲突；原工具可能复用并覆盖同名标题目录。分批串行提交已核定清单，每批先写提交中回执，再发起一次请求并保存任务编号。响应未知时保留回执并回读应用，不凭换文件名再次提交。操作示例见接口参考。
6. **等待与核验。** 有间隔地查询精确任务编号，不启动新的自动调度。`completed` 表示任务结束，仍须核对成功、失败、总数及逐条结果，保存完整回执。按结果中的实际 `path` 找文件，不能只信设置中的下载目录。运行 `verify` 检查 HTML、TXT 和图片引用，再抽查正文；该检查不证明视频、附件或全部媒体已离线。
7. **交付与收尾。** 复制到独立交付目录后以 SHA-256 比对原件和副本，再核对目录链接及压缩包内容。输出可点击目录和机器可读清单，至少含文章 ID/链接、标题、发布时间、任务编号、实际路径、状态、原始错误及覆盖说明。分别统计全文成果、缺媒体/文字补取、失败和未覆盖。回读本次任务已结束、没有新增持续订阅，并按实际使用的浏览器/界面技能收尾自有窗口。

## 辅助命令

脚本只用 Python 标准库，不新增服务或采集引擎。`doctor`/`task` 读取本地接口，`verify` 只读本地文件；`page` 会通过原工具访问上游，只有获取任务已获授权时执行。全局参数写在子命令前。

```powershell
$py = 'C:\Users\12070\AppData\Local\Programs\Python\Python312\python.exe'
$helper = 'C:\Users\12070\.codex\skills\wechat-mp-tools\scripts\wechat_mp.py'
& $py -X utf8 $helper doctor
& $py -X utf8 $helper page --fakeid '<公众号标识>' --begin 0 --count 5 --out '<新回执.json>'
& $py -X utf8 $helper task --task-id '<任务编号>' --out '<新状态回执.json>'
& $py -X utf8 $helper verify --root '<本次文章成果目录>' --out '<新文件核验.json>'
```

`page` 保存成功也不会自动宣告“全部获取”；退出码 2 表示受限或覆盖待核实。默认每页 5 条只是起步值，不代表安全频率保证。回执路径已存在时拒绝覆盖，换新路径仅用于保存新观察，不能作为重复请求未知任务的理由。

## 失败解释

- **列表受限**：上游明确限频，或空列表同时账号进入冷却。这证明列表未取全，不代表所有正文也因限频失败。
- **正文失败**：保存“未知页面”“仅内部分享可见”等原始报错。这些可能是工具的页面结构判断，不能单凭文案断言文章已删除或确属私密。
- **验证页/登录页**：可按用户授权通过普通浏览器检查实际页面；需要人工验证时交给用户，不绕过限制。浏览器正文能打开不等于原工具已下载成功。
- **文字补取**：另存补充目录，保留原失败记录，标明缺失图片/附件，不能混入全文成功数量。

## 技能维护验证

使用模拟响应与临时文件验证脚本，并对已运行的原应用做只读 `doctor`。不以测试为由新增抓取、重新登录或重放下载。真实任务的验收以当次分页证据、任务回执、文件及抽查为准。

# 通用下载传输与缓存规则

## 参数契约

- `--url`：无签名 HTTPS 直链。带临时签名或令牌时改用 `--url-stdin`。
- `--output`：最终文件的绝对路径。已有不同文件时拒绝覆盖。
- `--storage-root` 加 `--target`：`--output` 的安全替代。存储根目录必须绝对；目标必须相对且不能含 `..`，最终路径必须留在该根目录内。
- `--sha256`：可选官方 SHA-256；模型、安装包、可执行文件和依赖包应优先提供。
- `--probe-only`：验证 Range、空间和 SSH 直连；不创建缓存。
- `--status`：只读取本机状态、输出锁和脱敏日志；不连接 Meifu、不启动或重试传输。
- `--execute`：单文件例外模式。默认启动一个脱离调用终端的工作进程；不得从 Codex 当前会话使用 `--foreground` 执行长传输。
- `meifu_download_queue.py enqueue/start/status/list/audit`：公共直链的持久队列。除 `start` 外只操作本地状态；`start` 只请求已安装的 Windows 后台任务。

状态文件仅保留去除查询参数后的来源、来源身份哈希、ETag、大小、块校验值和输出路径，不保存完整签名链接。

## 传输保证

1. Meifu 只保留当前正在中转的分块，不要求保存完整大文件。
2. 每个分块先在 Meifu 计算 SHA-256，再由本机通过 SFTP `reget` 续传并二次校验。
3. 仅当完整文件大小正确且可选官方 SHA-256 匹配时，才原子写入最终位置。
4. 上游、SSH 或 SFTP 的临时故障会保留本机状态和远端当前块；来源 4xx、空间不足、目标冲突和哈希不匹配转为人工处理。
5. 同一输出路径只允许一个实际传输。后台启动器先原子保留输出锁，只能把锁交给持有匹配令牌的工作进程；重复请求不会并行写入本地暂存或 Meifu 分块。
6. 签名链接只经标准输入交给单文件工作进程，不进入命令行、持久队列、状态或日志。
7. 旧锁只在记录进程已停止时精确回收；身份不明的新锁保留两分钟，避免竞争窗口误删。
8. 公共直链队列始终限定为单工作者、单个 Meifu 分块。Windows 计划任务而非 Codex 命令树负责运行与网络恢复后的续传。
9. `queue.json` 只能由受管队列命令和后台工作者内部写入。每个读改写操作先取得短时单写入租约，再核对递增版本号后原子替换；租约忙或版本不一致时拒绝写入，绝不以旧内存快照覆盖新条目。
10. 后台任务引用已核验的版本化运行时副本，而不是会被同步过程整体替换的已安装技能目录。运行时缺失、哈希不匹配或无法启动时，当前条目恢复为排队状态，队列转为 `runtime_unavailable` 并停止；绝不把同一基础设施故障扩散成后续条目的逐条失败。

## 共享队列清单写入协议

多个 Codex 任务、ComfyUI 委托或人工脚本共用通用队列时，调用方不得直接编辑 `queue.json`、临时文件或锁文件，只能调用 `meifu_download_queue.py enqueue`、`pause`、`resume`、`remove`、`move`、`retry` 和只读 `status/list/audit`。

1. `enqueue` 在同一短时租约内完成“检查工作者状态 → 读取队列 → 验证输出路径 → 提交”；因此刚启动的工作者会在取得队列责任前读取到最新条目。
2. 每次提交写入递增的清单版本号，并记录最后一次本地变更。磁盘版本已变化时，旧调用方必须重新读取后再提交。
3. 租约文件只保护本地 JSON 写入，绝不跨越网络传输或退避等待。长期顺序性仍由队列工作者锁和单文件输出锁保证。
4. 旧 V1 队列在下一次受保护的正常写入时自动补齐版本元数据；结构异常、符号链接或仍存活的写入者一律拒绝处理，不尝试覆盖或递归清理。
5. 所有变更命令都必须写入稳定 `requested-by` 标识；可选 `request-id` 用于关联上游任务。审计 JSONL 只记录无签名公开来源、输出位置、条目编号、顺序、请求方和原因，并按固定大小轮换，避免无限增长。
6. 工作者每处理一个文件都在短租约内重新认领、写回结果；因此运行中的条目仍不可改动，但其他排队/待人工处理条目可以在传输期间安全追加、移除、重排或恢复。
7. 重复入队只有在来源、输出和 SHA-256 全部相同的情况下返回既有条目；同一输出位置不同来源或哈希一律拒绝，避免跨任务静默覆盖。

## Meifu 缓存生命周期

本 skill 的缓存根固定为 `/root/.cache/meifu-downloads`。清理器每小时运行一次，并只枚举该根目录的一层任务文件夹：

1. 任务目录最新活动时间超过 72 小时后可以清理。
2. 清理后仍低于 8 GiB 可用空间时，按最早无活动任务继续回收，直到达到保留空间或没有安全候选。
3. `--dry-run` 只输出候选；实际删除仅发生在定时服务或当前用户明确授权的部署操作。
4. 不删除缓存根、其他目录、正在写入的近期分块或任何本机最终文件。

旧 `/root/.cache/comfyui-models` 只作为已退役 ComfyUI 队列的遗留范围；通用下载器不会向其中写入、迁移或删除。是否清理或从服务端清理规则中移除，必须先审计旧任务并另行授权。

## 队列与缓存的配合

- 完整校验与原子落盘后，下载器删除自己的本地暂存目录和 Meifu 任务目录。
- 队列暂停、断网或 Windows 重启时不主动删除当前分块；它们是安全续传依据。
- 临时网络失败从 15 分钟开始指数退避，最长 6 小时；计划任务在用户登录及每 30 分钟唤醒，网络恢复后自动续传。
- Windows 计划任务只负责唤醒单工作队列，不能替代缓存清理器。安装、查看和卸载必须走该 skill 的精确生命周期脚本。

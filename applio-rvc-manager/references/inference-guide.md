# Applio 推理与跨语言转换

## 先判断任务类型

- 现有语音改成目标音色：使用 RVC Inference。
- 输入文字生成语音：先用 TTS 生成源语音，再用 RVC 改音色。
- 歌曲翻唱：先做人声与伴奏分离，再转换干声，最后混音。
- 实时直播：使用 Realtime，但先在离线 Inference 验证模型和参数。
- 中文转日语角色：内容仍是中文，只改变音色；不会自动翻译成日语。

## TTS 加 RVC 的统一流程

Applio 当前支持的文字生成角色声音流程是：

```text
UTF-8 文字或文本文件
        ↓
EdgeTTS 生成语言匹配的底稿（需要联网）
        ↓
选择目标 RVC .pth + .index
        ↓
Applio RVC 转换
        ↓
项目目录中的候选 WAV → 试听验收 → locked 母版
```

执行时分别保存 EdgeTTS 底稿和 RVC 输出，并在参数记录中写入文本版本、TTS 音色、TTS 语速、RVC 模型哈希、索引哈希和输出哈希。TTS 音色只决定底稿的语言、音域和韵律起点，不等于专属角色音色；最终音色由 RVC 模型决定。

### 方言和日语

- 普通话模型可以保留普通话源音频的音色特征，但不能把普通话发音可靠转换为粤语、四川话、东北话、吴语或河南话。
- 目标是方言特色时，使用对应方言录音训练的模型，并让底稿或源录音本身使用对应方言发音；必要时用原生方言录音替代 EdgeTTS 底稿。
- 日语文本使用日语 TTS 或日语源录音，日语音色模型和中文音色模型分开记录；先用含清音、浊音、长音、促音和拗音的短句验收。
- 如果确实需要一个模型混合多种语言/方言，必须在数据清单中标注 `locale`，保持各语言数据有意识地平衡，并明确可能出现的口音漂移。

### 不要把语言转换误认为音色转换

RVC 是音频到音频的转换器，不负责翻译、重新编排文字或可靠地重建方言音系。文本翻译、方言改写和日语文本准备属于前置文本工作；完成后再进入 Applio TTS 加 RVC。

## Applio 内置 TTS

Applio 3.6.4 的 TTS 不是单独的本地语音模型。它以 EdgeTTS 为中间件，执行：

`文字或 UTF-8 TXT → EdgeTTS 基础语音 → RVC 角色音色`

- 普通话可先从女声 `zh-CN-XiaoxiaoNeural` 或男声 `zh-CN-YunxiNeural` 开始。
- TTS Speed 控制 EdgeTTS 语速；先确定语速和停顿，再调整 RVC 参数。
- 默认底稿为 `assets\audios\tts_output.wav`，RVC 输出为 `assets\audios\tts_rvc_output.wav`。
- EdgeTTS 不需要下载本地 TTS 模型，但需要联网。
- 角色音色仍需要 `.pth`，建议配套 `.index`；只选择 EdgeTTS 音色不能得到目标角色音色。
- EdgeTTS 音色清单来自 `rvc\lib\tools\tts_voices.json`，在线服务可用性和音色数量应以现场查询为准。
- 需要完全离线、可训练或更强韵律控制时，应另选专用 TTS 项目和模型，不要把它误认为 Applio 内置能力。

## 输入质量

优先使用：

- 单人、无背景音乐、无明显混响的干声；
- 峰值不过载、底噪较低、语速自然的音频；
- 与目标角色音域接近的源声；
- 说话模型处理口语，唱歌模型处理歌声。

多人、重叠说话、笑声、喘息、吞咽声和餐具噪声应先分离或剪辑。RVC 不会可靠地自动解决说话人分离。

## Applio 3.6.4 基线参数

### 中文口语

| 参数 | 起始值 | 调整方向 |
|---|---:|---|
| Pitch extraction | `rmvpe` | 默认优先 |
| Pitch | `0` | 按源声与目标音域调整 |
| Search Feature Ratio | `0.50–0.70` | 电音或含混时降低；音色不像时提高 |
| Volume Envelope | `1.0` | 音量动态不自然时尝试降低 |
| Protect Voiceless Consonants | `0.40–0.50` | 中文辅音模糊时提高 |
| Embedder | `contentvec` | 先作为通用基线 |
| Clean Audio | 关闭后比较 | 底噪明显时开启，强度先 `0.3–0.5` |
| Autotune | 关闭 | 口语不要开启 |

可将 `chinese-hubert-base` 作为中文清晰度对照项，但不要假定它对每个外语训练模型都更好；使用相同短音频 A/B 验证。

### 跨语言角色音色

- 日语模型可以转换中文，但 `zh/ch/sh/r`、`z/c/s`、`ü`、儿化和声调可能不稳定。
- 优先选择由角色台词训练的模型；主要由歌曲训练的模型可能产生电子感。
- 先固定模型和源音频，仅比较 `contentvec` 与 `chinese-hubert-base`。
- 索引比例过高可能强化日语训练特征并损害中文咬字。

音高仅作起点：

- 男声转高音女声或派蒙：从 `+6` 或 `+8` 开始，必要时逐步到 `+12`。
- 女声转一般女角色：先用 `0`，再尝试 `-2` 到 `+3`。
- 男声转低沉男角色：先用 `0`，必要时尝试 `-2` 到 `-4`。
- 女声转低沉男角色：可从 `-6` 开始，不要直接假定 `-12` 最好。

Applio 支持 Proposed Pitch 和 Formant Shifting。男女声跨音域时可与手动 Pitch 对比，但一次只改变一个变量。

### 歌声

- 使用 `rmvpe` 作为基线，必要时与 `crepe` 对比。
- Autotune 仅用于歌唱，先从低强度开始。
- 保留原伴奏和未经转换的干声，便于重新混音。
- 检查长音、转音、齿音、爆破音及无伴奏片段，不只听副歌。

## 长音频

1. 在停顿或镜头切点处分段。
2. 相邻片段保留少量上下文，避免句首句尾音色跳变。
3. 所有片段固定模型哈希、Pitch、Embedder、Index Rate 和 Protect。
4. 转换后统一响度、底噪和空间感。
5. 检查拼接点、口型对齐、环境声连续性和字幕时间轴。

“Split Audio”可以帮助处理长音频，但仍需人工检查分段边界。

## A/B 验收矩阵

每个模型至少测试四类短句：

1. 普通陈述，检查整体相似度。
2. 含 `知、吃、诗、日、资、次、思、女` 的中文句子，检查声母与 `ü`。
3. 高情绪或快速说话，检查爆音和节奏。
4. 气声、轻笑或弱音，检查辅音保护与索引伪影。

记录模型哈希、源音频、参数、输出和主观结论；不要只保留“最好听”的结果而丢失对照。

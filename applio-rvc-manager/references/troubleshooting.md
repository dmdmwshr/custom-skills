# Applio 故障诊断

## 界面打不开

1. 运行 `scripts/audit-applio.ps1`。
2. 确认 `run-applio.bat`、`env\python.exe`、`app.py` 存在。
3. 检查 6969 端口及占用 PID。
4. 从普通用户终端在安装根目录运行启动脚本，保留完整报错。
5. 若默认端口冲突，先识别占用者；确认不能复用后改用空闲端口。
6. 不以管理员身份运行，不移动单个 DLL，不向内置环境随意补包。

Web UI 进程存在但浏览器未打开时，直接访问 `http://127.0.0.1:6969`。本机安装是编译包内置 Python 加本地 Web UI，不是独立原生桌面窗口。

## 模型不显示或索引不匹配

检查：

- 模型位于 `logs` 的子目录；
- 推理权重后缀是 `.pth`，不是只存在 ZIP；
- 文件名不以 `G_` 或 `D_` 开头；
- 索引后缀是 `.index`，名称不含 `trained`；
- `.pth` 和 `.index` 位于同一模型目录；
- `.index` 的完整路径不含中文；当前 Windows FAISS 可能无法读取中文路径；
- 模型可被 `inspect-rvc-model.py` 安全加载；
- 在界面点击模型刷新。

多个文件都叫 `model.pth` 时可改成中文角色显示名；模型目录与 `.index` 名称继续使用唯一 ASCII slug。

## 下载失败

1. 使用 Hugging Face `resolve/main/...zip?download=true` 直链，不用搜索结果页。
2. 对大文件使用支持续传的 BITS 或下载器。
3. 下载完成后核对实际文件大小和 SHA-256。
4. 只有 `.pth/.index` 时分别下载，再人工配对；不要为了单个模型下载整个多 GB 仓库。
5. 网络中断时保留部分文件并续传，不重复启动多个相同下载。

## 高内存或显存

1. 先用路径和端口确认 Applio PID，不结束所有 Python。
2. 用 `nvidia-smi` 检查 GPU 进程、显存和驱动。
3. 确认是否同时打开 Inference、Realtime、训练、UVR 分离或其他 ComfyUI 任务。
4. 训练检查批大小、采样率、缓存和数据集长度；推理检查是否加载多个模型或超长音频。
5. 停止任务前先保存输出和训练检查点；仅在用户要求后停止已确认的进程。

## 输出电音、爆音或咬字差

- 确认输入没有伴奏、混响和削波。
- 使用 `rmvpe` 作为基线。
- 降低 Search Feature Ratio。
- 中文辅音丢失时提高 Protect。
- 将 Pitch 向 `0` 收回，避免跨越过大音域。
- 对比 `contentvec` 与 `chinese-hubert-base`。
- 关闭 Autotune；它主要用于歌唱。
- 低强度测试 Clean Audio，过强会压缩或损伤语音。
- 如果训练数据主要是唱歌，不要期待稳定的口语咬字。

## 语言和界面

当前配置可能仍显示英文。优先在 Settings 中选择中文并由界面保存；不要仅为翻译文本修改模型或 Python 环境。界面本地化与模型是否支持中文是两个不同问题。

## 升级失败

- 不覆盖式替换旧 `env`。
- 保留完整安装包与 SHA-256。
- 新版本放入独立临时目录验证，再迁移 `logs` 和配置。
- 回滚时恢复完整旧版本，不混用不同版本的 Python、PyTorch 和二进制文件。
- 报告“升级成功”前必须验证启动、GPU、模型扫描和一次短推理。

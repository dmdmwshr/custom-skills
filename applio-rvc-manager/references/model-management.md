# RVC 模型获取与管理

## 文件角色

- `.pth`：推理权重，必需；是基于 PyTorch 的序列化文件。
- `.index`：FAISS 检索索引，可选但通常建议保留，用于强化目标说话人的音色特征。
- ZIP：传输包，不是模型本体；安装前检查内容并提取。
- `G_*.pth`、`D_*.pth`：通常是训练检查点，不应当作最终推理模型。

Applio 3.6.4 会递归扫描 `logs`。模型文件与索引在同一目录时更容易自动配对；文件名以 `G_`、`D_` 开头的权重和名称含 `trained` 的索引会被过滤。

## 来源分级

按以下优先级选择：

1. 作者或项目官方仓库，模型卡说明训练数据、语言、版本、试听和许可。
2. 训练者本人仓库，提供 `.pth + .index`、参数、试听和用途约束。
3. 社区合集，文件成对但说明不完整；只用于隔离测试。
4. 仅有公众人物姓名、无模型卡、无许可、无试听的批量仓库；默认不推荐。

Hugging Face 的“Voice Conversion”标签不代表一定兼容 Applio。先确认是 RVC 推理权重，不要把底模、训练检查点、So-VITS、TTS 或其他架构当作 Applio 音色。

## 安全检查

1. 记录原始 URL、仓库页、提交版本或下载日期。
2. 对下载文件计算 SHA-256。
3. 检查 ZIP 条目，拒绝绝对路径、`..` 越界路径、脚本和可执行文件。
4. 只安装需要的 `.pth`、`.index` 和纯文本说明。
5. 使用 Applio 内置 Python 和 `inspect-rvc-model.py` 安全加载 `.pth`。
6. 检查 `.index` 能被 FAISS 读取。
7. 首次推理使用无隐私的短测试音频。

即使 Hugging Face 标记文件“Safe”，仍要保留哈希和本地检查结果。

## 中文显示与兼容命名

本机实测发现：PyTorch 可以加载中文 `.pth` 文件名，但当前 Windows FAISS 无法打开完整路径含中文的 `.index`。因此不要使用中文模型目录，也不要给 `.index` 使用中文文件名。

技术目录和索引使用唯一 ASCII slug：

```text
logs\genshin_paimon_jp_rvcv2\
├── 派蒙_日语角色_RVCv2.pth
└── genshin_paimon_jp_rvcv2.index
```

中文信息通过 `.pth` 显示名和模型清单提供：

```text
懒羊羊_中文口语_RVC.pth
派蒙_日语角色_RVCv2.pth
银狼_日语角色_RVCv2.pth
```

Applio 模型下拉框可通过中文 `.pth` 名称辨识角色，FAISS 同时可以读取 ASCII 索引路径。若其他旧版 RVC 工具连中文 `.pth` 都不支持，则复制一份 ASCII 名称用于该工具，不要改动已验证的 Applio 目录。

## 目录结构

```text
D:\Program_Files\Applio\
├── logs\
│   └── <unique-ascii-slug>\
│       ├── <中文显示名>.pth
│       └── <unique-slug>.index
├── model_packages\
│   └── <YYYY-MM-DD>\
│       ├── 原始下载包
│       └── manifest.sha256
└── assets\audios\
    └── 可重建的工作音频和输出
```

模型包保留用于追溯和重装。空间不足时，确认模型已安装、哈希已记录、来源仍可获取后再删除原包。

## 安装验收

每个模型至少验证：

- 一个可安全加载的推理 `.pth`；
- `.index` 可由 FAISS 读取，或明确记录未提供；
- 权重与索引位于同一 ASCII 模型目录；
- Applio 刷新后可见；
- 10–20 秒短音频推理成功；
- 输出无爆音、严重电音、错调或辅音丢失；
- 来源、训练语言、许可状态和建议音高已记录。

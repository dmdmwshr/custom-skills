## 1. 工具边界

- Applio 负责对白底稿、RVC 角色音色、逐句导出和参数复现。
- ComfyUI 负责用音频驱动人物嘴型、表情、动作或生成带声音的视频。
- 音乐、环境声和音效单独分轨，最后剪辑混音。不要把带背景音乐的成品声轨直接交给口型工作流。
- Applio 不负责翻译、可靠的多人分离、字幕时间轴或最终混音。

## 2. 先判断音频角色

| 音频角色 | 含义 | 对视频的约束 | 适用流程 |
|---|---|---|---|
| `final_dialogue` | Applio 已生成并锁定的最终对白 | 直接决定台词、时长、停顿和口型节奏 | Wan2.2 S2V、HuMo、InfiniteTalk、LTX2.3 IA2V |
| `voice_reference` | 用于展示目标说话人音色的短参考 | 视频模型仍会重新生成语音，不能保证精确沿用波形和节奏 | LTX2.3 ID LoRA |
| `music_or_sfx` | 配乐、环境声或音效 | 不作为主要嘴型驱动 | ACE-Step、Stable Audio 或剪辑软件 |

如果交付要求“必须保留 Applio 的角色音色、中文发音和台词节奏”，优先使用读取 `final_dialogue` 的工作流。不要把参考音频工作流误当成最终对白直通流程。

## 3. 标准项目目录与命名

项目事实源放在：

```text
D:\12070\Documents\workspaces\Comfy-Codex-Workspace\projects\<project_slug>\
└── audio\
    ├── script\       # 台词和分镜版本
    ├── source\       # 原录音或提取的干声
    ├── tts\          # EdgeTTS 底稿
    ├── rvc\          # Applio 候选输出
    ├── locked\       # 已锁定、可交给视频模型的母版
    ├── mix\          # 后期对白、音乐、音效混合结果
    └── records\      # 模型、参数、哈希和验收记录
```

执行文件名使用 ASCII、小写和下划线：

```text
sh010_usagi_zh_dialogue_rvc_v001.wav
sh020_hakimi_zh_dialogue_rvc_v002.wav
sh030_usagi_voice_reference_v001.wav
```

命名字段依次为：镜头号、角色 slug、语言、用途、来源和版本。中文角色名、台词和备注写在记录文件中，不依赖执行文件名表达。

锁定文件不得原位覆盖。修改台词、语速、模型或任一核心参数时增加版本号，并将旧版标记为 `retired`。

## 4. 端到端制作流程

1. **冻结分镜信息**：记录镜头号、说话人、逐字台词、情绪、目标时长、人物图和 ComfyUI 工作流。
2. **选择声音入口**：
   - 有合格表演录音：提取单人干声后使用 RVC。
   - 只有文字：先用 EdgeTTS 生成底稿，再使用 RVC。
3. **按镜头切分**：一条音频只服务一个镜头和一个说话人。对话镜头为每个说话人保留独立轨道。
4. **短样本定参**：固定 10–20 秒样本，只改变一个参数做 A/B；确定模型、Pitch、F0、Embedder、Index Rate 和 Protect。
5. **生成候选**：输出到项目 `audio\rvc`，检查发音、气口、伪影、情绪和目标时长。
6. **锁定母版**：选中的无损 WAV 复制到 `audio\locked`，记录 SHA-256、时长、采样率、声道、台词版本和参数。
7. **暂存到 ComfyUI**：把锁定文件复制到 `C:\Users\12070\Documents\ComfyUI\input\audio\<project_slug>`。如节点列表未刷新，刷新文件列表或重新打开工作流。
8. **绑定工作流**：确认 LoadAudio 使用正确版本，并在记录中写明它是 `final_dialogue` 还是 `voice_reference`。
9. **生成与验收**：先做单镜头低成本测试；通过后再生成正式镜头。
10. **归档结果**：将选定视频复制回项目或工作区 `outputs`；ComfyUI `input/output` 与 Applio `assets\audios` 都只作中转。

## 5. Applio 操作要点

### 现有录音换角色音色

1. 打开 `Inference`。
2. 选择目标 `.pth`，核对自动匹配的 `.index`。
3. 输入单人、无音乐、无明显混响的干声。
4. 口语先用 `rmvpe`；固定短句测试 Pitch、Index Rate、Protect 和 Embedder。
5. 输出到项目 `audio\rvc`，不要把唯一结果只留在 `assets\audios`。

### 文字生成角色音色

1. 打开 `TTS`，输入文字或 UTF-8 `.txt`。
2. 中文底稿先选与性别和音域接近的 EdgeTTS 音色；语速和停顿先于 RVC 参数确定。
3. 选择目标 RVC `.pth/.index`。
4. Applio 先生成 EdgeTTS 底稿，再生成 RVC 输出；分别保存到底稿和候选目录。
5. 台词中容易误读的姓名、外语、数字和语气词应先改写成能稳定朗读的形式。

### 参数冻结

每个角色至少冻结：

- RVC 模型与 `.index` 的完整路径和 SHA-256；
- 模型训练语言、说话/歌唱用途和授权；
- EdgeTTS 音色与 TTS Speed，或源录音文件哈希；
- F0 Method、Pitch、Embedder、Index Rate、Protect；
- Volume Envelope、Clean Audio、Split Audio、Autotune 等开关；
- 输出采样率、声道、响度处理和版本。

## 6. 音频锁定规格

- 母版优先使用无损 WAV；不要把 MP3 作为长期事实源。
- 对白驱动母版优先单声道。保留项目统一的采样率；无明确限制时可保存 48 kHz PCM WAV，工作流需要其他采样率时生成派生副本。
- 不允许削波。响度应在项目内统一，但不要在每次返工时反复归一化。
- 保留有意设计的句首、句尾静音。锁定后不要再自动裁切，否则会改变嘴型起止时间。
- 驱动音频不混入音乐、房间混响和强环境声；这些声音在视频生成后单独混合。
- 每次交给 ComfyUI 前记录文件大小、时长和 SHA-256，防止界面仍选中同名旧文件。

## 7. ComfyUI 工作流选择

以下路径以本机 `官方模板学习库\02_视频生成与控制` 为准：

| 工作流 | 音频输入角色 | 适合场景 | 关键注意 |
|---|---|---|---|
| `04_音频驱动视频_角色图加语音到视频_Wan2.2-S2V.json` | `final_dialogue` | 单人物图加对白，生成说话视频 | 当前保存模板使用英文 Wav2Vec2 编码器；中文必须先做发音和口型短测，不能默认适配 |
| `14_音图文生视频_音频加角色图和提示词到视频_HuMo.json` | `final_dialogue` | 音频、人物图和文本共同控制 | 当前模板使用 Whisper Large V3 音频编码器；提示词不要与实际说话动作冲突 |
| `16_音频配音视频_人物图加语音到全身视频_InfiniteTalk.json` | `final_dialogue` | 单人或双人说话、全身动作、较长续写 | 双人必须分别加载两条音频并绘制人物蒙版；模板每个扩展组约增加 3.24 秒，需按总音频长度规划 |
| `20_图像音频生视频_角色图加语音到口型视频_LTX2.3.json` | `final_dialogue` | 图片加最终对白生成口型视频 | 最适合把已锁定的 Applio 对白直接用于镜头 |
| `29_人物音色一致_人物参考图加短音频和提示词到视频_LTX2.3-ID-LoRA.json` | `voice_reference` | 用短参考音色、人物图和结构化提示词生成音画 | 输入音频是音色参考；实际台词写在 `[SPEECH]`，声音会重新生成，不保证精确保留 Applio 输出 |

ID LoRA 的结构化提示词包含：

```text
[VISUAL]: 镜头、人物、服装、场景、光线和说话动作
[SPEECH]: 与分镜记录完全一致的逐字台词
[SOUNDS]: 音量、语气、麦克风距离和环境声
```

若 `[SPEECH]` 与项目台词不一致，应停止生成并先修正文本。Applio 的 `voice_reference` 建议使用 5–15 秒单人干声，避免音乐、混响和多说话人。

## 8. 多人物与长镜头

- 双人对话优先拆成正反打短镜头；每个镜头只让当前说话人驱动嘴型。
- 必须同框时，为每个说话人保留独立 `final_dialogue`，再使用支持多音频与人物蒙版的 InfiniteTalk。
- 不要先把两个人的对白混成一条音轨再要求模型自动判断谁说话。
- 长对白按分镜和语义停顿切段，镜头通常按 3–8 秒管理；每段沿用同一角色参数预设。
- 相邻段要检查句尾气口、背景底噪和响度，避免音频接缝暴露镜头拼接。
- 音频版本变化后，只返工引用该版本的镜头，不重做无关画面。

## 9. 验收和定向返工

锁定音频前检查：

- 台词逐字正确，数字、人名和外语发音正确；
- 说话人与角色模型对应；
- 音色相似且跨镜头稳定；
- 无电音、破音、金属感、吞字和异常呼吸；
- 句首句尾、停顿和目标时长符合分镜；
- 文件规格、模型哈希、参数和版本已记录。

视频生成后检查：

- 嘴型起止与音频一致；
- 重音、闭口音和停顿处没有明显错位；
- 双人场景没有串嘴；
- 人物身份、姿态和背景没有因音频驱动发生不可接受漂移；
- 输出视频实际包含所选音频，而不是模板示例音频或旧版本。

返工时只改一层：

| 问题 | 返回环节 |
|---|---|
| 台词、发音、音色或节奏错误 | Applio/TTS/RVC |
| 音频正确但嘴型错位 | ComfyUI 口型或音频驱动镜头 |
| 双人串嘴 | 音频分轨、人物蒙版和说话人绑定 |
| 音色参考工作流无法精确保留角色声音 | 改用读取 `final_dialogue` 的工作流 |
| 音画都正确但环境声不连续 | 后期混音 |

## 10. 常见误区

- 固定随机种子不能锁定音色；应锁定模型、参数、源音频和后期处理。
- RVC 只换音色，不翻译台词，也不会自动修正口型。
- 日语训练模型能处理中文不代表中文咬字稳定，必须先测中文声母和声调。
- LoadAudio 能读取 MP3 不代表 MP3 适合作为母版。
- ComfyUI 模板自带示例音频；生成前必须再次核对 LoadAudio 文件名。
- LTX2.3 ID LoRA 的短音频是参考，不等于最终对白输入。
- Applio `assets\audios`、ComfyUI `input` 和 `output` 都不是长期素材仓库。

# Applio 数据集与模型训练规范

## 1. 目标和分集原则

一个 RVC 模型默认只服务一个说话人、一个主要语言/方言和一种主要用途。口语、歌声、强表演声可以分别建模型；若必须混合，必须在项目记录里写明混合比例和预期代价。

默认把以下数据集分开：普通话 `cmn`、粤语 `yue`、四川话 `scn`、东北话 `dng`、吴语 `wuu`、河南话 `hen`、日语 `jpn`。这些代码是项目内部标签，不代表完整语言学分类。吴语和河南话要注明具体城市或片区，避免把不同变体误当成同一口音。

普通话录音训练出的模型可以承载说话人的音色，但不能可靠地产生地道粤语、四川话或日语发音。要做方言特色，训练集必须包含该方言的真实发音；文字生成时还要让 TTS 底稿或源录音先具备目标语言/方言的发音。

## 2. 录音和数据量

### 录音条件

- 单人、固定麦克风距离和角度；每次录音前后保持增益一致。
- 无音乐、无电视、无风扇、无键盘声和明显房间混响。
- 不削波、不强降噪、不使用反复压缩的 MP3 作为训练母版。
- 语句之间保留自然停顿；不要把多说话人、重叠对白和长段情绪表演直接混在一起。
- 母版优先为单声道 PCM WAV，48 kHz、24 bit；训练时在 Applio 选择一个目标采样率并在同一模型内保持一致。当前界面支持 32/40/48 kHz，默认可从 40 kHz 开始。

### 数据量参考

| 目标 | 清洁单人语音参考量 | 说明 |
|---|---:|---|
| 快速可行性测试 | 5–10 分钟 | 只能验证音色方向，容易过拟合或咬字不稳 |
| 自然口语模型 | 30–60 分钟 | 覆盖普通语气、问句、感叹、数字和不同句长 |
| 高质量角色模型 | 1–3 小时 | 增加情绪、节奏、音域和目标语言/方言覆盖 |

时长不是唯一指标。重复同一句话、含背景噪声或音色变化过大的录音不会等价于有效数据量。

## 3. 文本稿规范

训练稿和录音稿分别保存：

- `script\<locale>\<purpose>_dataset.txt`：UTF-8，每行一条可独立录音的句子，不加序号、不加引号、不混入说明。
- `script\<locale>\<purpose>_dataset.srt`：UTF-8，用于录音提示、字幕和时间复核；一条字幕对应一句话，时间码使用 `HH:MM:SS,mmm`。
- 长句和短句混合；覆盖陈述、疑问、感叹、命令、数字、日期、单位、专名、英文/日文混合和不同情绪。
- 方言稿注明语言/方言与地区；日语稿单独保存，不与中文稿拼接成同一个录音清单。
- 修改文本时增加 `v002` 等版本号，不能静默覆盖已经录音或训练过的版本。

录音前先人工校对姓名、数字、外语、方言词、儿化、轻声和容易多音字；错误文本会被模型当作训练目标，后期很难补救。

## 4. 音频清洗和切句

1. 保留原始录音到 `dataset\raw`，只读归档，不在原文件上降噪或裁切。
2. 将派生文件写入 `dataset\clean`，记录处理方式；只做必要的去噪、去混响、增益整理和静音处理。
3. 将单句文件写入 `dataset\segments`，推荐每段约 2–12 秒；太短的片段合并，过长的片段按自然停顿拆开。
4. 句首和句尾保留少量自然静音，不要把呼吸、爆破音和弱辅音全部裁掉。
5. 将无法确认说话人、含明显噪声、错读、爆音、重叠说话或严重混响的文件移到 `dataset\review`，不要混入训练目录。

## 5. 清单和质量检查

`dataset\manifests\segments.tsv` 使用 UTF-8、制表符分隔，至少包含以下字段：

```text
segment_id	audio_path	transcript	locale	speaker	emotion	duration_ms	sample_rate_hz	channels	status	sha256
```

字段含义：

- `audio_path` 必须是项目内相对路径，不能指向临时下载目录。
- `transcript` 必须与音频逐字一致；文本中若含制表符，应先转义或修正。
- `locale`、`speaker`、`emotion` 用于复核，不要靠文件名猜测。
- `status` 使用 `accepted`、`review`、`rejected`；只有 `accepted` 进入训练。
- `sha256` 用于确认音频没有被原位替换。

训练前至少检查：单说话人、无削波、无长时间静音、采样率一致、声道一致、文本非空、路径存在、编码为 UTF-8、拒绝项未被引用。

## 6. Applio 训练步骤

在 Applio“训练”页按以下顺序执行：

1. 在“模型设置”填写模型名称，选择训练采样率和声码器；同一模型不要中途改采样率。
2. 在“预处理”选择 `dataset\segments` 或 Applio 可读取的数据集目录，完成预处理。
3. 在“提取”使用 `rmvpe` 作为口语基线，使用 `contentvec` 作为通用嵌入基线；中文清晰度不足时再做对照测试。
4. 在“训练”按 GPU 显存选择批处理大小；先完成小轮数试跑，再决定是否进行长训练。记录总轮数、保存频率和实际显存。
5. 训练完成后生成 `.index`；不要把 `G_*.pth`、`D_*.pth` 或中间检查点直接当作最终推理模型。
6. 运行 `scripts/inspect-rvc-model.py` 检查最终 `.pth`，并用 FAISS 检查 `.index`；保存模型和索引哈希。
7. 安装到 Applio `logs\<unique-ascii-slug>\`，刷新界面，做 10–20 秒短音频推理。

### 推荐的首轮基线

- 口语：`rmvpe`、`contentvec`、Autotune 关闭。
- 批大小：根据 RTX 5080 实际可用显存试跑，不把固定数值当成所有数据集的保证。
- 先固定源音频和模型，只改变一个参数做 A/B；不要同时改变 Pitch、Index Rate、Protect 和 Embedder。
- 中文模型增加含 `zh、ch、sh、r、z、c、s、ü` 的句子；方言和日语模型增加该语言/方言的高频音节和真实语气。

## 7. 训练验收

至少用四类短句试听：

1. 普通陈述，检查整体音色和自然度。
2. 含目标语言/方言关键音的句子，检查咬字和声调。
3. 快速说话、疑问或高情绪句，检查节奏、爆音和断裂。
4. 轻声、弱音、短停顿句，检查辅音保护和索引伪影。

通过标准：文本正确、音色稳定、无明显电音/金属感/爆音、辅音可辨、停顿自然、跨多句不漂移，并且模型、索引、数据集版本和参数可以复现。只听一条“最好听”的样本不能作为训练完成证据。

## 8. 失败处理

- 音色像但发音错：先检查源音频语言/方言和 TTS 音色，不要只提高索引比例。
- 中文辅音模糊：降低 Search Feature Ratio 或对比嵌入模型，并提高 Protect 做短样本验证。
- 电音和断裂：先确认训练集无削波、无过强降噪、无大量短片段，再调整参数。
- 方言不地道：补录真实方言数据或更换目标语言 TTS；不要把普通话训练集强行标成方言模型。
- 训练过拟合：减少重复句，增加不同句长和语气，保留验证句，不要只增加轮数。

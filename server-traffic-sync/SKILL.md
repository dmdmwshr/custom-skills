# Clash 配置与面板流量维护

目标是统一维护订阅规则、节点与生成链，并让每轮可追溯的供应商面板观察驱动正确流量展示和余额保护。当前实现依赖 WSL/Linux 项目、Codex 桌面内置浏览器与已登记 SSH 入口；其他主机先核实实际能力，不复制认证或状态。

在 `server-traffic-sync` 项目读取 `PROJECT_STATUS.md`、`config/runtime.json` 和 `docs/AUTOMATION.md`。从当前 cwd 或产品项目登记定位，不固定任务 ID、浏览器编号或临时 tab。来源、服务器绑定和输出映射由项目维护。定时运行复用已登记 heartbeat，不另加 cron/timer 或并行采集者；正常运行不加载全部历史验收。

## 按任务选择入口

配置/节点维护先读项目现行职责与发布说明，对照 meifu 当前生成器和受控输入指纹，确认无在途/未知写入后，在隔离数据中验证，再使用原发布锁、精确备份及事务更新。不得直接用旧主机镜像覆盖线上，不因旧“只镜像”说明否定当前明确维护授权；但当前用户保留的 CN2 等范围不变。测试覆盖新增规则的引用、客户端字段和失败回退；已有标准 Mihomo CLI 可用 `-t` 只测配置，FlClashCore 的 socket 服务不等于该 CLI，不为验收启动真实代理连接。

流量周期继续下列既有入口；阀门阈值和作用范围读项目策略/文档，不在 Skill 维护第二套业务参数。订阅节点过滤在客户端刷新后生效，与实时停服不同；停服、改变采集频率或客户端强制刷新须符合当前具体需求。合法新观察按原校验恢复余额后重新加入，缺失/异常观察不放开已关闭节点。跨主机移交维护入口时同步两侧当前职责，保留只读观察；产品 host 未连接不得伪称任务消息送达或自动化已迁移，不手改状态库/automation.toml。

## 执行原则

- 每轮先用项目 `traffic_cycle.py status` 判断有没有在途周期、待决发布或待清理页面。已有周期先接续；正常任务退出、应用重启不等于业务已失败或可重新发布。真实身份从当前环境/工具读取。
- 浏览器按当前工具文档操作。此项目有用户明确的内置浏览器例外，不能扩大成其他项目的浏览器授权。可使用已导入凭据自动填充正常登录，只看隐藏状态与登录结果；不读取密码、Cookie、令牌，详情页避开 SSO 链接与全页转储。
- 先确认服务器身份，再读取流量的标签、数值、单位和观察时间。使用当前页面实际可用的选择器或语义读取，不把示例选择器、旧按钮位置、文案换行当永久契约。标题先到而数值未到时有界等候；只有本轮新鲜页面能形成新观察。
- 采集由模型适应页面，数值校验、单写者、原观察时间、发布、哈希和日志由项目脚本承担。真实字段含义不变而适配器过严时，依据当页证据做最小修正和针对性测试；不能通过编造身份、用量、周期或删 pending 绕过真实错误。
- 每站独立处理可确认的读取失败。另一站有效时允许更新另一站，失败方保留原值与原时间。远端发布未知则先对账原事务，不能重发或用新采集覆盖未知结果。
- 正式写入沿用项目 meifu 接收器；下载层按项目当前输出清单逐一验证全部文件、GET/HEAD 流量元数据及 Stash 更新地址；启用阀门时同时验证决策与真实输出，完成数量以实际核验结果为准。原生进度来自订阅响应，不插入流量策略组。CN2 不采集、不连接、不改其文件。
- 页面按用途登记，完成后只关闭自己的临时页并回读，再登记清理、结束周期。未关闭或归属不明的页保留待处理状态，不因本轮已有流量结果就称全部完成。

## 问题处理与记录

常见分支见 [运行与恢复](references/operations.md)，实际命令及格式以项目 `docs/AUTOMATION.md` 为准。每次有实质变化再继续诊断，避免无变化轮询、机械重试或重复重跑整套验收。默认一轮约 15 分钟预算；已知慢页面可根据证据调整，不能让单轮永久占住后续执行。

使用每轮目录中的 `run.json`、`events.jsonl`、白名单面板字段、接收器回执和下载核验排错。不要把页面全文、私有节点 YAML、密码或 SSO URL 存进日志。成功记录与故障记录按项目保留策略整理，待决事务、未清理页面和最新有效证据不按日期清掉。

调度创建、修改、暂停通过产品工具，查重并回读目标、频率、状态和下一次时间；源码准备、手动完整周期、调度配置以及自然定时触发分别报告。本机运行需要电脑与桌面应用可用，停机恢复后采集当前值，不补造过去的面板观察。

已验证的新问题解决方法合并回项目适配器或本 Skill 对应分支；不要为一次故障不断叠加新门槛。凭据验证、额外认证、来源资源实质变化或无法核定的发布结果，保留证据并明确所需用户动作。

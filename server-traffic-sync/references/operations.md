# 运行与恢复分支

按现象选择必要分支，不逐条走完整检查表。

| 现象 | 可继续的处理 | 停止影响范围 |
| --- | --- | --- |
| 页面慢或只有流量标题 | 核对 URL 与身份；等待数值出现，重新读取小范围区域；已知只读失败可短暂退避后重新导航 | 单站，建议最多三次有依据的读取尝试 |
| 登录失效 | 点击已知账户字段触发内置凭据填充，正常提交一次，再核对结果 | 仍未登录、验证码或额外验证时记录 needs_user；不自动读出或修改密码 |
| 选择器/布局/换行改变 | 从当前页面重新找流量标签及其关系，必要时最小修改解析器并验证数值和错绑用例 | 不因表现差异阻塞，但身份、含义、单位不明时保留该站旧值 |
| 某一面板暂时不可用 | 登记该站错误；可验证的另一站继续提交和验收 | 不把两站捆绑成全有或全无 |
| 用量减少、套餐或单位变化 | 重新读同一资源，找真实周期重置/套餐字段。明确证据足够时修正项目策略与必要测试；RackNerd 已登记自然月重置 | DDO 不从旧网卡脚本或日历猜重置日；证据不足保留旧值 |
| SSH/HTTP 临时故障 | 只读探测有界重试；写入请求不明确时先看本轮 pending 和远端锁内状态、事务回执 | 未知写入不能重放；明确失败且远端无在途后才作为已拒绝处理 |
| 已发布但下载核验失败 | 复查同一次发布的文件、元数据和 GET/HEAD，区分 Nginx 接管、网络与实际内容错误 | 不再次采集或重复提交来掩盖验证失败 |
| 任务/应用中断 | 读 active-cycle、最后事件、pending 和登记页面，按真实当前工具刷新引用；接续原周期或完成对账清理后登记 interrupted | 不拿旧 PID、tab 数字或任务截图当当前身份，不直接清状态 |
| 发布未改值但时间已更新 | 新鲜采集仍保存其原时间；只读验收当前输出即可 | 不因无业务数值变化通知用户或重启服务 |
| 达到保留期 | 由周期结束入口清理本项目已终结运行目录 | 待决、清理未完成、最新成功/问题摘要和部署恢复点保留 |

页面读不到与工具连接未知是不同问题；未知时先查原页面/请求回执，不能连续新建页。关闭页的结果未知也先回读列表。已没有下一轮同页复用入口时，本轮页应关闭；后台执行不打扰前台。

正常成功只写运行日志。出现新的故障、故障实质变化、需要用户登录/验证，或从已报告故障恢复时，给出简短可操作说明；相同未变化的问题不反复刷屏。具体通知行为应与已保存自动化的用户偏好一致。

# Windows 计划任务生命周期规范

## 适用对象

本规范只管理由 Codex 或本机开发项目创建、更新、启停或删除的任务。Windows、硬件厂商和已安装软件自行维护的任务只读识别。若无法从项目清单、任务描述和动作入口确定归属，停止变更并标记为归属不明。

## 唯一身份与命名

1. 创建前枚举现有任务，并核对目标项目清单、生命周期脚本和相同动作入口。优先原位更新，禁止通过近似名称、不同根路径或重复触发器创建功能相同的副本。
2. 每个项目冻结唯一、稳定、ASCII 小写的 `project_key` 和简短大写的 `project_code`。
3. 新项目默认使用任务路径 `\DevProjects\<PROJECT_CODE>\<CATEGORY>\`，任务名使用 `DEV-<PROJECT_CODE>-<CATEGORY>-<NN>-<Purpose>`。已有项目若有稳定且无歧义的体系可继续沿用，但不得并行创建默认命名副本。
4. 每个任务分配项目内稳定编号 `<CATEGORY>-<NN>`。推荐类别：`DATA`、`AUTO`、`LIVE`、`WEB`、`GOV`、`MAINT`、`BACKUP`、`SYNC`。
5. 唯一身份是 `TaskPath + TaskName`。显示名、脚本文件名、入口文件或描述均不能替代该复合身份。

## 描述与项目清单

新建或重新登记的任务，其 `Description` 以以下标签开头：

```text
[DEV_TASK_V1][project=<project_key>][id=<CATEGORY-NN>][category=<CATEGORY>]
```

标签后用中文记录用途、触发频率、入口、权限级别、网络、模型、凭据、数据写入边界，以及是否涉及交易或其他高风险动作。描述、参数和日志中不得写入密钥、口令或令牌。

项目维护 `docs/WINDOWS_TASK_CATALOG.md` 或等价清单，至少记录：

- `project_key`、`project_code`、稳定编号、`TaskPath`、`TaskName`。
- 用途、动作入口、工作目录、触发器、运行账户和权限。
- 并发策略、超时、失败重试、电池、登录、唤醒和错过触发补跑策略。
- 启停状态、网络/模型/凭据/写入/交易边界。
- 安装、只读查看、更新和精确卸载入口。

项目清单是项目事实源，本机计划任务实例是运行验收事实源；实施后必须双向回读一致。

## 创建

1. 读取项目 `AGENTS.md`、任务清单和已有安装脚本，确认动作文件与工作目录存在。
2. 冻结身份、触发器、运行账户、权限、`MultipleInstances`、执行时限、失败重试、电池、登录、唤醒和补跑策略。
3. 默认使用当前交互用户、`Interactive` 和 `Limited`。只有任务确需管理员能力且当前用户在当前消息中明确授权时才使用 `Highest`。
4. 项目提供可重复执行的安装、查看和精确卸载脚本。脚本只能操作清单中的精确身份；卸载不得按前缀、通配符或模糊匹配。
5. 创建后回读动作、参数、工作目录、主体、触发器、设置、状态和描述，并完成适合任务类型的生命周期验证。

## 更新

1. 更新前导出 XML，或记录动作、触发器、主体和设置的结构摘要；只修改当前用户授权的字段。
2. 只改备注时不得启动、停止、启用、禁用、重建、改身份或改触发器。
3. 动作、触发器、权限、状态和删除属于实质变更。当前消息已经明确指定这些对象和动作时视为授权；无需再次逐项确认。
4. 更新后回读所有结构字段，并对运行中的服务型任务核对进程链、监听端口、健康接口或数据水位。

## 启停与生命周期验证

1. 创建或实质更新后台任务后，执行一次与任务语义相符的启动、停止或重启验证。
2. 验证是否出现新的 `OpenConsole.exe` 或 `WindowsTerminal.exe`，以及停止后是否遗留子进程。
3. 按任务类型核对端口、健康接口、文件产出、数据水位或失败日志。`Ready` 和 `LastTaskResult=0` 不能单独证明业务正常。
4. 高频任务使用有大小上限和轮换数量的失败日志；联网、模型、数据库写入、消息发送和交易动作分别记录成本与安全边界，不得把模型空轮询当成本地检查。

## 删除

1. 从项目清单和本机实例双向解析唯一目标，核对任务是否运行、动作入口是否被其他任务复用。
2. 先保存可恢复的 XML 或结构摘要，再用精确 `TaskPath + TaskName` 删除。
3. 删除后回读目标不存在，并在项目清单记录删除或迁移状态。
4. 不得删除系统、厂商或归属不明任务。

## 旧任务与服务迁移

- 不符合规范的现有项目任务只登记为 `legacy_unregistered`，不得为了形式统一自行改名、移动、重建或删除。迁移时保持动作、触发器、权限、状态和运行语义。
- 常驻 API、WebSocket 或守护进程可在独立评估后迁移为正式 Windows 服务，但这是新的实质范围，必须由当前用户明确授权，并使用固定服务名、版本化产物、影子端口、健康检查、可回滚切换和旧实例精确卸载。

## 回滚与停止条件

- 身份不唯一、目标归属不明、动作入口缺失、清单与实例冲突或备份失败时，停止变更并报告证据缺口。
- 回滚只恢复本次变更涉及的精确任务和项目清单，不使用通配符，也不影响其他任务。
